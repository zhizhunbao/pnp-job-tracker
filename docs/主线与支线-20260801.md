# 主线与支线(2026-08-01 定)

> 起因:Frank「现在的任务需要分一下主线和支线,要不然一跑偏」。
> 当天的实况就是证据 —— 一天做了 10 笔提交,**主线只动了一格**(雇主线索),其余全是支线。
> 本文只定「什么算主线、下一格是什么、支线什么时候才配被做」。进度真相仍看 STATUS.md 与 git log。

## 0. 唯一判据

> **这件事能不能把「有人真的掏钱」往前推一格?**

推不动的,一律是支线。不管它多有价值、多该做、多让人手痒。

理由:产品分三段,前两段已经做了大半,第三段**一次都没验证过** ——
| 段 | 状态 |
|---|---|
| ① 有别人没有的数据 | ✅ 4.7 万在招 + 清单/门槛/打分表/抽选/LMIA/AIP,官方源带出处 |
| ② 把数据变成结论 | 🟡 七卡里四卡有报告;规则引擎两刀;雇主线索让锁区第一次有货 |
| ③ **有人真的掏钱** | ❌ 30 天里 /pricing 只被打开 1 次 |

**继续加厚第二段是最舒服也最危险的事** —— 它看起来一直在进步,但从不撞第三段。

## 1. 主线队列(有序,一次只推一格)

| # | 一格 | 完成的样子 |
|---|---|---|
| **M1** | 锁区铺到人真正落地的地方 | 职位详情页直接露出该职业的锁区预览(「23 家雇主发过能走省提名的岗 🔒 名单」),而不是只有一句「看报告」。依据:30 天数据里入口=出口=职位详情页,67.5% 只看一页 |
| **M2** | 漏斗五个数能看 | 详情页 → 报告 → **锁区曝光** → pricing → 付费。埋点件都在,只差串成一条能读的线。现在连「多少人见过锁区」都不知道 |
| **M3** | 按数据分叉 | 曝光够、点击少 → 锁的东西不值钱 → 继续做硬货(雇主线索历史维度 / 时间线判断);曝光就少 → 是入口问题 → 回 M1 换位置。**没有 M2 之前这两种可能分不开** |
| **M4** | 第一笔真实付费 | 北极星(整体开发计划:首月注册 ≥50 / 付费 ≥5) |

## 2. 支线四类,各有触发条件

| 类 | 例子 | 什么时候才做 |
|---|---|---|
| **保险** | 政策变更留痕 + 入库闸门、`build_bc_sirs`/`build_sk_points` 进批、`bc-sirs.json` 纳管 | **出过一次事故** 或 主线空窗时。它防的是我们出错,不是让人付钱 |
| **债务** | `/jobs` unique-key 警告、#126 小分类错标、建档向导退役 | 碰到就顺手清,**不单独排期** |
| **体验** | UI 队列、版式统一、文案打磨 | Frank 当面提 → **攒批**做,不占主线的 push 窗口 |
| **扩面** | 其余省门槛、选城市/选学校/选专业三张卡、简历上传解析 | **等主线证明「结论卖得动」再做**。现在扩面 = 把没验证的东西复制十遍 |

## 3. 纪律三条

1. **开工前先答一句**:这是主线哪一格?答不上来就是支线,答不上来就别开工。
2. **支线不占 push 窗口**:攒批,或纯数据/文档带 `[skip render]`(每天 ≤3 次构建,见 [[render-cost-and-limits]])。
3. **一次只推一格,推完必须量数**:不许连着做两格主线而不看数据 —— 那又变成"加厚第二段"了。

## 4. 已知的诱惑(点名记下,免得下次又被带走)

- 「规则引擎再加一个省」—— 扩面,支线。**准 ≠ 值钱**;
- 「政策留痕/入库闸门」—— 保险,支线(虽然是我自己提的,而且真有价值);
- 「变化提醒」「时间线判断」—— 是主线 M3 的**候选**,但**必须等 M2 的数据说话**再选,不许现在开工;
- 「把七卡补齐」—— 扩面,支线。四张卡还没证明能收钱,补到七张不会改变这一点。
