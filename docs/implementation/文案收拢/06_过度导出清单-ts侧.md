## 8 · 工具与验收方法

**`cms/scripts/scan_exports.py`** —— 头部写了用法、分档处置、和**四个坑**
(相对路径整体丢弃 / `with_suffix` 解析到错文件 / `tests/` 没扫 / 桶转发重复计数)。
四个坑**每一个都会把「在用的」算成死代码**,初版全踩过,零消费者一度虚报到 612。

⚠️ **验收方法:别拿 grep 验 grep。**
- 多行 import **逐行 grep 抓不到**(`META_ANSWER` 因此被误判)
- 全文 grep 又会把**同名不同模块**的算成一个 —— 本仓有两个 `OccRow`、两个 `DrawRow`、两个 `PROV_NAMES`

正解:抽样后**跨行**复核,并确认命中的是**同一个模块**的那个。
最后一版:**83 个抽检样本 0 误判**。

### 顺带更正一条先前说错的数字

先前称「三个带桶模块 67 次 import **零绕过**」——**不对,真实是 1 次**。
那次只 grep 了 `@/lib/X/` 绝对路径,漏了 `lib/` 内部兄弟文件的相对路径 `./i18n/chat`。

| 模块 | 从桶取 | 直接点文件 |
|---|---|---|
| `lib/i18n` | 59 | **1**(`chatOrchestrate.ts` 取 17 个桶没转发的名字) |
| `lib/pathways` | 4 | 0 |
| `lib/quiz` | 10 | 4(**模块内部相对引用,设计如此**) |
| `lib/db` | 0 | 48(命名空间形态,非违规) |

结论方向没变(约定基本守住),但数字要以这张表为准。
