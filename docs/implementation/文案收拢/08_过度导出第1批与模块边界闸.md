## 3 · 🔴 扫描器又漏了四个坑(⑤⑥⑦⑧)

上一轮 `scan_exports.py` 收进仓库时头部写着「四个坑、83 个抽检样本 0 误判」。
**动手当天又出四个** —— 抽检没覆盖到 `collections/`、也没覆盖嵌套块里的动态 import。
**「抽检 0 误判」不等于「没误判」,这条结论本轮被推翻。**

| 坑 | 症状 | 谁抓出来的 |
|---|---|---|
| ⑤ `SKIP_DIRS` **两边都生效** | `collections/*.ts` 的 **import 不算数** → 只被 collection 引用的常量全成死代码 | tsc(3 条) |
| ⑥ `DYN` 内层写了 `[^}]*` | 外层函数的 `{` 当起点把整段吞掉,**嵌套块里第一个**解构动态 import 解析不出名字 | tsc(1 条) |
| ⑦ `import('./X').then(m => m.Y)` 没认 | `next/dynamic` 的取名形态 | 本轮没踩(`.tsx` 侧一定踩),预先补上 |
| ⑧ `local` 计数不剥注释、`\b` 认成员访问 | **死的看着像活的** → 分档错(混进「零风险」批) | eslint 的 unused |

⑤⑥ 的具体面目:

```
collections/SavedJobs.ts     → lib/plan 的 SAVED_JOBS_CAP
collections/SavedSearches.ts → lib/plan 的 FREE_SAVED_SEARCHES / PRO_SAVED_SEARCHES
instrumentation.ts:8         → lib/db/database 的 getDb
```

`SKIP_DIRS` 的本意是「Payload 的 collection 自己的导出是框架约定,不统计」——
但它们的 **import 照样算数**。一个集合两处用途,是这个坑的全部。

⑥ 最难看的地方是**同一个文件只错一半**:`instrumentation.ts` 第 8 行的 `getDb` 丢了,
第 9 行的 `getTopNocsCached` 因为正则从新位置重新起手反而对了。
只抽检「有没有解析到这个文件」会得出「解析对了」的结论。

⑧ 是反方向的坑,前七个都让**在用的**变成**死的**,它让**死的**看着还活着:

```ts
// database.ts 第 48 行(注释里):要兜底的用 dbOrNull。   ← local 计数 +1
function dbOrNull(...)                                    ← 全仓唯一的真实出现
const JOB_COLUMNS = SQL.JOB_COLUMNS                       ← `\b` 把后半截也算一次
```

**tsc 抓不到它**(去掉 `export` 照样编译绿),要 eslint 的 `no-unused-vars` 才亮。

### 方法论(比这四个坑更值钱)

**扫描器是取数工具,不是判据。** 判据是 `tsc`(谁真的 import 了)和 `eslint`(谁真的在用)。
本轮 4 条误判全部在动手后 3 分钟内被这两道工具当场抓住,**代价是重跑一次 tsc**;
若反过来「先信扫描器、再靠人核」,那 4 条会以「已核对」的名义留在清单上。

四个坑连同复现细节已写进 `cms/scripts/scan_exports.py` 头部(现共八条),脚本本身也一并修好。

## 4 · 模块边界闸(`no-restricted-imports`)

```
桶就是这个项目的头文件 —— 绕过去点具体文件,桶写的那份「对外是什么」当场作废,
而编译器不会有任何意见。
```

- **管三个带桶模块**:`lib/i18n` / `lib/pathways` / `lib/quiz`。
- **不管 `lib/db`**:那边是 `import * as SQL from './db/sql'` 的命名空间形态(48 处),
  调用点写 `SQL.foo()` 自解释,**设计如此不是绕过**(06 号清单已定性)。
- **直接给 `error`**:存量绕过本轮清到 **0**,不会出现「一次性红一片,结果没人再跑 lint」。
  上面那批 `react-hooks/*` 降 `warn` 是因为存量 73 条,两者判据是同一条。

### 🔴 flat config 的同名规则是**覆盖**不是合并

第一版写成两块:全局管绝对路径、`src/lib/**` 那块管相对路径。**结果 `src/lib` 下的绝对路径没人管了** ——
后一块的 `no-restricted-imports` 把前一块整条顶掉。修法是第二块把绝对模式一起带上。

相对模式只在 `src/lib/**` 生效,因为 `app/(frontend)/` 下有个同名的 **quiz 页面目录**,
`Jobs.tsx` 正当地引 `../quiz/EntryQuiz` —— 全局开会误伤。

### 探针验过(**规则不验就是装饰**)

临时造两个文件、四种写法,四条全红、正当的那条不红,验完即删:

| 写法 | 位置 | 结果 |
|---|---|---|
| `'./i18n/chat'` | `src/lib/` | ✅ 拦下 |
| `'@/lib/quiz/fields'` | `src/lib/` | ✅ 拦下(第一版这条漏了) |
| `'../lib/pathways/index'` | `src/lib/` | ✅ 拦下 |
| `'@/lib/i18n/chat'` | `app/(frontend)/` | ✅ 拦下 |
| `'./quiz/EntryQuiz'` | `app/(frontend)/` | ✅ **不**拦(那是页面目录) |

## 6 · 留下的账

### 🔴 第 2 批多两个候选:`dbOrNull` / `withTransaction`(`lib/db/database.ts`)

去 `export` 之后 eslint 亮了:**它们连自己文件里也没人用**,之前是被坑⑧盖住的。

`withTransaction` 的注释写着「seed 灌库靠它保证原子性」—— 长得就像 06 号文档里那四面红旗
(「有拍板记录的逻辑没人调用」)。**但这次不是**:`seed/route.ts` 自带事务体
(第 217 `BEGIN` / 477 `COMMIT` / 479 `ROLLBACK`,文件第 36 行注释也写明「本文件的事务体照旧不动」)。
所以它是**第二份实现没人采纳**,不是原子性丢了。`dbOrNull` 同理(「留给少数调用点」——那些调用点不存在)。

**两条都没删**,按第 2 批的规矩走人核。

### 既存的两个死别名(不是本轮造成的)

`jobsSql.ts:215-216` 的 `const JOB_COLUMNS = SQL.JOB_COLUMNS` / `JOB_FROM` —— `sql.ts` 收拢之后留下的
本地别名,现在没人用。它俩也是「本仓有两个同名 `JOB_COLUMNS`」这个陷阱的来源。

### 原样压着的

1. **`lib/resumeMatch.ts` 的 `LANG_NAME` 键是 `'zh-cn'`,`ResumeMatchModal.tsx` 发 `'zh'`** ——
   改一行但会改线上行为,**仍等点头**(这轮同样没动)。
2. **`prompts.ts` 还没建**(`advisor/route.ts` 453 行里躺着 `SYSTEM`/`GROUNDING_RULES`/`HEADINGS`)。
3. **27 张色值表**、`app/api/alerts/run/route.ts` 279 行 —— 都排在 `.tsx` 那轮。
