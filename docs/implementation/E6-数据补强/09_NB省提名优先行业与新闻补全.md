## 0.5 实施中的两处方案修正（2026-07-26，把官方原文读全之后）

立项时只读了 NB notice 页的**一条**通告就定了方案;实施时把整页读完 + 找到 MB 现行清单真页,发现两处得改:

**① NB 不做「行业→broad 大类」逐岗判定(原 ①④ 方案作废)。**
官方只给行业名(Healthcare/Education/Construction Trades)不给 NOC,映射到本站 broad 会硬猜:
NOC 大分类 4「教育」里同时装着教师、律师、警察、社工;护理员 44101 首位是 4 → 落在「教育」而不是「医疗」;
「Construction Trades」在 7 里也切不干净(73 含货车司机)。这正是 #138/#151 两次栽过的坑 → **留空不猜**。
且该限制**只针对 NB Experience 一条 pathway**(限的是新 ITA),拿它否掉全省非三行业岗属过度断言。
改为:**只落官方逐条给了 NOC 码的硬限制**(2026-02-03 起,针对 NB Skilled Worker + NB Express Entry 的 EOI/ITA):
- `nb-ineligible.json`「NB 不符合清单」14 个 NOC —— 不论行业,无条件不受理;
- `nb-ineligible-food.json`「NB 餐饮住宿不符合」13 个 NOC —— 住宿餐饮业(NAICS 72)。
  **条件性**:官方留口子「雇主不属 NAICS 72 的同款岗仍可提交」。本站无雇主行业字段(不猜),按多数情形判不符合,
  条件写进 label 与 note 由用户核对自己雇主 —— 粗筛信号,非资格认定。
行业限制这条事实**照旧上站**,走 NB 新闻(scrape_nb_nbpnp_news,上轮已建)→ 弹框「本省最新公告」,不做逐岗判定。

**② 新增 `overlay` 语义(08_score 第三种)。** NB 的排除不能套 AAIP 那种 `ineligible`——AAIP 语义是
「本省无 TEER 门槛,除清单外 TEER0-5 全可」,而 NB Skilled Worker 仍要技能岗 offer,套过去会把 NB 的
TEER4-5 岗全放开(反向错)。故 `type=ineligible` + `overlay=true` = **叠加式排除**:不动该省默认规则,只是命中即不可。

**③ MB 真页 URL 改正 + 不造 stream 维度。** 立项写的 `/work/in-demand-occupations/` 已被站方 301 到 2023 年一篇
更新通告(只有增补几条),现行总表在 **`/mpnp/idol/`**。该页按 NOC 大类分 9 节(=在需总表)+ 一节 Rural
(仅首都区外算在需)→ 落两张表;页面**没有**逐职业的 stream 限定列(正文那句是概述),**不猜 stream 维度**。

**④ SK 的 `type` 不改。** 原计划 indemand→talent-pathway;但 `type` 在 08_score 是 inclusion/exclusion 的
**语义开关**不是描述字段,塞第三个值会让语义漂移(SK 三表确实是 inclusion)。改为把「需雇主 offer + EPA、
2026 三行业配额封顶」写进表的 `note`(数据层事实)。**用户可见文案仍未做** —— pnp_occupations 无 note 列,
要展示得走 DDL,单独一件排队。
