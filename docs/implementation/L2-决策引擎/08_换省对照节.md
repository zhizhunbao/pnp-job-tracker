# L2-08 换省对照节(「换一个省会更有利吗?」)

> 承接 [E12-09](../E12-移民路径引擎/09_省提名分数参考与换省建议.md) §3.4/3.5(方案 A 拍板 2026-08-01)与
> [L2-03](03_报告分层v2c.md) 的付费闸;版式照 `docs/assets/mockups/报告v5-定稿.html` 第三节(效果图
> `报告v5-定稿-桌面.png` / `-375.png`)。
> 立项原话(E12-09 头部):「如果用户觉得自己分不够,赶紧换省换工作,不要继续耗」——
> 本站已有「这个岗能不能提名」,缺的是「**你现在够不够分、不够该换去哪**」。

## 1. 目标与非目标

- 目标:报告新增一节「换一个省会更有利吗?」——现选省 vs 备选省并排,有官方分值表的省给**自算分**
  + 官方申请门槛 / 近期抽选线,没有分值表的省明说「该省未公布分值表」。
- **不加必答题**(方案 A 的核心):打分要 8 个字段,报告只问 4+2 题 —— 用**已答项**算,
  缺项当「补齐可提高精度」的钩子指向 `/pathways` 完整估分器。
- 非目标:自建 CRS 算分、新抓分值表(BC/SK/ON 三省已在 `pnp_score_factors`)、把打分题塞进报告问卷。

## 2. 方案

### 2.1 分数怎么来:**已答项的下界分**,不是完整估分

报告手上只有 `clb`(英语档)与 `canadianExpMonths`(加拿大经验档),官方分值表还要学历/年龄/二语/时薪/地区。
**分值全为非负 → 已答项之和是一个真实下界**,所以句子写「至少 N 分」、尾标 `N+ / 200`,并同一行说清
「完整估分还差 X 项」。这样既给得出 Frank 要的「分数」,又不冒充完整估分。

红线三条:
- **未答的因素一律不参与匹配**(不能让 CLB 缺答落到「Below 4」那档白捡分)——
  `scoreProvince` 加第 6 个参数 `only`(白名单),只有 `language/language1`(有 clb 时)与
  `work/work5`(有加拿大经验时)进自动匹配,其余全算未答。
- **只在下界已过门槛时下「已达标」判定**;下界低于门槛**不说「不达标」**(缺项补齐后只会更高)。
- 免责句**不逐节重复**(2026-08-01 Frank「这个废话删了」):法律免责由全站页脚那句统一承担;
  每行都写「离**该省**门槛差多少」,本来也没请人横向比分数。

加拿大经验当「同职业经验年数」用是**下界口径**(境外经验也算分,我们没问)——句子里写「按你已答的
语言与加拿大经验」,不写「你的经验」。

### 2.2 引擎:`Report.switches`(第三个新增节,同 requirements/employers 先例)

`switchLines(facts, dims, profile, extra, targets)` 纯函数,产出:
1. **现选省一行**:有分值表 → `rpt.s.cur`(至少 N 分);无 → `rpt.s.cur.noTable`(该省未公布分值表)。
2. **备选省每省一行**(排除现选省与 QC,按具名命中 → 在招量排序,cap 3):
   下界已过门槛 → `rpt.s.alt.pass`;有门槛未达 → `rpt.s.alt.mark`(带「最多差 X 分」);
   无门槛 → `rpt.s.alt.plain`;通道对不上抽选 → `rpt.s.alt.noDraw`;无分值表 → `rpt.s.alt.noTable`。
   每行的**行尾灰字**挂该省最近一次抽选(见 §2.4)。
3. **可操作两条**:`rpt.s.next`(先补哪一项最值钱 → `/pathways`)、`rpt.s.offer`(拿到该省 offer 官方给几分)。

挂在 pr / prov / job 三张卡(career 是职业跃迁,不涉及省);`ReportFacts` 新增 `scoreFactors`
(整张 `pnp_score_factors`,120 行,一次 SELECT),`scoreProvinces` 由它派生 —— 原先那条
`SELECT DISTINCT province` 撤掉,少一次往返。

### 2.3 付费闸(gateReport)—— **整节收费**(2026-08-01 Frank 看实拍后拍板)

初版做的是「免费给省级事实、锁分数」,实拍出来四行全是「该省有没有分值表」——
Frank 原话:「**你这说完不是等于没说么**」。他说得对:这一节的标题是个问句,而**回答那个问句的东西就是分数**,
分数一锁,免费层剩下的是废话不是 aha。免费层的 aha 由清单命中与「有 N 家雇主」那两句承担,不靠这节。

所以:**免费层整节不下发**(`switches: []`,响应体里 grep 不到 `rpt.s.`),
只在锁区留一行问句当广告 ——「换省会不会更有利:各省自算分与门槛差距」(`rpt.lock.score`)。

配套:锁区里必须有可操作的东西,不然解锁完还是一堆「至少 N 分」。Pro 侧新增三样(全是官方表里的数):
① **离门槛还差多少分**(下界与门槛的距离是差距的**上界**,句子写「最多差 X 分,补齐只会更近」);
② **先补哪一项最值钱**(现选省未答因素里 `factorMax` 最大的那个,译名复用 `ps.f.*` 单一来源);
③ **拿到该省 offer 官方给几分**(只有官方表真有 `offer` 因素的省才出,SK 30 分;BC/ON 没有就不编)。

### 2.4 抽选事实进行尾灰字(2026-08-01 Frank 追问后加)

Frank:「不需要显示一下最近的最低分数吗?以及池子大小,以及他们在池子里待了多长时间吗」——
**有的给,没有的不编**:
- **最近一次抽选线**:有(`pnp_draws.score`)→ 每省一行的行尾灰字;
- **每轮邀请人数**:有(`pnp_draws.invitations`,官方每轮公布)→ 与最近一次一起给;
- **候选池规模、在池等待时长**:本站没有,**各省官方也不公布**(BC/SK/ON 都只公布逐轮结果,不公布池子)——
  不写、也不拿别的数冒充。真要这两个数只能靠用户自报聚合,那是另一件事(且样本偏差极大)。

红线跟着抽选线那条走:**该省近几轮跨了多个通道就只给区间**(BC 近 6 次里 Rural Health 50、Innovate 132,
把 50 说成「BC 最近一次」会让人以为自己够线了);没有分值表的省(MB)照样给抽选事实 —— 那与「能不能自算分」是两回事。
行尾灰字本来就是 v5 定稿 HTML 里的 `.tail`,实装时欠着,这次补上(桌面右对齐、手机自成一行)。

### 2.5 省份下拉 + 抽选明细展开(2026-08-01 Frank「最好有个下拉列表吧」)

「只给 3 个备选省」本来就是替用户做主。改成:**引擎把每个候选省都算好**,前 3 个直接摆出来,
其余打 `more` 标记 → 显示层一个原生下拉「再看一个省…」,选中即加进列表(选过的从下拉里消失)。
候选池=该职业有在招或在公开清单上的省,排除现选省、QC、排除清单省。

行尾灰字可点开:`tail.rows` 带该省近 6 次的**逐轮明细**(日期 / 通道 / 分数线 / 邀请数,全是官方公布的字段)。
通道过滤对明细同样生效 —— 打分表自报通道的省(ON)点开也不会冒出旧通道的分。
手机上通道名给两行余地(截成「Temporary R...」等于没显示),桌面整行显示。

### 2.6 版式

复用现成 `Sec` + `Line`(v5 定稿节结构),节标题 `rpt.q.switch`「换一个省会更有利吗?」,
位置在雇主线索之后、薪资之前(照定稿 HTML 的顺序)。无新组件、无新样式。

## 4. 红线

- 未答因素不参与匹配(白名单),否则「没考语言」会被判成最低档白捡分。
- 下界低于门槛只陈述门槛,**不说不达标**。
- 跨通道混抽只给区间,不把最低那条通道的线说成「该省最近一次」。
- 分值一分不许前端编,全部来自 `pnp_score_factors`(官方抓取入库)。
- 免费响应里 grep 不到自算分。
