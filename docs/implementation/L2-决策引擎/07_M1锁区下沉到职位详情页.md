# L2-07 M1:锁区铺到人真正落地的地方(职位详情页)

> 主线第一格,判据见 [主线与支线](../../主线与支线-20260801.md)。
> 事实基础:30 天 Umami —— **入口=出口=职位详情页**、67.5% 只看一页、`/pricing` 只被打开 1 次。
> 也就是说:锁区一直挂在报告页里,而**人根本走不到那儿**。

## 1. 目标与非目标

- 目标:详情页那张报告入口卡上,直接露出**这一行职业的锁区**(有几家雇主发过能走省提名的岗),
  并埋下 M2 需要的第一格数据(曝光/点击)。
- 非目标:名单本体(仍在服务端锁着)、定价改动、报告页改版、其余入口(公司页/榜单)。

## 2. 方案

### 2.1 数据:扩已有端点,不新开

`/api/quiz?noc=` 的 `fetchQuizFacts` 多返回一个 `sponsors`(**只给家数,不给名单**)。
WHERE **与 `reportFacts` 的名单口径逐字一致**:清单式省认具名通道、不公布清单的省(`NO_LIST_PROVINCES`)认粗筛可提名 ——
两处对不上,详情页说「74 家」而报告里名单是另一批,用户第一眼就抓到我们数不准(8-01 已经撞过一次)。

### 2.2 版式:免费的先给足,锁行只摆标题与家数

卡内顺序不变(本岗 vs 中位 → 本省在招 → 粗筛可提名 → 全国中位薪资),末尾加一行锁行 + 主按钮。
锁行整块可点(能点才有 hover 和小手),落到 `/plan/job?noc=…&view=report`,名单该锁的仍锁着。

两条不能破:
- **有货才挂**:`sponsors = 0` 不渲染锁行(不卖不存在的东西);
- **aha 在掏钱之前**:免费三行 + 本岗薪资对比照旧全给。

### 2.3 埋点(M2 的原料)

- `jd-lock-seen` —— **锁行真的渲染出来**时打一次(不是页面加载就打,否则漏斗第一格是假的);
- `jd-lock-click` —— 点了锁行。
- 既有 `jd-report-open`(点主按钮)保留。

## 3. 影响面

`QuizFacts` 多一个字段;详情页卡多一行;三语 2 个新键。未动:报告引擎、付费闸、名单口径。

## 4. 验收

- [x] `/api/quiz?noc=31301` 返回 `sponsors: 74`,与报告里的计数同口径
- [x] 375 / 1280 实拍:锁行渲染、文案一行不折、零横滚
- [x] 埋点实测:进视口后只打一次 `jd-lock-seen`
- [ ] 生产复验 + 一周后看 M2 的第一格数(曝光 → 点击率)

## 5. 风险与回退

- **口径漂移**:两处 WHERE 必须一起改 —— 这是最容易再犯的错,已在两边代码里互相点名;
- **过度打扰**:锁行只占一行、无弹窗、无遮挡;`sponsors=0` 直接不渲染;
- **回退**:卡片本就是自包含组件,删掉锁行那段即回原样。

## 6. 后续(M2)

漏斗五个数串成一条能读的线:详情页 PV → 报告打开 → **锁区曝光** → pricing → 付费。
现在有了 `jd-lock-seen` / `jd-lock-click`,还缺:报告页锁区曝光事件、pricing 到付费的归因。
**M2 出数之前不许再加功能**(见主线纪律第 3 条)。
