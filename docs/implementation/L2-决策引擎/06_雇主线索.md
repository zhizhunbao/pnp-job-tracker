# L2-06 雇主线索(锁区里已经在卖的那份名单,实装)

> 2026-08-01 Frank「开始做雇主线索」。承接 [L2-03](03_报告分层v2c.md) 的付费闸:
> 锁区一直挂着「有担保记录的雇主是哪几家」,但**名单本体没实装** —— 解锁了也只有一个数字。
> 这是我判断的三样真能收钱的东西之一(另两样:变化提醒、时间线判断)。

## 1. 目标与非目标

- 目标:卡①「找工作」报告里,Pro 拿到**具体雇主名单**;免费拿到「有 N 家」+ 锁行。
- 非目标:雇主评级/推荐度(「这家好签」是判断不是事实,红线);雇主联系方式;跨卡铺开(先只做卡①)。

## 2. 方案

### 2.1 数据:一条 SQL,零新表

`reportFacts.assembleOccStats` 里加一条聚合(与既有的 sponsors 计数**同一口径**,只是不 count 而是列出来):

```
jobs(在招 ∧ noc=? ∧ pnp_stream 非空) JOIN companies
GROUP BY 公司 → named 岗数 / 最近发布日 / 最近那条岗的省市
挂公司级事实:is_designated_employer(AIP)、lmia_positions + lmia_last_quarter(ESDC 正面 LMIA)
ORDER BY named DESC, 最近发布 DESC   LIMIT 12
```

排序口径:命中清单岗多的在前,同数看谁最近还在发 ——「还在招」比「历史上招过」有用。

### 2.2 契约:结构化行,不是句子

`Report` 新增 `employers: ReportEmployer[]`(name/slug/named/city/province/lastPosted/lmiaPositions/lmiaQuarter/aip)。
**没有走 ReportLine**:这是一张表,站规是「多值拆列网格对齐」,硬塞进一句话既难读又对不齐。

### 2.3 付费闸:免费层响应体里根本没有名单

- `gateReport` 非 pr 卡:`employers: []`,锁行 `sponsors` 由 **employers 非空**触发(名单空就不挂锁行 —— 不卖不存在的东西);
- **口径改了一处**:`rpt.j.sponsors`(「有 N 家雇主发过清单岗」)从锁区**放回免费层** ——
  它是这张卡最像 aha 的一句,连它一起锁,免费层就什么都没有了;锁的是**名字**,那才是「花钱买省下来的时间」。

### 2.4 措辞红线

节下第一行就写死:「**是否愿意担保只有雇主自己知道**,下面全是可核验的公开事实」。
名单里只出现:命中清单的在招岗数、地点、ESDC 批过多少 LMIA(带季度)、在不在 AIP 名单、最近发布日。
不出现任何「容易/推荐/靠谱」类判断。

## 3. 影响面

- `assembleOccStats` 多一条查询(卡①/⑥ 才调,拿 PR 不查);`Report` 加一个数组字段(四个 builder 全显式返回);
- 三语 5 个新键 + 一个新节;未动:清单判定、抽选、门槛对照、匹配引擎。

## 5. 风险与回退

- **名单会过期**:雇主停招后岗位转 closed,名单自然掉出(查询只看在招);不做历史留存。
- **同名不同主体**:公司名归一在 ETL 层做过(`norm_name`),但仍可能把连锁的不同门店算成一家 —— 现在按 `companies.id` 分组,门店各算各的,宁可分散不合并。
- **回退**:`employers` 恒空即回到改前(节不渲染);SQL 单独 catch,查挂了只丢名单不影响报告。
