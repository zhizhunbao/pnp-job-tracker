# L2-01 七目标决策树(每张卡片一棵树)

> 2026-07-30 Frank:「我每个决定的卡片都需要有一个单独的决策树吧」——是。
> 承接 [产品架构v2.0](../../产品架构v2.0-决策智能平台.md) L2 与 [L1-01 Landing 页](../L1-用户目标层/01_landing页.md)。
> **共用的是引擎与报告契约,不共用问题**:七个目标各有一棵问题树,答完落进同一个 `report` 结构。

## 1. 目标与非目标

- 目标:定死每棵树的**问题、分支、判定规则、证据来源、出口**,以及「数据不够时说什么」。
- 非目标:UI 步进器样式(并入 L1 施工)、付费墙位置(收费方案已定:结论页才收费)、新数据抓取(缺口只标注不立项)。

## 2. 所有树共用的骨架:问题分两层

2026-07-30 Frank:「问题也要分基本问题和深入问题,还有给用户解释你是什么样的人、适合什么样的方向,类似九型人格那种。」

```
基本问题(5 题以内,全站共用一次,零打字点选)
  → 画像卡:你是哪一型 + 适合什么方向 + 为什么(带数)     ← 免费,人人可得,回访钩
       ↓ 点任一目标卡片
深入问题(每棵树自己的 1-3 题,见 §3)
  → 规则引擎(纯函数,读库内维度表)
  → report:结论 + 依据 + 缺口 + 下一步 + 备选
```

- **基本问题 = 已上线的分型五问**,不另起炉灶:`currentStatus`(E11-04)+ 职业 + 语言 + 加拿大经验 + 目标省,
  控件与分叉全用 `OnboardingWizard`(E11-05)。答过就永不再问,深入问题只补该树缺的那 1-3 题。
- **两层的分界**:基本问题决定**你是谁**(画像),深入问题决定**这件事怎么办**(结论)。
  一道题如果换个答案不会改变结论,它两层都不进。

### 2.1 画像卡:**可叠加的处境标签,不是九选一**

2026-07-30 Frank 两次澄清:「九型人格不是说只有 9 种情况」「人家那种性格测试一般会搜集很多问题」。落到本站:

- **画像 = 一句话概括 + 若干可叠加标签**。标题由答案组合出来(「在读学签的注册护士」),不从固定枚举里挑;
  标签由规则命中产生,命中几条列几条 —— 紧缺职业、清单命中、需职业认证、毕业窗口内要落定、低 TEER、无具体通道、
  薪资低于门槛、该省不公布清单、雇主有担保记录、偏远地区可加分、语言分未达线、工签剩余不足一年……
  **标签库随规则增长,不设上限**;组合空间 = 各维度取值的乘积,不是 9 个格子。
- **题多是因为结论多,不是为了做题**。每道题仍必须绑定一个字段并影响至少一条结论,进不了这条的题不入库。

### 2.2 题库与追问节奏(像性格测试那样"问很多",但每题都算数)

| 维度 | 题数(v1 目标) | 决定什么 |
|---|---|---|
| 身份与时间线 | 8 | 分叉起点、签证剩余、家属随行 |
| 职业与经验 | 10 | NOC、TEER、年限、证书牌照 → 清单命中与门槛 |
| 语言 | 6 | CLB 档、考试类型、成绩有效期 → 通道门槛与分数 |
| 教育 | 6 | 学历层级、是否加拿大学历、DLI、专业方向 |
| 地域与约束 | 5 | 目标省、能否搬家、偏远接受度 → 可选通道集 |
| 资金与家庭 | 5 | 存款证明档、随行人数、配偶职业与语言 |
| 求职现状 | 6 | 有无 offer、雇主类型、LMIA 意愿、工资档 |

节奏:**基本 5 题 → 出画像 → 每次追加一批(4-5 题)→ 画像与结论同步变细**。

- **自适应抽题**:引擎只问「当前还悬着的分支」需要的题(例如已判定走 BC 且语言未填 → 先问语言),不按固定顺序灌题。
- **画像完整度**是进度也是钩子:卡上显示百分比与「再答 N 题可算:能不能走 EE、差多少分」——把下一批题的**回报**说清楚再问。
- 每批答完立刻更新标签、结论与 `confidence`;不答也能用,只是结论粗、置信度低。
- 采集控件复用 `OnboardingWizard`(E11-05)的零打字点选;题库是**配置**(`lib/questions.ts`:字段、选项、影响哪些规则、属于哪层)。

红线:① 标签是**处境描述不是资格认定**,卡上写明「按你自报的情况归类」;② 每条标签与方向必须挂库内事实(清单命中数、在招量、抽选线、中位薪资),挂不上就不显示;③ 缺字段的标签**不出**(如配偶联动需配偶字段);④ 改答案立刻重算,不做「测过一次定终身」。

四条铁律:

1. **每多一题必须能改变结论**,否则删。答过的题跨树复用(档案已存的直接跳过)。
2. **无解不给空页**:命中为 0 时给「差什么、差多少、换哪条」,这本身就是结论。
3. **每条结论带证据**(`source_url` + `as_of`),数据不足时降 `confidence` 并写明为什么,不硬编结论。
4. **数据缺口照实说**:生活成本、专业(program)两项没有数据源,在结论里明确「未计入」,不装作算过。

## 2.3 「很懂你」从哪来(2026-07-30 Frank:让用户觉得很懂他,才会付费)

题海不产生「懂」。**懂 = 用他给的 4 个答案,说中他没说出口的事**。五种句式,全部由规则 × 库内数据生成,不是文案:

| 句式 | 例(真实库内数据) | 为什么显得懂 |
|---|---|---|
| ① 说中他没提的卡点 | 「注册护士在 BC 有 17 个在招、全部命中具体通道;但你得先过 NNAS 认证才能注册执业」 | 他只说了职业和省,认证是我们替他想到的 |
| ② 给数不给形容词 | 「BC 差 12 分,SK 够线」 | 「分可能不够」谁都会说,差多少只有算过的人知道 |
| ③ 点破他正在踩的坑 | 「你现在的雇主是派遣公司,430 个同类岗里 0 个命中具体通道」 | 说破他自己没意识到的死路 |
| ④ 预判下一问 | 他问 BC,顺手给 SK 对照:「同职业月薪低 $300,但快一年」 | 顾问才会主动给的备选 |
| ⑤ 把时间摆上台面 | 「你签证还剩 8 个月;BC 近 4 次抽选平均 12 天一轮,你还能赶上约 20 轮」 | 把抽象焦虑变成可数的窗口 |

配套三条,少一条「懂」就翻车:

1. **一条错全盘归零**。每条结论必须可点开依据(数据 + 出处 + 日期);算不准就标 `confidence` 低,或直接说「这个省不公开算分,只能给规则对照」。宁可说不知道,不可猜。
2. **懂在免费层就要发生**。基本 4 题后的画像与前两条结论**免费**,aha 必须在掏钱之前 —— 循 [收费方案](../../design/收费方案-20260727.md):事实与「说中」免费,完整报告与持续盯梢收费,界线仍在「事实 → 结论」。
3. **样本小就说小**。上表 ⑤ 的 12 天出自库内 4 次抽选,文案必须写「近 4 次」,不能写成规律。

## 3. 七棵树(下表「特化问题」= 深入问题层;基本五问已答的不重复问)

### ① 找工作(数据齐,可直接做)

| | |
|---|---|
| 特化问题 | Q1 职业(NOC 搜索,可多选) · Q2 目标省或城市(可「不限」) |
| 规则 | jobs 按 NOC × 地区检索 → 命中省清单/EE 类别/AIP → `match.ts` 与档案比对 |
| 结论 | 「你的职业在 X 省有 N 个在招,其中 M 个命中具体通道,中位 $Y」 |
| 证据 | jobs(在招数、发布日) · pnp_occupations(清单行) · wages(ESDC 中位) |
| 出口 | 职位板(预设筛选) · 职业实体页 |

### ② 拿 PR(付费核 A 的入口,树最深)

| | |
|---|---|
| 特化问题 | Q1 职业 NOC · Q2 语言(有成绩填分/没考过) · Q3 加拿大工作经验(无/<1年/1-3年/3年+) · Q4 学历 · Q5 目标省(可「帮我选」→ 转 ③) |
| 规则 | TEER 判定 → 各省清单命中 → 通道门槛比对 → 分数参考(BC SIRS 可算;ON EOI 未公开只摆规则) |
| 结论 | 「可能走 A、B 两条;BC 差 12 分,SK 够线」+ 每条缺口与补法 |
| 证据 | pnp_occupations · pnp_draws(历次分数线) · pnp_score_factors · ee_categories |
| 缺口 | 多数省不公布 EOI 算分表 → 该省结论 `confidence=低`,只给规则对照不给分差 |
| 出口 | /pathways 方案卡 · 省实体页 |

### ③ 选省份

| | |
|---|---|
| 特化问题 | Q1 职业 NOC · Q2 语言 · Q3 有无加拿大经验或亲属 |
| 规则 | 十省逐个算:清单命中 → 通道门槛 → 最近分数线 → 在招量 → 竞争比(difficulty.json) |
| 结论 | 省份排序 + 每省一句「你在这的门槛与差距」;QC 单独说明走自己体系 |
| 证据 | pnp_occupations · pnp_draws · stats(在招/薪资) · difficulty |
| 出口 | /stats · 省实体页 |

### ④ 选城市

| | |
|---|---|
| 特化问题 | Q1 省(或不限) · Q2 职业 · Q3 是否接受偏远地区(RNIP/AIP 加分) |
| 规则 | stats_city 在招量 × 中位薪资 × 是否在 AIP/RNIP 地区 |
| 结论 | 城市短名单 + 「在招多但薪资低 / 薪资高但岗少」的权衡说明 |
| 缺口 | **生活成本无数据源** → 结论必须写明「未计入房租与税后收入」,不排「宜居度」 |
| 出口 | 城市实体页 · 职位板(按市筛) |

### ⑤ 选学校

| | |
|---|---|
| 特化问题 | Q1 目标省(或不限) · Q2 目标职业或行业 · Q3 学历层次(学院/本科/硕士) |
| 规则 | DLI 名单(可申 PGWP)× 所在省 × 该省清单职业 |
| 结论 | 学校短名单 + 「读完这条路怎么走」(PGWP → 工作 → 提名)与各段门槛 |
| 缺口 | **只到学校层**:专业(program)无数据 → 明说「专业与清单职业的对应未覆盖」 |
| 出口 | 学校实体页 · ② 拿 PR 树 |

### ⑥ 职业规划

| | |
|---|---|
| 特化问题 | Q1 现职业或专业 · Q2 是否愿意转行 · Q3 目标省 |
| 规则 | NOC 邻近(同中类/大类)× TEER × 清单命中 × 在招量 × 中位薪资 |
| 结论 | 「与你相邻的这 3 个职业更容易走通道」+ 每个的差距(证书、语言、年限) |
| 证据 | noc_categories · pnp_occupations · stats_occupation · wages |
| 出口 | 职业实体页 · 技能实体页 |

### ⑦ 选专业 —— **不上树**

无 program 数据源。卡片保持灰态,点不动;数据到位前不做问题树,也不用 AI 编。

## 4. 复用与边界

- 问题控件、进度、记忆全部复用入口三问 `EntryQuiz`(组件提到 `(frontend)/quiz/`);**七棵树是配置,不是七个组件**。
- 树定义写成数据(`lib/trees.ts`:目标 → 问题 → 分支 → 规则名),引擎读配置执行 —— 加一棵树 = 加一段配置。
- 结论一律走 `report` 契约;免费给结论摘要,完整报告与「替你盯着」按收费方案分层。

## 5. 验收

- [ ] 基本五问答完出画像卡:一句话画像 + 命中标签 + 方向 + 风险,均带库内数字与出处
- [ ] 追问按批(4-5 题)推进,画像完整度与结论 confidence 同步变化;每批前先说清能算出什么
- [ ] 题库为配置,每题可追溯到「影响哪条结论」;挂不上结论的题不入库
- [ ] 改答案 → 标签与结论实时重算;缺字段的标签不出现
- [ ] 七卡片各自进入自己的问题树;基本层答过的题不重复问
- [ ] 每棵树在「零命中」时给缺口与备选,不出空页
- [ ] 每条结论可展开证据(来源链接 + 数据日期)
- [ ] ④ 明示未计生活成本;⑤ 明示未覆盖专业;⑦ 不可点
- [ ] 树定义为配置,新增一棵不改引擎代码
