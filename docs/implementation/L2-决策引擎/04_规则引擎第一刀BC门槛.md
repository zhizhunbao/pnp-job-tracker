## 1. 目标与非目标

- 目标:BC 官方门槛入库 → 纯函数引擎求值 → 报告新增「门槛对照」节;免费/付费界线照设计 §6。
- 非目标:**不加任何新题**(六条规则里四条吃已问字段);SK/ON 门槛(第二刀);学历与年龄题;
  「补完够哪条通道」的跨省排序(付费文案里承诺的那半,等第二个省进来再做)。

## 2. 方案

### 2.1 数据层:`etl/pnp/build_bc_req.py` → `data/raw/pnp/bc-req.json`

来源与 `build_bc_sirs` 同一份官方 PDF(Skills Immigration Program Guide;网页正文只写「详见指南」)。
抓四类共 20 条,每条带官方原文与节号:

| 节 | 门槛 | 落到谁 | 值 |
|---|---|---|---|
| 3.4 | 语言 | 申请人 | TEER 2/3/4/5 → 四项均 CLB 4;TEER 0/1 → 注册时不强制(`op='none'`) |
| 3.10 | 最低家庭收入 | 申请人 | 家庭人数(1..7)× 区域(大温 / BC 其余)= 14 行,$26,057–$82,739 |
| 4.1(c) | 技术工作经验 | 申请人 | 近十年内 ≥2 年(24 个月)TEER 0-3,**境内外都算** |
| 6.7 / 6.8 | 经营年限 / 全职雇员数 | **雇主** | 在 BC 经营 ≥1 年;大温 ≥5 人、大温外 ≥3 人 |

自校是硬闸(照 `build_bc_sirs` 惯例):任何一组没解析到、收入表不递增、大温档不高于其余档 →
**保留旧表不覆盖**并 exit 1。门槛错一位比没有更危险(用户照着它决定考不考雅思)。

### 2.2 集市层与 DB

- `etl/09_build_mart.py`:`IN_REQ_TABLES`(一省一个文件,加省=加一行)→ `mart/pnp_requirements.json`;
  `appliesTeer` 存 `"2,3,4,5"` 文本(Payload 没有整型数组列)。
- `docs/sql/e13-01-pnp-requirements.sql`:建表 + 两个索引 + **`payload_locked_documents_rels` 补列**
  (少了它 seed 500 无 body,见 [[new-etl-dim-table-checklist]])。DDL 先行,生产先跑再 push。
- `cms/src/collections/PnpRequirements.ts` + `payload.config.ts` 注册 + `seed/route.ts` 白名单映射。

三张 `pnp_*` 表各答一个问题:occupations=**在不在**清单、score_factors=**能打几分**、requirements=**先要满足什么**。

### 2.3 引擎:`cms/src/lib/rules.ts`(纯函数,无 IO)

```ts
evaluateRequirements(reqs: Requirement[], p: RuleProfile): RuleResult[]
// verdict: 'pass' | 'fail' | 'unknown';fail 才带 short(差多少)
```

判定口径(单测逐条锁死):

- **unknown 是一等公民**:没收录、没答、判不了 → unknown,绝不滑成 pass/fail;
- **经验的非对称**:官方要的是境内外都算的技术经验,站内只问了**加拿大**经验 →
  够了判 pass(子集够则总量够),不够只能 **unknown**(他可能有海外经验),不许判 fail;
- **收入的下界推理**:家庭人数与居住区域都没问 → 用 1 人档 + 两区域档做上下界。
  最低那档都够不到 = 任何情况都不达标 → fail;两档之间 / 人数未知 → unknown,只摆门槛;
- **收入的对照基准**是「该职业在该省的 ESDC 官方中位年薪」(岗位自带的事实,设计 §4 规则 2),
  **不是他本人的工资** —— 文案里必须写清,否则等于替他填了一个他没说过的数;
- **雇主侧恒 unknown**:经营年限/雇员数本站没有,照实说「只有雇主拿得出材料」(设计 §3.5)。

### 2.4 报告与付费闸

- `Report` 契约新增 `requirements: ReportLine[]`(七卡共用,当前只有卡② 拿 PR 填);
  `reportFacts` 整表取回 `pnp_requirements`(几十行)+ 各省 ESDC 中位年薪,按省筛交给引擎(纯函数好测)。
- 免费/付费照设计 §6:**免费=门槛是多少 + 达标/不达标**(官方事实,锁了只是挡路);
  **付费=差多少**(`gateReport` 把 `rpt.r.*.fail` 换成 `.failFree` 并把 `short` 从响应体里摘掉)。
  锁行 `req` 只在真有 fail 行时才挂 —— 全过就没有「差多少」可卖,不卖不存在的东西。
- UI:`PlanPrView` 报告态在「结论」与「还差什么」之间插一节「门槛对照」,行样式复用 `Line`;
  出处按 URL 去重进底部「依据与链接」(全站唯一对外出口),label=`BC PNP — official program guide`。

## 5. 风险与回退

- **官方改版**:PDF 结构变 → 自校不过、保留旧表并 exit 1(不会静默写坏门槛);
  正文文案改写(如把「at least five」写成数字)会导致解析空 → 同上,日志里喊。
- **回退**:`requirements` 为空数组时报告与改动前完全一致(该节不渲染),
  数据层回退=不灌 `pnp_requirements` 表;代码回退=revert 本批提交。
- **口径风险**:收入行拿职业中位当基准,若用户理解成「我的工资」会误判 —— 文案已写「你这行在当地的官方中位年薪」;
  家庭人数入题库后可升级成真判定(那才是设计 §4 里「新增两道题」的位置)。
