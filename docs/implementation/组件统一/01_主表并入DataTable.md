## 2 · 实测前提(动手前先核,别照抄本节)

主表带着 DataTable 目前**没有**的四样能力,合并方向只能是把它们搬进 DataTable:

1. **服务端排序** —— 主表数据量大,排序走 URL/后端;DataTable 是客户端全量排序。
2. **冻结列** —— 横向滚动时首列钉住。
3. **拖列宽 + 持久化** —— DataTable 有拖拽但不落盘;主表宽度存 cookie/localStorage(见 `colWidths.ts`)。
4. **字段显示面板** —— 用户自选列,列集本身是状态。

另有 Pro 剥离(锁列)、行内弹框动线、通道胶囊列等主表专属渲染。

## 3 · 方案(两条路,开工前选一条)

- **路 A(增量,推荐先评估)**:把上述 4 项逐项搬进 DataTable 成为可选能力,主表改吃 DataTable。
  好处=真正一套;风险=DataTable 被撑成重器,7 个现有用点全在回归面上。
- **路 B(收敛口径,不合并实现)**:承认「简单表 / 数据网格」是两类件,把共享面收敛到
  **视觉 token + 单元格渲染约定**,并在文档里写死边界。好处=风险可控;代价=Frank 的
  「统一用 jobtable 的 table」没有兑现,只是把两套讲清楚。
