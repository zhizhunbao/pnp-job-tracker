# E7-05 · 漏斗五个数(主线 M2)

> 主线 [M2](../../主线与支线-20260801.md#1-主线队列有序一次只推一格):**详情页 → 报告 → 锁区曝光 → pricing → 付费**。
> 立项理由(那份文档原话):「埋点件都在,只差串成一条能读的线。现在连**多少人见过锁区**都不知道。」
> M3 的两种分叉(曝光够点击少=锁的东西不值钱 / 曝光就少=入口问题)在没有这五个数之前分不开。

## 1. 目标与非目标

- 目标:五个数**每天能看**,且能按天回看 30 天;锁区曝光这一步第一次有数。
- 非目标:替代 umami(流量/来源/国家继续看它)、做通用 BI、按用户画像切分、做图表。

## 2. 为什么自己记,而不是从 umami 拉

试过了:umami cloud 的分享链接能拿到 `token`(`/analytics/us/api/share/<id>` 返回 200),
但拿它去调 `/websites/{id}/metrics` 一律 **401** —— 免费档不开放 API,要拉数就得升套餐(花钱的事 Frank 亲手,且不该为五个数买单)。

更重要的是**口径**:umami 脚本会被广告拦截器挡掉,而「锁区曝光」正是要精确计数的那一步 ——
拦截率未知的数字不能拿来做 M3 的分叉判断。所以走第一方:自己的 API、自己的库,拦不掉。

按决策阶梯:不引依赖(Postgres + 现成 API 路由 + 现成 admin 角色就够),表只存**按天聚合的计数**,
不存明细、不存 IP/UA/用户 id —— 天然匿名,隐私承诺不用改口径(文案补一句"计数存在我们自己的库")。

## 3. 方案

### 3.1 表:`funnel_events`(日聚合,一行=某天某事件某分组的次数)

```sql
CREATE TABLE IF NOT EXISTS funnel_events (
  day date NOT NULL, event text NOT NULL, prop text NOT NULL DEFAULT '',
  n integer NOT NULL DEFAULT 0, PRIMARY KEY (day, event, prop)
);
```
`prop` 只放**低基数**枚举(卡名 pr/job/prov、锁区类别 score/sponsors…),不放 NOC 之外的自由文本。

### 3.2 `/api/track`:白名单 + UPSERT,别的一概丢掉

事件名不在白名单 → 静默 204(前端不该因为埋点报错;库里也不该被垃圾事件撑爆)。
归一与白名单是纯函数(`lib/funnel.ts`),单测锁行为;路由只做 UPSERT。

### 3.3 五步事件(缺的补齐)

| 步 | 事件 | 现状 |
|---|---|---|
| ① 详情页 | `jd-open` | 有(`modal-jd`)→ 同时打第一方 |
| ② 报告 | `report-open` | 有(`plan-*-report`、`jd-report-open`)|
| ③ **锁区曝光** | `lock-seen` | 详情页有(`jd-lock-seen`);**报告页缺 → 补**(锁区进视口才算,不是渲染即算)|
| ④ pricing | `pricing-open` | 有 |
| ⑤ 付费 | `pay-click` + **真实付费** | 点击有;真实付费不靠事件,直接数 `users.proUntil`(唯一付费真相)|

`lib/track.ts` 一处改动:原来只喂 umami,现在同时 `sendBeacon('/api/track')`。调用点不动。

### 3.4 看的地方:`/funnel`(role=admin 才渲染,其余当不存在)

一张表就够:五步 × (30 天合计 / 最近 7 天 / 昨天) + 相邻两步的转化率 + 真实付费人数。
不做图表(现在数据量画出来是噪声,等有量再说)。

## 4. 红线

- 白名单之外的事件不入库;`prop` 只收低基数枚举。
- 只存按天计数,**不存任何可识别到人的东西**(没有 IP、UA、user id、session id)。
- 转化率分母为 0 时显示「—」,不显示 0% 或 NaN。
- 「真实付费」数 `proUntil`,不数 `pay-click`——点击不是钱。
- 页面对非 admin **不存在**(404),不是隐藏。

## 6. 落地记录

2026-08-01 施工完成。112 测试绿、tsc 干净;实拍 `docs/assets/mockups/漏斗五个数-375.png`。

**本地实测(dev 直连生产库)**:
- 打开报告页 → 滚到锁区 → `navigator.sendBeacon('/api/track')` 发出 → 表里出现
  `(今天, lock-seen, job, 1)` —— 端到端通了(验完把这行删掉,免得把自测算进真实数据)。
- `/funnel` 匿名访问 → **404**(闸门对);临时旁路闸门实拍页面,验完即恢复。
- **`stripe_customer_id` 那列全库是空的**(92 个用户 0 个有值)—— 一开始拿它当「走过 Stripe」的信号,
  实核发现会永远显示 0 = 假数;改数 `stripe_sessions`(webhook 拨 proUntil 时写的 session id),实测 2 人。
- 手机版:五列在 375 下会把步骤名折成三行 → 砍掉「7 天/昨天」两列(趋势不是手机上的重点),
  表格改 auto 布局、步骤名不折行;页面不横滚。

**没做的**:图表(现在数据量画出来是噪声,等有量再说)、按 NOC/省切分(高基数,会把日聚合表变明细表)、
umami 那边照旧(流量/来源/国家继续看它,两套口径互不干扰)。
