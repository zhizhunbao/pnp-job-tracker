# E9-06 · 网页客服（解释内容归口 + 用户反馈入口）

> 立项 2026-07-26（Frank：「我们之后可以做一个网页客服，**把解释性的内容都放那里**和收用户反馈」）。
> 与同日拍板的硬规矩配套：页面上的解释类文案一律删（只留法律免责 / ≠资格认定 / tooltip 口径 / 空态引导），
> 删掉的解释**不是消失，是搬家** —— 搬进客服窗口，想问的人才看。

## 1. 整体目标

一个常驻的小窗口，承担两件事：① 回答「这个词什么意思、这个数怎么来的」（解释库）；
② 收用户反馈（数据错了、想要什么功能）。页面因此保持只放事实与结论。

## 2. 验收标准

- [ ] 站内常驻入口（手机优先，不挡内容、可收起）
- [ ] 解释库：站内名词与口径各一条（TEER、NOC、PNP、AIP、LMIA、EE 类别、vs 中位、通道档…），三语
- [ ] 回答**只从解释库检索**，命中不了就说不知道并转反馈 —— 不让模型自由发挥编政策
- [ ] 反馈：一句话 + 可选邮箱 → 落库 + 邮件通知（复用 Resend，已实证）
- [ ] 反馈带上下文（当前页面、当前岗位 id、界面语言），省得来回问

## 3. 实现步骤

- [ ] **3.1** 解释库落数据层（`data/raw/glossary/*.json` → mart → DB；一条=一个词条+口径+官方链接）
- [ ] **3.2** 组件：右下角常驻按钮 + 抽屉；搜索 + 常见问题列表
- [ ] **3.3** 反馈表：`feedback` 表 + `/api/feedback`（限频，匿名可用）
- [ ] **3.4** 把本轮及后续从页面删掉的解释文案**迁进词条**（不是重写，是搬运）
- [ ] **3.5** 三语

## 4. 涉及目录 / 文件

| 路径 | 角色 |
|---|---|
| `data/raw/glossary/glossary.json` / `data/mart/glossary.json` | 词条源 / 集市 |
| `cms/src/app/(frontend)/ui/HelpDock.tsx`（新） | 常驻窗口 |
| `cms/src/app/api/feedback/route.ts`（新） | 反馈落库 + 通知 |

## 5. 红线与坑

- **不接自由问答**：检索不到就转反馈。移民问题答错的代价是用户的钱和时间。
- 常驻窗口**不许挡手机首屏内容**（纯手机流量，见 [[mobile-first-priority]]）。
- 反馈入口不收敏感个人信息（护照号、住址一律不要）。
