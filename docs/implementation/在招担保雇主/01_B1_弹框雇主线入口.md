# B1 · 入口下沉:modal-pnp 里接雇主线(最小刀)

> 蓝图 [在招担保雇主计划-20260808](../../design/在招担保雇主计划-20260808.md) §2-B1,Frank 2026-08-08「开工 B1」。
> 依据:modal-pnp 167 次/月=全站第一信息点击,超 apply(107)——用户已经在点的地方就是入口。零 ETL。

## 1. 整体目标

用户点开 PNP 弹框(与公司弹框)时,把「担保雇主」这条线递到手上:本雇主有凭证就亮凭证
(AIP 指定 / 近两年 LMIA 获批 N 岗)并给「看它全部在招」;无论有无凭证都给
「看该职业的全部担保雇主」直达 /employers(B2 接手筛选)。埋点量点击率,数字决定 B2/B3 加码。

## 2. 口径与方案

- **凭证=已入库历史事实**:`job.aip`(AIP 指定名单命中,05c 归一匹配)、`job.lmiaPositions`
  (ESDC 近 8 季聚合)。**无凭证整行不出,不写「无」**(蓝图红线;负断言不上台面)。
- 新卡「担保雇主」挂 PnpListSection 判定卡之后(块自身无数据不渲,循「每块一卡」惯例):
  - 凭证行(有据才出):`AIP 指定雇主` / `近两年 LMIA 获批 {n} 岗`;
  - 链接一(有凭证才出):「看它全部在招职位」→ `/?q=<公司名>`(职位板既有搜索,2499 行先例);
  - 链接二(有 NOC 就出):「看该职业的全部担保雇主」→ `/employers?noc=<码>`。
- 公司弹框(CompanyPanel)只加链接二成卡——凭证与在招职位它已有整卡,重复=违反文案闸。
- **`noc` 参数是给 B2 的前向契约**:B2 改造 /employers 时必须读它做职业筛选;B1 期间落页
  显全量名录(页面本身成立,不算断链)。
- 埋点:`pnp-employer-click`(链接一)/ `pnp-sponsor-list-click`(链接二),`kind=pnp|company`
  区分来源弹框;走既有 `track()`(umami),不进漏斗白名单(B5 再定)。
- 措辞红线:凭证=历史事实非担保承诺,弹框内不加解释句(免责归 B2 页头与全站页脚)。
