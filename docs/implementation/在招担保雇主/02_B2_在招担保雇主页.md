# B2 · /employers 改造成「在招担保雇主」页(聚合工程,零新抓取)

> 蓝图 [在招担保雇主计划-20260808](../../design/在招担保雇主计划-20260808.md) §2-B2,Frank 08-08「开工 B2」。
> B1 前向契约在此兑现:`/employers?noc=<码>` 必须按职业筛选。

## 1. 整体目标

用户问的是「**现在**有哪些能担保我的雇主在招人」——/employers 默认视图从静态名录换成
**在招×凭证** 聚合:每行=一家在招且有担保凭证(AIP 指定 / LMIA 获批 / 紧缺清单命中)的雇主,
默认按在招岗数排序,可按凭证/省/职业筛。

## 2. 方案与口径

- **口径**:行=companies 且该雇主有 `status≠closed` 在招岗;凭证三类=①AIP:任一在招岗 `j.aip`
  ②LMIA:`c.lmia_positions>0`(近 8 季 ESDC)③紧缺:任一在招岗 `j.pnp_stream≠''`。三者全无→不进榜。
  红线沿用:凭证=历史事实/官方名录,非担保承诺(页头一行免责,蓝图 §4 允许)。
- **聚合**:单条 GROUP BY SQL(jobs⋈companies)进程内 TTL 10 分钟缓存([[prod-pool-wedge]] 铁律;
  Render 单实例=进程缓存即全局;并发 miss 单飞去重)。筛选/排序/翻页全在进程内做,零每请求聚合。
- **URL 参数**(GET=每页有 URL,SEO 照旧):`f=aip|lmia|named`(凭证 chip)、`prov`、`noc`(B1 契约,
  显示为可摘除的职业 chip,带 NOC 官方名)、`q`(名称搜)、`sort=open|skilled`(skilled=sponsor-likely
  并入:按技能类 LMIA 获批数)、`page`。
- **兼容**:旧名录视图保留在 `type=aip|lmia` 参数下原样渲染(已收录 SEO 页不断链);无 `type`=新视图。
- **每行**:雇主名(+别名/担保档药丸)、凭证 chips(`AIP 指定雇主`/`近两年 LMIA 获批 N 岗`/`紧缺清单命中`,
  措辞与 B1 弹框 spl.* 同源)、在招 N 岗(链 `/?q=名称`)、市/省。桌面 DataTable + ≤640 域卡双形态(站规)。
- **入口**:顶栏新一级项「担保雇主」(spl.head 复用)→ /employers;资料库下拉里的旧「雇主名录」项移除;
  `/rankings/sponsor-likely` 301 → `/employers?sort=skilled`,榜单页 tab 摘除(蓝图:减页面不加页面)。
