# #286 · 公司弹框「获批职业拆分」(高技能岗获批只有计数无明细)

> 工作台 #286(Frank 08-08 晚截图实指「有哪些岗也不知道」);上游=在招担保雇主计划 B 系列收尾。
> 姊妹项:#285 三灯默认序(排序面已上线 `a3f2333`;其「弹框逐层证据」半边并入本项之后的判定弹窗设计,与 #287 一并拍)。

## 1. 整体目标

公司弹框「担保记录」卡只有股别计数(高薪股 56)——用户不知道这 56 个岗是什么职业。把 ESDC 原始数据里已有的**雇主×NOC 拆分**(raw `lmia-employers.json` 每雇主 `nocs:{码:岗位数}`,68,611 家,近两年窗口与 lmiaPositions 同口径)下沉进库,弹框里逐行列出「职业人话名 + 岗位数」。

## 2. 口径与方案

- **数据窗口**:raw nocs 字典即近 8 季(近两年)聚合,与卡内「获批 LMIA 职位数」同窗,不另开窗。
- **链路**:09_build_mart 把 nocs 下沉 `companies.lmia_nocs`(jsonb,`{"95106":685,...}`)→ docs/sql DDL(`ADD COLUMN IF NOT EXISTS`)→ seed 白名单+Companies collection 声明(Payload 不声明=数据不存在)→ 换版后清 seed_state(companies)(哈希投毒铁律)→ 整点批灌值。
- **API**(jobsSql fetchCompanyWhere):`lmia_nocs` 单独 try/catch 查询(列没建不掀接口,#284 探列同款容缺);top 码 join noc_descriptions 取三语名,产 `CompanyDetail.lmiaNocs[]`(按岗位数降序)。
- **UI**(担保记录卡内,股别网格与结论句之间):小节题「获批职业(近两年)」+ Top 6 逐行(职业名走界面语言、灰注 NOC 码、数值右对齐)+「其余 N 个职业」汇总行;`lmiaNocs` 空=整块不出(自激活)。
- **版式教训(效果图第一轮实撞)**:FactGrid 的 max-content 名列遇英文长职业名把数值列挤出 375 屏 → 本块自用两列网格 `minmax(0,1fr) max-content`,长名折行(禁截断→折行,#268 同判)。
- 名缺(noc_descriptions 没收录)渲裸码,不生造。
