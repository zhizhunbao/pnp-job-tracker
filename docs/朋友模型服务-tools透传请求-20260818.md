# 给朋友的模型服务:请在 `/v1/chat/completions` 上支持 tools

> 2026-08-18。承 [朋友模型服务-兼容网关请求-20260804.md](朋友模型服务-兼容网关请求-20260804.md)。
> **这一页可以直接转发。** 下面每条都是本机实测,不是听说。

---

## 一句话需求

**把请求里的 `tools` / `tool_choice` 透传给模型,并把模型返回的 `tool_calls` 原样放进回包。**

其余一切不用改。

---

## 现状:字段被**静默忽略**

三种 `tool_choice` 都试过,回包一模一样:HTTP 200、只有文本、**没有 `tool_calls`**。

| 请求 | HTTP | `finish_reason` | `message.tool_calls` |
|---|---|---|---|
| 带 `tools`,不给 `tool_choice` | 200 | `length`/`stop` | 无 |
| 带 `tools` + `tool_choice: "auto"` | 200 | `stop` | 无 |
| 带 `tools` + **`tool_choice: "required"`** | **200** | `stop` | **无** |

第三行是关键:按 OpenAI 规范 `required` = **必须调用工具**,不支持就应当回 **400**。
现在既不调用也不报错,调用方无法判断「是不支持」还是「模型选择不调」。

## 复现(把 `{BASE}` `{KEY}` 换成实际值)

```bash
curl -s -X POST "{BASE}/v1/chat/completions" \
  -H "content-type: application/json" -H "authorization: Bearer {KEY}" \
  -d '{
    "model": "qwen3.6", "stream": false, "max_tokens": 300,
    "tool_choice": "required",
    "messages": [
      {"role": "system", "content": "需要事实时必须调用工具,不许自己编数字。"},
      {"role": "user",   "content": "NOC 21231 在 BC 的省提名门槛是多少?"}
    ],
    "tools": [{
      "type": "function",
      "function": {
        "name": "lookup_thresholds",
        "description": "查某职业在各省 PNP 的官方门槛。需要 5 位 NOC 码。",
        "parameters": {
          "type": "object",
          "properties": { "noc": {"type": "string"}, "provs": {"type": "array", "items": {"type": "string"}} },
          "required": ["noc"]
        }
      }
    }]
  }'
```

**期望**:回包里出现

```json
"finish_reason": "tool_calls",
"message": { "tool_calls": [{ "id": "...", "type": "function",
  "function": { "name": "lookup_thresholds", "arguments": "{\"noc\":\"21231\",\"provs\":[\"BC\"]}" } }] }
```

**实际**:`finish_reason: "stop"`,`tool_calls` 不存在,`content` 是一段自由文本。

---

## 佐证:**是网关的事,不是模型不会**

同一个模型 `qwen3.6` 在 Ollama 的 OpenAI 兼容端点上,同样的工具声明、同样的问题 ——
**工具调用全对**,参数也对:

```
lookup_thresholds({"noc":"21231","provs":["BC","ON"]})
lookup_draws({"prov":"BC"})
```

`GET {BASE}/v1/models` 显示 `{"id":"qwen3.6","owned_by":"local"}`。
如果后端就是 Ollama / vLLM / SGLang,它们的 OpenAI 兼容层本身都支持 `tools`,
**多半是网关自己重新组请求时把 `tools` 字段丢了**。

---

## 退一步也行

如果暂时不打算支持,**请至少对 `tool_choice: "required"`(或带 `tools` 的请求)回 400**,
错误结构照现在的 `{"error":{"type","message","param","code"}}` 就好。
这样调用方能当场判断能力、走别的后端,而不是拿到一段看似正常、实则该查库却自己编的答复。

—— 顺带说明为什么在意这个:没有工具时,它对上面那个问题的回答是
「截至目前(**2024 年**),BC 省提名计划并没有针对特定 NOC 设定统一门槛……」。
年份是错的,结论是编的。我们这边所有数字都必须来自数据库并带官方出处,
所以**要么让模型调工具、要么明确报错**,不能让它自由发挥。

---

## 支持之后我们这边怎么切

一行 model 定义:`api` 从 `anthropic-messages` 换成 `openai-completions`、`baseUrl` 指到 `{BASE}/v1`
(见 `cms/src/lib/agent/planner.ts` 的 `MODEL`),再补一条 `outputFileTracingIncludes`。
切过去之后这条路径的模型成本归零。
