## 1. 现状核对(先看代码,再谈设计)

动手前把三条前提对着 `chatOrchestrate.ts` 核过了。**这三条决定了施工顺序**,不是背景介绍。

### 1.1 🔴 对话内容一个字都没存

- `cms/src/collections/` 无 chat/conversation 表;
- `api/chat/route.ts:98` 只 `console.log("noc=… facts=N in=123ch")` —— **连问题原文都没有,只有字数**;
- Umami 只有事件计数(`chat-submit`/`chat-answer`/`chat-example`),无内容。

**后果**:今天没有任何办法回答「用户实际最常问什么」「哪一类问题最容易 guard 降级」。
每天的真实语料在答完的瞬间永久丢失。**这是本方案里唯一每晚一天就亏一天的事,所以排第一。**

### 1.2 今天没有「能力路由」,`collectFacts` 是无条件全量扇出

`chatOrchestrate.ts:1007-1070` 每轮把 jobs/coverage/thresholds/EE/draws/ops/plan 全打一遍
(同参 SQL 走 `memoPool` 缓存),只有 permit/crs 有正则闸门,判据明确写着
「只读用户原话,不拿模型猜的 topic 当开关」。

**所以 `capabilities[]` 不是「把现有路由规范化」,是新建一个只能做减法的开关层。**
全量扇出在这里是特性:漏查一个工具 = 少一条事实 = 答案变差,多查一个的代价已被缓存吃掉。
要上 capability 路由,理由只能是 prompt 预算或 `MAX_FACTS=40` 挤爆,不能是「路由更准」——
而这个理由今天没有数据支持。**不做。**

### 1.3 `Fact` 缺两个字段,而这两个字段是一切的前提

```ts
// chatOrchestrate.ts:32
export type Fact = { tool, label, value, valueText, unit, evidence, cited? }
```

- **没有稳定 code**。`label` 是本地化的人话,runner 想断言「这轮必须出现 SK 抽选线」
  只能匹配中/英/韩字符串 —— 等于把测试和见客文案焊死。
- **`availability` 在构造时被压成句子**。`statusFact`(:852)把四态渲染进 `valueText`,
  结构化值当场丢失。**所以 CLAUDE.md 那条铁律(`not-published` 必须 URL+quote,
  举不出来只能 `not-collected`)今天没有任何机器在管**,全靠写 lookup 的人自觉——
  而 :846-850 那段注释记的正是这条路上刚踩的坑(`ok` 占位符当人话喂出去,
  英文答复把「一个类别都不在」说反成「都能走」)。

**加这两个字段是本方案性价比最高的一刀:见客文案一个字不动,却同时解锁机器断言和一条铁律的执行。**

## 2. 边界

| 名称 | 定义 | 不是什么 |
|---|---|---|
| **family** | 一类问题的骨架:要查什么、答哪几节、给什么下一步。同一 family 内问法千变万化,差别只在槽位取值 | 一个问题、一条固定回复 |
| **variant** | 同一 family 下的一组具体输入(职业/省份/身份/语言/多轮) | 新 family |
| **复现率** | 「完美结果」里的句子,今天引擎能说出口的比例 | 测试通过率 |
| **fixture** | 替代 DB 行和 LLM I/O 的**边界**数据 | 生产逻辑的静态复刻 |

### 2.1 硬边界

- **Case/family 定义放测试域**(`cms/tests/cases/`),生产包不引用。
  判据只有一条:**说得出「有它和没它」哪条生产路径行为不同**。按本方案 D1–D4 答案是零,
  所以不进生产。哪天生产真按 capability 路由了,再把那一小块上提——那时它有消费者。
  (人读的产品资产已经存在,就是[案例库](案例库-问题与结果先行-20260803.md),不需要在生产里再放一份。)
- **只允许 mock 两个外部边界**:DB 返回行、LLM I/O。严禁在 fixture 里复刻槽位归一、
  工具路由、四态、事实组装或 guard —— 否则测的是复制品。
  (`chatPreset1.int.spec.ts` 文件头已是这个纪律,照抄即可。)
- **生产不许出现 case 专属分支**。没有 `if (caseId === 'C01')`。
- family 不携带分数线、费用、岗位数等易变数字;所有数字来自当轮真实工具返回。

### 2.2 🔴 fixture runner ≠ 复现率(这两个数字不许混)

| | fixture runner | 复现率批跑 |
|---|---|---|
| 跑什么 | 假 DB + 假 LLM | 真库 + 真模型(friend provider) |
| 证明什么 | **没退化** | **能答对多少** |
| 稳态 | 永远 100% 通过 | 12/36 起步,目标是往上走 |
| 何时跑 | 每次 PR | 每批收口 + 每周一次 |

**门禁看第二个数,不是第一个。** fixture runner 恒绿,拿它当验收等于没有验收。

顺带纠一条常见误判:**批跑不花钱**。生产 chat 走 `provider: 'friend'`(`chatOrchestrate.ts:2276`),
真模型批跑的成本是 ngrok 可用性和输出抖动,不是账单。别拿"费用"当理由推迟批跑档。

## 3. 八个 family

C01–C16 合并后如下。**C03、C16 踢出本 harness**(理由见表下)。

| ID | family | 吸收 | 骨架(要查 / 答哪几节) | 差异只是槽值 |
|---|---|---|---|---|
| F1 | 约束下的选省 | C01, C08 | 各省岗位数 → 各省门槛 → 抽选竞争 → 时间线 → 这周投哪些 | 约束 = 0 经验 / 窗口剩 N 月 |
| F2 | 私人主张核验 | C13, C14 | 主张三分法(能核/核不了/他没说的) → 官方规费 → 雇主硬指标 → 该问的问题 | 主张人 = 雇主 / 中介;是否涉钱 |
| F3 | 分数线赶不赶得上 | C07, C15 | 当前下界分 → 近 N 次抽选节奏 → 差多少分 → 补哪一项最值钱 → 备选 | 省级抽选 / 联邦 EE |
| F4 | 海外起点路径排序 | C04, C05, C09 | 最长的杆是什么 → 语言/年龄/注册门槛 → 逐省对比 → 顺序 | 年龄归零省 / 受监管职业 / 受限行业 |
| F5 | 读书 vs 直接工作 | C02, C06 | 两条路一张账 → PGWP 资格与时长 → 毕业时点 → 一生一次条款 | 在读 / 已毕业;是否二学位 |
| F6 | 家庭财务门槛 | C10 | BC 收入表 → 全家口径 → 配偶工签 → 其余省不发数额 | (独立:全国只有 BC 发表) |
| F7 | 法语与 QC 边界 | C11 | QC 不下结论 + 官方入口 → 法语在 QC 之外的价值 → EE 法语类别 | (独立:唯一一条主动弃权的场景) |
| F8 | 雇主驱动试点 | C12 | RCIP 逻辑 → 社区指定雇主名单 → 没 offer 前别付钱 | (独立:逻辑与其余七个都不同) |

**踢出的两个**:

- **C03(死链用户)**:原文写着「没说话,行为就是问题」——它根本不是对话。
  它是职位详情页的 JD 对照功能(G3,已上线)。塞进 chat harness 得先给它编一个假问句。
- **C16(未分类岗)**:这是 `askOccupation` / `noOcc` 降级路径,属**系统行为回归**,
  已有测试覆盖;它和八个业务场景不是一类东西。

**收益**:D3 从「16 个文件各带一份 fixture」变成「8 个骨架 × N 组输入」。
覆盖率靠加 variant 涨,不靠加 family 涨;16 份 fixture 是 16 个漂移点。

## 4. 施工顺序

| 批次 | 内容 | 为什么在这个位置 | 规模 |
|---|---|---|---|
| **D1** | **对话留痕**:`chat_logs` 表 + route 写入 | 每晚一天丢一天真实语料;而且它比整套 harness 都便宜 | 一个 collection + 一处 insert |
| **D2** | **覆盖矩阵 + 复现率基线**:八个 family 逐句标 supported / data-gap / rule-gap / unverifiable / invalid-gold | 唯一自带直接收益的一步——告诉你下一批补什么(C02 那次 12/36 已证明) | 纯人工核,不动代码 |
| **D3** | **`Fact.code` + `Fact.availability` 提为一等字段**;guard 加「`not-published` 必须 url+quote」 | 最便宜、解锁机器断言、当场堵上一条今天没人管的铁律 | 改 `fact()`/`statusFact()` 两个构造器 + 各 lookup 传参 |
| **D4** | **统一 runner**:按八个 family 组织,先迁三个 preset 保证行为不变,再补 variant | 复用现有 fixture,不新建 16 个漂移点 | 一个 spec + 一张 family 表 |
| **D5** | **章节/追问优先级表**:从现有隐式序抽出来 | 多 family 同时命中时唯一的真难点(见 §5) | 一张整数表 + 一个纯函数 |
| **D6** | 视 D2 结果决定:非数字主张 guard / capability 路由 / DecisionPlan | 三件都要 D2 给出发生率才知道值不值 | 待定 |

每批独立提交、独立验收。**当前聊天 UI 的全屏/窗口按钮/预设宽度/输入框改动必须单独成批**,不与本重构混交。

## 5. D5 的那张表(多 family 命中怎么合并)

一句问题同时命中多个 family 是常态。「中介收钱包曼省木匠 offer」= F1 + F2。

工具集合并是伪难题(今天就是全查)。真会打架的是两样:

1. **追问哪一个槽** —— 一次只问一个,问哪个?
2. **章节排序** —— F2 想先「三个硬指标当场验」,F1 想先「逐省对比」,谁在前?

做法:**一张全局 section/slot 优先级整数表(单一来源)**。
合并 = 并集 → 按整数排序 → 去重;追问 = 未满足 required slot 里优先级最小的那个。约 20 行纯函数。

🔴 **绝不许让 family 在表里的书写顺序参与决定** —— 那是隐式全局状态。

这张表不该新发明:`chatOrchestrate.ts:2150` 已有一条既定裁决——
「别人跟他说的话排最前 —— 他就是为这个来的,而它偏偏在 `collectFacts` 存储序里排最后」。
**先把现有的隐式序抽出来成表,再谈扩展。**

## 6. D3 的具体改法

```ts
export type Fact = {
  tool: string
  code: string                    // 新增:稳定、语言无关,如 'jobs.byProvince' / 'draws.cutoff'
  label: string                   // 照旧:本地化人话,见客用
  value: number | null
  valueText: string
  unit: string
  availability: Availability      // 新增:'ok' | 'not-published' | 'not-collected' | 'not-applicable'
  evidence: { url: string; fetched: string; quote?: string }
  cited?: boolean
}
```

配套三条硬约束(写成断言,不写成注释):

1. `availability === 'not-published'` 时 `evidence.url` 与 `quote` 必须非空 —— 举不出来只能降 `not-collected`。
   **这是 CLAUDE.md 铁律第一次真的有机器在管。**
2. `value === null` 保持 null,任何地方不许折成 0。
3. `statusFact` 继续渲染人话句子给模型看,但**结构化四态不再被丢弃**。

runner 断言一律用 `code`,不碰 `label`。见客文案随便改,测试不动。

## 7. 🔴 待 Frank 拍板的两件事(D1 的前置)

**① 对话原文存不存?存到哪?**

推荐默认:**存原文,不关联用户 ID,只存 session 哈希**。

存:`ts`、`lang`、原文、`slots`(JSON)、`factCodes[]`、答复、`degraded`、耗时、`sessionHash`。
不存:IP、user_id、邮箱。

理由:用户自述里天然含职业/身份/省份/年龄,关联到人就成了移民身份档案,风险与收益不成比例;
而做语料分析并不需要知道是谁。**隐私页需要加一句**(「为改进问答质量,我们保存提问内容,不与账号关联」)。

需要你点头的是:**隐私页那一句要不要加、怎么措辞**——这属于对外声明。

**② 论坛语料还抓不抓?**

建议**先不抓,等 D1 攒够两周自家语料再决定**。理由:论坛是替代品,自家对话是正品
(带真实语言分布、真实追问、真实哪轮降级)。原方案花整节设计论坛管线,
而自家用户的问题正在被扔掉——顺序反了。

将来若抓:**只存 URL + 内容哈希 + 脱敏摘要,正文不入库**。既躲开版权,
也省掉「脱敏是否彻底」的长期责任。频次阈值不设死(按当前流量几个月凑不齐一个簇),
人工判定重复即可。**论坛里的费用/分数/时间/成功率永不进 facts**,必须另找官方来源。

## 9. 明确不做

- ❌ 生产 registry / `capabilities[]` 路由(§1.2:今天没有消费者,且只能做减法)

- ❌ 论坛抓取管线(§7②:先攒自家语料)
