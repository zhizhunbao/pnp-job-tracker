# PGWP 规则库(B1-4)设计草案 — 2026-08-03

> 立项出处:[未结问题清单 §B1-4](未结问题清单-20260803.md) —— Frank 本人案例:
> 「1 年 AI 研文 + 想再读 1 年 cloud,两个 1 年研文能不能换 3 年 PGWP?」
> 现在题库只问「许可还剩几个月」,没有规则能算「再读 X 会变几个月」——
> 「读书 vs 直接工作」这类最贵的决策(一年学费 + 一年收入)完全答不了。
> **本文档是地基草案:URL 已建档,抓取与引擎未动工。细节下轮照此施工,拿不准的先问 Frank。**

## 1. 官方 URL(✅ 已入 crawl 役,2026-08-03)

`discover_sources.py` SEEDS 加 `fed-pgwp`(canada.ca 扁平路径,httpx 直通),
首轮建档 **25 页** → `data/crawl/fed-pgwp/manifest.json`(crawl 役周更 + diff 政策雷达)。核心页:

| 页 | 管什么 |
|---|---|
| `.../after-graduation/eligibility.html` | **时长规则**(课程时长→许可时长档;硕士 ≥8 个月特例;**两个课程叠加**的官方条款)+ 学校/课程资格 |
| `.../eligibility/field-of-study.html` + 6 张分表(education/trade/agriculture/health-care/transport/stem + currently-eligible) | **CIP 码白名单**(按学位层级豁免与否) |
| `.../eligibility/language-results.html` | 语言门槛(按学位层级 CLB 档) |
| `.../after-graduation/about.html` | 一生一次、申请窗口(毕业后 180 天)等硬约束 |

## 2. 数据层(照 AI 进两头不进中间:官方页 → 结构化事实,判定留规则引擎)

- `etl/pnp/build_pgwp.py`(或 `etl/build_pgwp.py`,联邦源不属省)→ `raw/ircc/pgwp_rules.json`:
  - `lengthRules[]`:课程时长区间 → 许可时长(含硕士特例、叠加条款原文引用 + url + fetched)
  - `fieldOfStudy[]`:CIP 码 × 类别 × 适用学位层级(6 张分表逐行)
  - `constraints[]`:一生一次 / 180 天窗口 / 语言档(带 section 锚点)
- **自校硬闸**照 build_bc_req:解析不全 → 保留旧表 + exit 1;钉 `ircc` 役(日更)末尾;
  `source_manifest.json` 的 glob 默认自动把它纳入新鲜度哨兵(cadence 4 天)。

## 3. 引擎与题库(下轮拍细节)

- 纯函数 `pgwpMonths(programs: {months, level, cip?}[], …) → {months, basis[]}`——
  每条结论指回官方页(结论要能指回出处,LLM 不下结论)。
- 题库最小增量:只对「在读/计划读书」状态的用户追问课程时长与层级(挂不上结论就不问);
  CIP 码用户答不了 → 先按「学位层级豁免/不豁免」粗判,判不了就说判不了,**不硬映射 CIP**。
- 消费点:卡②「拿 PR」的许可窗口节(现有 `rpt.c.window` 拿「还剩几个月」算轮次)——
  加「再读 X 个月的 Y 层级课程 → 许可变 Z 个月」的对照行;免费=规则本身,付费=拿他的答案算差值(口径同门槛对照)。

## 4. 拿不准、要 Frank 拍的

1. 叠加条款细节(两个 1 年研文=3 年?)**以抓下来的官方原文为准**,设计不预设答案 —— 引擎只复述规则+算术;
2. 题库加几道:倾向只加「课程时长档 + 学位层级」两道,CIP/学校资格不问(答不准的题=脏数据);
3. field-of-study 是否第一期就抓 6 张 CIP 分表(几百行)——倾向第一期只抓 lengthRules + constraints,
   CIP 表第二期(个人判定用得上时再说,YAGNI)。
