## 0. 为什么是它(数据依据,2026-08-08 拉的 30 天真实行为)

- **modal-pnp(职位页省提名弹框)= 全站第一大信息点击:167 次,超过 apply(107)**。用户的主问题
  就是「这岗/这雇主能不能带我移民」。其余:modal-company 68、modal-salary 61、modal-ee 54、modal-aip 21。
- 流量结构:入口=出口=职位详情页(jd-open 220 + modal-jd 194,/jobs/* 占页面榜半壁);
  榜单页是走廊:/start 30 天 10 次、/pricing 5 次、**/employers 9 次、/rankings/sponsor-likely 4 次**
  ——雇主视角功能已存在但无人可达,是入口问题不是功能问题。
- 家底(生产库现货,零新抓取):AIP 指定雇主在招 **325 家/773 岗**(NS 217/472、NB 75/222、
  NL 24/60、PE 9/19);AIP 名录 3,476 家(NS 1,574+NB 1,263+NL 639,PE 名录缺=WAF);
  LMIA 担保历史雇主在招 **5,129 家/8,643 岗**;紧缺清单命中在招 1,933 家/2,403 岗。

## 1. 完美问题与完美结果(案例先行,验收标尺)

- 完美问题:「我是厨师,想走雇主担保,**现在**有哪些能担保我的雇主在招人?怎么联系?」
- 完美结果:按 职业×省 筛好的**在招担保雇主名单**,每家带:在招岗数与直达链接、担保凭证
  (AIP 指定 / 近两年 LMIA 获批 N 岗 / 紧缺清单命中)、所在市。事实免费,筛好的名单+联系口径收费。
- 红线不变:凭证=历史事实与官方名录,**粗筛信号非担保承诺**(rank.note.sponsor-likely 现有措辞沿用)。

## 2. 分批

### B1 · 入口下沉:modal-pnp 里接雇主线(最小刀,先上先验)
用户已经在点的 167 次/月就是入口。modal-pnp(与 modal-company)内加两行:
- 「该雇主:AIP 指定 / 近两年 LMIA 获批 N 岗 → 看它全部在招」(无凭证则整行不出,不写「无」);
- 「看 {职业} 的全部担保雇主」→ B2 页带筛选直达。
埋点 `pnp-employer-click` / `pnp-sponsor-list-click`。**验收线(可证伪缺省,Frank 可改):
两周窗 modal-pnp 打开 → 雇主线点击 ≥5%。**
涉及:`JobsTable.tsx`(弹框)、`lib/track.ts`、i18n 三语。零 ETL。

### B2 · /employers 改造成「在招担保雇主」页(聚合工程,零新抓取)
现 /employers(30 天 9 次访问)升级:
- 默认排序=在招岗数;筛选 chips:全部 / AIP 指定 / LMIA 历史 / 紧缺清单命中;省、职业(NOC)筛选;
- 每行:雇主名、在招 N 岗(直达职位板 company 筛选)、凭证 chips、市/省;
- 聚合走 API + 进程内 TTL 缓存([[prod-pod-wedge]] 铁律:站级聚合禁每请求现算);
- 顶栏入口与命名 Frank 拍(候选:「担保雇主」一级项;sponsor-likely 榜并入本页当一个排序,不再单页)。
涉及:`EmployersView.tsx`、新 API route、`SiteHeader`。表结构现成(jobs.aip/pnp_stream/company_id、
companies.lmia_*、designated_employers)。

### B3 · 个人化与付费衔接(事实免费,结论收费)
- 免费层:名单可浏览、计数、单个雇主详情(现有 companyResearch 懒查询照旧);
- 付费层:按「你的职业×目标省」筛好的担保雇主名单导出/收藏 + 报告卡①雇主线索与本页互通
  (付费概率提升计划 L1 的延伸:雇主线索从只长在卡①,变成有自己的货架);
- 定价页把本页截图当第一卖点素材(现在挂的是雇主名单文案,没图)。
**本批不改定价数字,只接线。**

### B4 · 数据补口与保鲜(唯一涉 ETL 的批)
- PE 指定雇主名录:官方页在 WAF 后,按 PE 惯例走文件/PDF 路线(E13-09 的 PDF 直取先例);
  举证不出就 not-collected,页面该省筛选注「名录未收录」;
- NS/NB 名录是否带 NOC 维度核对(NL 已带 639 家含 NOC;带 NOC 才能做职业级精筛);
- 名录保鲜进 crawl 周更雷达(ns-root/nb-imm/nl-imm 已覆盖,确认 diff 报警链路);
- **懒查询铁律不破**([[lazy-first-company-data]]):公司级富化(官网/邮箱)仍懒查,本计划只用已入库字段。

### B5 · 读数与迭代(两周窗)
- 漏斗:modal-pnp → 雇主线点击 → B2 页 → 职位板/锁区曝光 → pricing-open;
- 与付费概率提升计划同一张 funnel_events 表,别另起炉灶;读数前先验探头在不在(M2 教训);
- 数字说话决定 B3 加码还是转向;仍 <验收线 → 回访那 69 个注册用户问真需求,不是再改文案。

## 3. 优先级与 E14 的关系

- **顺序建议:B1(半天)→ B2(1-2 天)→ B5 埋点同步上 → B3 → B4。**
- E14(JVWS/Indeed/担保率/抽选线)不冲突且互喂:担保率与抽选线以后直接成为 B2 每行的
  「该雇主/该职业竞争维度」;E14 的 Indeed 全市场侧**不进**担保雇主口径(origin 隔离铁律)。
- 把脉首页(E13)冻结拋光:流量证据在 §0,后续只随数据层升级顺带更新,不再单独立批。

## 4. 风险与不做清单

- 不做:雇主联系方式批量抓取(懒查询铁律+合规);不做「担保成功率」这类无法举证的数字;
  不做新排行榜页(sponsor-likely 并入 B2,减页面不加页面)。
- 措辞风险:「担保雇主」≠「承诺担保」,页头保留一行免责(四类允许文案之一),
  凭证全部可溯源(AIP 官方名录链接/ESDC LMIA 公开数据季度)。
