# 用户是谁 · 付费错配诊断（2026-08-10）

> 起因：上线一个月零收入。本文把「为什么没人付费」查到底，结论**推翻了此前几轮的整改方向**。
> 全部数字来自生产库（`funnel_events` / `users` / `chat_logs` / `saved_jobs`），不是 Umami——
> share token 现在调 API 一律 401（四种姿势实测，见 §6），页面数字有入场动画也不可信。
> 复查用的 SQL 全在 §7，下次直接跑，不用重新推。

## 一、一句话结论

**来的人主体是「已经有身份、想找工作」的人，而站卖的是给「要靠 offer 走移民」的人的结论。**
零付费不是定价、文案或锁区的问题，是**流量引擎与付费产品的结构性错配**——Google 招聘富结果
天然吸引求职者，而付费面卖的是移民判定。这一层不修，改价、改锁、改文案都是在错的地基上砌砖。

## 二、证据

### 2.1 付费链（`funnel_events`，08-01 建表至 08-10，9 天）

| 步 | 次数 |
|---|---|
| jd-open（职位详情打开） | 2517（**有水分，见 §6**） |
| lock-seen（报告锁区真进视口） | 249 |
| report-open | 149 |
| pricing-open | 18（`rpt-pr` 9 + `direct` 9） |
| **pay-click** | **0** |
| 完成付费 | **0** |

`users.stripe_customer_id` 全表 0 行非空——**上线至今没有任何人走进过 Stripe**。
`pay-click` 埋点在登录判断之前发（`PricingModal.tsx`），所以这个 0 不是埋点坏了。
锁区用 IntersectionObserver 0.4 阈值记，249 是**真看见了**，不是渲染即算。

### 2.2 用户链（全周期）

- 真人注册 **87**（剔 25 个 `@test.local`），07-04 ~ 08-09，峰值 07-27 那周 53 个，约半数走 Google OAuth
- 存过岗 **69 人 / 73 条** —— **69 个人各存恰好 1 个**，唯一存到 5 个的是 user 10
- 跨天回来过：**4 人**
- 填过档案 40 人，**上传简历 0**
- 周报已发 **67 人**，退订 1
- 对话：6 天 124 次打开 / 75 次答复，但 `chat_logs` 157 轮里绝大多数是自测与 case-harness 复跑

### 2.3 他们是谁（决定性的一张表）

`users.profile_current_status`，35 人填了、52 人没填：

| 身份 | 人数 | 对移民产品的需求 |
|---|---|---|
| jobhunting（找工作中） | 12 | 不明 |
| **pr（已是永久居民）** | **9** | **零** |
| working（在职） | 8 | 低 |
| studying（在读） | 4 | 有 |
| **overseas（人在境外）** | **2** | 高 |

旁证：填了 CLB 的 13 人，**填了 CRS 的 0 人**（CRS 是移民打分的核心输入，一个人都没碰），
有 PGWP 剩余月数的 7 人。往宽了算，可能需要移民服务的（境外 2 + 在读 4 + PGWP 7）不到四成。

对话里抽出来的身份槽同向：graduated 33 / working 23 / student 4，**没有一条 overseas**。

### 2.4 墙立在哪、卖点立在哪（两拨人）

全站会弹注册/登录的 8 处，触发动作依次是：**投递**、收藏岗位、切「我的匹配」、点打码的 Pro 列、
三重判定锁区、简历匹配弹框、定价页免费栏按钮、顶栏登录注册。

**第 1 处（投递）几乎肯定就是 87 个注册的来源** —— 这解释了「69 人各存恰好 1 个岗然后消失」：
他们冲着投一个具体的岗来，被注册墙拦下，注册完投完就走。

也就是：**站里所有的墙都立在求职动作上，所有的卖点都立在移民结论上。**

## 三、诊断

1. **人群错配（根因）**：见 §2.3。付费产品的目标客群在流量里占比极低。
2. **付费面只有一扇门**：`/pricing` 整页 9 天只有两条来路进得来（报告锁区 9 次、SEO 直达 9 次），
   另外四个弹窗入口（汉堡菜单升级、存搜索超额、三重判定锁、雇主对比演示）**9 天一次都没被触发过**。
3. **定价页与代码对不上账**（独立于人群问题，仍需修）：
   - 代码里真实的收费闸有 6 处：报告锁区结论、三重判定 `tier:'paid'` 行、简历匹配第 6 行起、
     职位表匹配列超每日 10 岗、雇主名单 CSV 导出（402）、每日额度池（匿名 10 / 免费 20 / Pro 200）。
   - 定价页 Pro 栏只写 3 条，其中**「岗位盯梢」免费用户就在收**（周报对免费照发，今天刚发 67 封，
     收信的没有一个是 Pro）。
   - `price.f6~f10` 五条文案在 i18n 里三语齐全但**页面一条都没渲染**（旧三栏表拆三卡时掉的），
     其中 `f7`「AI 顾问档案感知」是真 Pro 卖点（`advisor` 路由里 `profileFacts` 是 Pro-only），
     而免费栏偏偏写着「AI 顾问（判断 + 追问）」——用户读完的结论是「顾问免费」。
4. **锁区自己不说卖什么**：四行纯灰马赛克盖住的**不是答案，是问题本身**；价格不在锁区上，
   要点一次跳到 `/pricing` 才看得到；而锁区正上方就是一张**免费**的「下载完整报告（PDF）」。
   249 → 9 的点击率（3.6%）由此而来。

## 四、由此作废/降级的三个方向

| 方向 | 判定 | 理由 |
|---|---|---|
| 把弹框「有价值的内容」都锁上 | **不做** | 锁是「需求存在但被免费满足」时的正确动作；现在是需求不在这批人身上。锁得越紧掉量越多，付费不会涨。（真要锁，判据也该是**事实免费、结论收费**：薪资/中位/地点/公司是事实，锁了既伤 SEO 又违立身之本；身份判定、通道报告、雇主名单才是结论。） |
| 降价到 $1.99 / 改成按次计费 | **不急** | 9 天只有 18 人看见过价格，改价影响的是这 18 人，测不出统计意义。另：**现在就已经是一次性时长包**（定价页副标题写着「无自动续费」），$19 买的是 30 天使用期，不是订阅。改价只需动 `NEXT_PUBLIC_PRICE_DISPLAY` + Stripe 建价（零代码）；改「按次」要动 `users.pro_until` 这个全站唯一付费真相，是真项目——**在 0 付费用户时重构计费模型，是拿最贵的工程时间赌未验证的假设**。 |
| 周报加 utm 量回访 | **降为次要** | 本身没错（周报链接全是裸 `${SITE}/jobs/${id}`，回访记成直接流量，等于看不见），但它是量具不是主线。人群问题解决前，量回访量不到钱。 |

## 五、分岔：只有两条路，必须选一条

- **换获客**：把产品端到移民人群面前（小红书、一亩三分地、留学生社群）。产品基本不用改，
  但要另建一条获客路，慢，且与现在的 SEO 引擎不是一条腿——招聘富结果天然吸引的就是求职者。
- **换卖法**：向这批已有身份的求职者卖他们真要的东西。但求职者历来不付费，
  全世界的职位板都是向雇主收钱。

### 选之前先做这个测试（花时间不花钱）

拿现有产品，去移民人群聚集的地方发一次内容，看**那批人**来了之后的行为——
锁区点击率、注册率、身份分布，跟现在的 Google 流量对照。

- 对的人来了**还是不付费** → 产品问题，回头改产品。
- 对的人**付费** → 纯获客问题，力气全押换渠道。

**现在这两种可能分不清，而后续所有决定都取决于分清它。**

## 六、口径与不确定性（别当没说）

1. **`jd-open` 的 2517 有水分**：按天拆 `page` 口径，正常日 80~95，但 08-04 是 846、08-05 是 894、
   08-08 是 311。这三天跟日访客几十人对不上，可能是爬虫，也可能是走查脚本批量开页。
   **漏斗第一步的分母目前不可信**，拿它算转化率之前得先摘机器流量。
2. **`pricing-open` 的 `rpt-pr` 库里是 11，真值 9**：另外 2 次是 2026-08-10 我用 playwright
   截锁区实拍时打的。
3. **身份分布的样本是 35/87**，52 人没填。填的人多半是走投递/匹配向导时填的，有选择偏差。
   但这是目前最好的证据，且三个独立来源（users 档案、chat_logs 槽位、CRS 填写数）同向。
4. **Umami 现在拉不到数**：`cloud.umami.is/analytics/us/api/share/<id>` 能换到 token，
   但拿它打 `gateway-us.umami.is` 与 `cloud.umami.is` 的 `/api/websites/<id>/stats`，
   四种 header 组合（`x-umami-share-token` / `Bearer` / 两者都带 / 换域）**全部 401**。
   要 session 级数据只能走登录态 Chrome。第一方 `funnel_events` 因此是唯一可靠口径。
5. **成本侧只有 7 月旧账**（Render 月约 $10~16），本文没核当前账单。

## 七、复查 SQL（下次直接跑，别重新推）

```sql
-- 付费链
select event, sum(n) total, min(day) frm, max(day) last from funnel_events group by 1 order by total desc;
select prop, sum(n) n from funnel_events where event='pricing-open' group by 1 order by n desc;
select day, prop, sum(n) n from funnel_events where event='jd-open' group by 1,2 order by 1;  -- 查水分

-- 他们是谁（本文的核心表）
select coalesce(profile_current_status,'(没填)') st, count(*) n
from users where email not like '%@test.local' group by 1 order by n desc;
select count(*) filter (where profile_clb is not null) has_clb,
       count(*) filter (where profile_crs is not null) has_crs,
       count(*) filter (where profile_pgwp_months_left is not null) has_pgwp
from users where email not like '%@test.local';

-- 付费真相（唯一）
select count(*) filter (where pro_until is not null) ever_pro,
       count(*) filter (where stripe_customer_id is not null) has_stripe from users;

-- 留存代理
select count(*) from (select s.user_id from saved_jobs s join users u on u.id=s.user_id
  group by s.user_id, u.created_at::date having max(s.created_at)::date > u.created_at::date) t;
```
