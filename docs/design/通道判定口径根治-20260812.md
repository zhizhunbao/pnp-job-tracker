## 0. 目标一句话

**把「你能走这条通道」从默认值改回需要举证的断言** —— 举不出证只能说「判不了」,不许说「能走」。

## 1. 病灶:开放世界的数据 + 封闭世界的推理

`pnp_requirements` 是**开放世界**的表:它只装 ETL 从官网抽到的行,永远无法证明「这条通道的门槛就这些了」。
而 `pathVerdict` 对它做的是**封闭世界**推理:「库里这几条你都满足 → `verdict='open'`」。

两者对不上,结果必然是**静悄悄的假阳性**:抽不到的门槛不是不存在的门槛,但代码把它当成了后者。

### 1.1 实测证据(2026-08-12,打生产 `/api/profile-pathways`)

五个画像 → **15 条结果全是 `open`,一条 `needs-info` 都没有**,包括「CLB 4 / 零经验 / 从没来过加拿大」这种最弱画像。
唯一如实报警的是 `blockedBy='language'`(联邦 EE),那正是**库里有行**的那一类。

三条最刺眼的错判,以及它们在库里对应的行:

| 通道 | 现网判定 | 库里**实际有的**门槛行 | 官方真正的定义性条件(库里**没有**行) |
|---|---|---|---|
| NLPNP 国际毕业生 | 海外护士(从未来过加拿大)→ `open` tier 0,**排进前三** | `language>=CLB4`、`language none`、`experience none` | 须毕业于加拿大/纽省认可院校 + 持有效 PGWP |
| AAIP Alberta Opportunity | 海外零售(零经验)→ `open` tier 3 | `language>=4/5/7`、`experience>=24 months` | 须**人在阿省境内持有效工签在职** + 阿省雇主 offer |
| BC PNP Skilled Worker | 海外软件工程师 → `open` tier 0 | `experience` 1 行,`language` **0 行**(CLB 行挂在另一条 stream 名下) | offer + 雇主资质 |

### 1.2 代码上的确切位置

```ts
// pathVerdict.ts:790 附近
const needsInfo = !excluded && (!gate.picked || gate.gap == null || missingSlots.length > 0)
const verdict   = excluded ? 'excluded' : needsInfo ? 'needs-info' : 'open'
```

`gate` **只看 experience 那一类**;语言或别的 factor 缺行只 `push` 一条 reason,**不影响结论**。
`missingSlots` 全文只在四处被填:`noc` / `clb` / `expCanadaMonths` / `province` —— 而这四处**都要先有一条匹配的
requirement 行**才会触发。于是:

> **没有行 ⇒ 没有闸 ⇒ 没有 unknown ⇒ `open`。**
> 系统只能发现「它有行的那些门槛里,你缺哪一项」,发现不了「它压根没有行的那类门槛」。

## 2. 为什么「把表补全」不是根治

- **不收敛**:补完 offer 还有身份、学历、雇主指定、社区连结、资金、体检、担保金……官网改版还会再缺。任何一条没抽到,`open` 就又错一次。
- **补的过程中系统仍在对外输出错误结论** —— 而且错得没有痕迹,没人会来报 bug。
- 这条铁律 CLAUDE.md 已经立过一次:「官方不公布」是需要举证的断言,不是默认值。现在是**同一个错误换了个位置**。

所以顺序必须是:**先把推理改成 fail-safe,再慢慢补数据**。改完之后,系统立刻从「乱说能走」退到「诚实说判不了」;
每补一类闸,就有一批通道从「判不了」升级成「能走」—— 用户看到的是**能力在长**,不是错误在改。

## 3. 方案

### 3.1 门槛清单(gate manifest):把「有哪几类闸」和「闸的数值」分开

每条通道一张清单,只回答**这条通道有哪几类闸**,每条挂一句官方原句作举证 —— **哪怕数值还没抽到**。

```
GATE_MANIFEST['NL-intl-grad'] = [
  { gate: 'credentialCanada', quote: '…graduated from a recognized post-secondary institution…', url, fetched },
  { gate: 'permitPgwp',       quote: '…hold a valid Post-Graduation Work Permit…',              url, fetched },
  { gate: 'offer',            quote: '…full-time job offer from a NL employer…',                url, fetched },
  { gate: 'language',         quote: '…CLB 4…',                                                 url, fetched },
]
```

- **13 条通道 × 6~8 类闸,一次性人工核定**,成本可数;它不是又一张 ETL 表,是**判定核的契约**。
- 有了它,「这一类闸我没数据 / 用户没答」才第一次**可被发现**;现在它根本不存在于系统里。
- 形状已被验证:联邦那几条早就是这个样子(库里 `FED` 有 52 行非语言/经验 factor,含
  `offerDesignatedEmployer` / `offerFullTime` / `workLocation` / `residence` / `workTeerMatch`),
  **缺的是各省**。所以这不是新发明,是把联邦已有的严谨度铺到省。

### 3.2 三值折叠:`met | failed | unknown`,禁止 null 静默通过

每一类闸的评估返回三值,裁决退化成一次纯折叠:

| 折叠结果 | 条件 | 对外口径 |
|---|---|---|
| `open` | 清单里**每一类**闸都 `met` | 能走(优先核对) |
| `needs-info` | 有任一 `unknown`(缺数据 **或** 缺用户答案) | 判不了,点名缺哪一类 |
| `gap` / `excluded` | 有 `failed`,按可否攒时间分 | 差 N 个月 / 不适用 |

`unknown` 必须分得清两种来源,因为对用户的意思相反(CLAUDE.md 那条铁律的同款):
**缺数据 = 本站没收录**(我们的问题) vs **缺答案 = 你还没答**(一步就能解决,给按钮)。

这一刀**不依赖补数据**,是让整套东西从 fail-open 变成 fail-safe 的关键改动,也是本批第一刀。

### 3.3 问卷由清单反推,而不是反过来

现在是 6 题 —— 因为当初定了 6 题。改成:**该问哪些题 = 用户职业/目标省相关通道的清单并集**,
按「能消掉几条通道的歧义」排序。信息量最高的三题就是:

1. 人在不在加拿大(境内/境外 + 持何种许可)
2. 手上有没有 job offer
3. 有没有加拿大学历

§1.1 那三条错判**全部落在这三题的射程内**。这样问卷不会再脱离判定核自己长。

### 3.4 案例库负例回归网

16 个 case 本来就是验收标尺([[case-library-methodology]]),现在只是文档。变成断言,**重点写否定式**:

- 从没来过加拿大 ⇒ 任何 International Graduate 类**不得**为 `open`
- 无 offer ⇒ AB Opportunity / SK Employment Offer **不得**为 `open`
- 缺学历认证 ⇒ 联邦 EE **不得**为 `open`

负例最便宜,也正是这次漏掉的东西。§1.1 的 5 个画像直接当头 5 行。

## 4. 词汇表:复用既有 `factor`,不新造

清单里的 `gate` 值**必须**取自 `pnp_requirements.factor` 已在用的词(`language` / `experience` / `residence` /
`education` / `workLocation` / `offerDesignatedEmployer` / `offerFullTime` / `workSelfEmployed` / `fundsMinimum` …)。
确实缺的才新增,新增时同步写进本节 —— 一个概念一个词,别让「加拿大学历」在联邦叫 `education`、在省叫 `credentialCanada`。

## 5. 展示口径(效果图,Mode B 注入生产页 DOM 实拍)

**排序即推荐** —— 未确证的通道**不许进前三**。宁可前三留白写「还要答 2 题才判得了」,也别拿一条他走不了的排第一。

**① 口径改后、只答 6 项时**:三条都判不了,点名缺哪一类,右上给一步就能解决的出口。

## 7. 影响面与回滚

- 同吃 `pathVerdict` 的三处:`/plan/pr` 方案卡、`/jobs` 详情页三项判定「个人条件」行、对话顾问通道话术。
  B1 会让这三处的 `open` 数量**大幅下降** —— 这是预期结果,不是回归。
- 回滚点:B1 是纯裁决层改动,单文件可 revert;清单(B3)是新增数据,不 revert 也不会让旧路径变坏。
- **埋点**:B1 上线后盯 `dp-quiz-done` → 方案卡曝光的漏斗,若「全判不了」导致跳出显著上升,
  说明 B4 必须紧跟,而不是回退口径。

## 8. 明确不做

- **不**继续「把 `pnp_requirements` 补全到不缺行」当作解法(§2:不收敛,且补的过程仍在输出错误结论)。
- **不**让 LLM 补判定结论 —— 工具层红线不变([[pivot-conversation-first]]),清单缺项由人工核定 + 官方原句锚。
- **不**为了让卡片好看而把 `unknown` 折算成一个「大概能走」的百分比 —— 那是把假阳性换了个包装。
