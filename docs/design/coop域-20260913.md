## 1. 用户故事

- 我选学校和专业之前想知道这校的 co-op 到底行不行:多少专业带 co-op、一个工作学期多长、真找到工作的比例、时薪多少。学校自己的宣传页不算数,要数字。
- 我想把渥太华三校和 Waterloo 这种标杆放一张表里横比,不是一校一个网站翻。
- 我是国际生,要确认自己能不能参加、2026-04-01 之后还要不要单独办 co-op 工签。
- 我登录了自己学校的板,想在站上直接看现在有哪些岗,不用每天登校内系统。
- 每个数字要有出处和年份;学校没公布就写没公布,本站没抓到就写没收录,别糊我。

## 4. 域设计(先判边界)

- **回答什么问题**:某校某专业的 co-op 能接到什么活、多少钱、多大比例找得到。主键 = 学校 × 专业,不是岗位 → 与职位板不同域。
- **和已有域的边界**:dli 域管「学校是谁、在哪、能不能申工签」(IRCC 名单);coop 域管「这校 co-op 的成果与规则」;两域靠 name 人工核定映射相接(照 qs → dli 8 所映射先例),coop 不 import dli。hireac(登录源岗位)另立域,方法 browser,原文进 crawl(slug 改 `board-hireac` 与其余板同名式),不挂 coop 役(禁顺手挂车)。
- **寿命**:学校公开统计一年一更,coop 役 interval 86400;hireac 按学期,手动触发(登录态在 Frank 本机共享 profile,容器拿不到 Windows 加密 cookie)。

```
etl/coop/          五件套:constants(SCHOOLS 人工核定表:校码 / 名 / 省 / 各项源 URL / 抓法)
                   scheme(SchoolFact / ProgramFact / WageFact / RateFact)
                   functions(段:fetch 官方页经 crawl 写门 → parse 四校各一解析函数 → store raw/coop/*.json)
                   main(SCHEDULED:fetch → parse → store;--only)
data/crawl/school-<code>/   官方页原文(每校一 slug)
data/raw/coop/     schools.json / programs.json / wages.json / rates.json

cms/src/collections/Coop*.ts;lib/db/sql.ts 加段;components/start 加 coopsection + 三小件
```

## 6. 口径与风险
