## 故事一:小李,IT 应届毕业生(主力盘,PGWP 开放工签)

**他是谁**:去年毕业,PGWP 在手,任何雇主雇他零成本零手续。刚在 `/plan/pr` 答完题(决策页是全站第二大动作:dp-open 454 vs jd-open 3,090),结论说他要靠雇主 offer 走省提名。他点了「查雇主」。

**他的痛**:板上的岗大部分要经验,应届的投不进;做 IT 也挑不了工种 ——「哪个要你去哪」。

**他怎么用**:
1. 从决策页带参直达:职业大类(IT)、省(ON)已预置;身份档案是「毕业一年内 + 无加国经验」,**「无经验可投」开关默认已开** —— 他没点任何东西,榜已经是他的切面。
2. 榜头一排职业胶囊(信息系统专家 100 在招、软件开发者 83…)给他号脉:这个市场哪个工种缺口大。胶囊只号脉,**不是筛选器** —— 整个 IT 桶是一个市场,不做下钻。
3. 从上往下扫星级,挑出十几家「有入门岗 + 有证据」的,点行进公司详情页,点「看岗位」落职位板去投。

**每行他要看到的(七格)**:雇主名+行业 / 地点 / **星级** / 在招(岗数,无经验占比灰注)/ 证据(指定雇主徽章 + 技能类 LMIA)/ 工资水位 / 动作(看岗位、盯这家)。

**要如实给他的真相**:入门岗大头在 TEER 4/5,移民要 TEER 0-3 —— 两个事实并排摆(入门友好 + 通道档),**不替他捏合**。

**做成的标志**:预置全对、榜首全是有入门岗+有证据的雇主、三步内落到一个岗。

## 故事二:老张,旅转工

**他是谁**:访客身份,没有工签 —— 必须有雇主愿意为他做 LMIA 才能落地。LMIA 对别人是旁证,对他是命门:做过一次的雇主才可能做第二次。

**他怎么用**:
1. 直达参数/身份档案标了旅转工画像 → **LMIA 筛选预置开、排序主键升格为技能类 LMIA**(身份预置层做,不动星级全局口径)。
2. 榜上只剩「在他的职业大类上有 LMIA 获批记录」的雇主,按最近获批季与份数排。

**做成的标志**:他看到的每一行都是做过 LMIA 的雇主,一行浪费他时间的都没有。

## 故事三:小陈,盯上 NB 试点

**她是谁**:分数不够 EE,盯上了大西洋/社区试点 —— offer 直通 PR、免 LMIA、雇主门槛低。一个社区的指定雇主就几十家,**那张清单就是她机会的全集** —— 她的打法是主动出击:圈定名单,一家家经营,投简历、冷邮件、上门。

**她怎么用**:
1. 选大类 + NB → **指定雇主 + 在招的排最高档**(有资格又真缺人,全板最该投);只有指定资格没挂岗的**不清零,中档保底** —— 正是她主动出击的对象。
2. 「只看指定雇主」开关做窄;行上徽章「指定雇主」,程序名 AIP/RCIP/FCIP 灰字小注。
3. 圈出目标后逐家点「盯这家」(见批三)。

**做成的标志**:她十分钟拉出一张可穷举的作战名单,知道先攻谁。

## 故事四:小王,查证中介说法

**他是谁**:中介跟他说「这家公司能担保,交钱包过」。他要验真。

**他怎么用**:
1. 板上搜索框常驻,输公司名即切**查证态:全库搜**,不受省/职业筛选约束(中介说的那家多半不在他的筛选面里)。
2. 命中:指定归属 + LMIA 记录直接摆行上 —— 有据。
3. 未命中:**「不在官方指定雇主清单内,警惕任何承诺担保的说法」**(文案属「≠资格认定」保留族)。

**做成的标志**:三十秒得到有据的答案,防坑定位落地。

## 从故事推出的形

**五个态**:① 首屏(未选大类+省):只有大类选择器、省选择器、搜索框,**不摊表**(混屏病根除);② 榜态:默认按星级排、点列头切主键(职位板惯例),开关三个:只看在招 / 只看指定雇主 / 无经验可投,375 表转卡;③ 行内:七格,点行进 `/companies/[slug]`;④ 查证态(搜索框有输入);⑤ 空结果态:放宽引导一键改筛选(换省/看全国),不给白屏。

**身份预置 = 全部智能**(零新判定逻辑,只读现成身份档案选开关):故事一~三的预置各一行规则;`noc=`/`program=` 直达参数照旧,精确 NOC 映射到大类、行上高亮「有你这个职业的岗」。

**路由**:双路由收敛一块板,mode 退役。`/employers/hiring` 301+「只看在招」开;`/employers/designated` 301+「只看指定雇主」开 —— 初评落点契约不断。

**Banner**:补戴全站统一页头(九模块页都有,此板漏戴),BannerModule 加 `employers` 档,照抄 jobs.tsx 的形。

**术语**:「名录」全站退役,统一**「指定雇主」**(小红书通用词);代码层 `designated` 不动。

**详情页补三块**:官方背书层级(指定=省审、LMIA=联邦审、Job Bank=CRA 商号)、招聘模式(当前岗 + 历史常招 + 规模代理)、按通道核对雇主(判据类核对清单,见「不做」)。

## 数据层:雇主池 mart 表(批一)

一行 = 一雇主;大类相关列按**雇主×本站 17 大类**分桶(一家最多 17 桶)。零新抓取,纯三源聚合(Frank 总纲:功能完全基于能抓到的数据)。

| 列组 | 字段 | 来源 |
|---|---|---|
| 身份 | 名称、行业、省、市 | 三源归一 |
| 在招(分桶) | 岗数、最新发布日、主要职业名 | jobs |
| 门槛(分桶) | 无经验岗数与占比、最低经验档 | experience_levels |
| 证据(分桶) | 技能类 LMIA 获批(份数+最近季) | build_lmia 按大类归桶 |
| 证据(全局) | 指定雇主归属+项目 | designated_employers |
| 星级(分桶) | 1-5 档 | etl 评分层算死 |
| 规模代理 | 历史累计岗数(含 closed)、运营省市数、wikidata 命中 | jobs+closed_jobs+employers 对齐 |
| 价值 | 工资水位 vs 行业中位 | 08 评分既有口径 |

**星级口径(Frank 拍死)**:权重 **指定雇主 >> 在招活跃+入门可及 > 技能类 LMIA(旁证)**;指定+在招=最高档,指定无岗=中档保底;**裸 LMIA 总量永不入星不入排序**(农场/海产霸榜实拍,技能列全空 —— 总量进详情页当背景);挂死「机会参考,≠资格认定」。

**口径单一(红线)**:星级/池表口径只有数据层一份;板只读,顾问工具只读(同 lib/ruling 先例:consult 调 ruling 引擎,LLM 只转述)—— 不许出现顾问说四星、板显三星。

**工程**:脏活归 `etl/clean/`(公司名三源归一复用 companies 既有逻辑,残差留空不硬合;经验档归一);DB 走 `docs/sql/` DDL 先行 + payload_locked_documents_rels 补列六步;池表构建落单源事实表惯例,自成整块,配合日后 etl 分域重构整体搬迁。

## 批三:盯这家

钮 = 注册闸(身份先留下,和答题前注册闸同一地基),订阅落库;提醒推送链路另立批。「盯一家雇主、深查一家雇主」= 对「经营名单」动作的代劳 —— 简化操作才收费。

## 不做 / 边界

- **不做全局机会榜**:农业/医疗水量必然霸榜(LMIA 排行实拍为证);所有信号只在「大类×省」切面内呈现。
- **不编规模**:雇员数/营业额无源永久结案(2026-08-10 拍板);代理列(历史岗数/运营省市数/wikidata)进事实不进星级 —— 大公司未必要新人。
- **不标「正规」**:官方背书层级已长在证据列里,挂标签像本站背书。
- **判据类雇主要求不入列**:安省 OINP 等(营收/员工数门槛)官方无名单、指标无源 —— 做**核对清单**给用户拿去问 HR,落 pathways 判定与公司详情页,板上不出现。
