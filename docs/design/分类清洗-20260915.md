# 分类清洗(2026-09-15)

> 起因:Frank 2026-09-15 看 HireAC 岗「HireAC 的分类好像都没有清洗出来」→「之后基于公司的分类清洗也很重要」→「分类需要基于 job 描述用 AI 来分吗」→「洗分类是非常重要的,如果没有分类,基本没法理解职位」→「职位的分类,公司的分类。之后就可以类比,相似,这些。如果没有分类,什么也做不了」→「清洗分类是不是需要单独创建一个域来处理比较好」→「用 NAICS,先写设计稿」。
> 主线哪一格:数据补全(地基)。职位板的筛选、TEER 与省提名信号、相似雇主、以后的相似职位,全部读分类;未分类的岗在这些地方等于不存在。

## 用户故事

- 作为求职者,我在职位板按职业大类筛,Jobillico、Jobboom、HireAC、GC Jobs 的岗和 Job Bank 的岗一样能筛到,不会因为来自第三方板就掉进「未分类」。
- 作为求职者,我看一条岗的 TEER 与「可走省提名」标记,它是按这个岗真实的职责判的,不是按标题里某个词撞出来的(筹款经理不会变成「工程科技研发主管」)。
- 作为求职者,我打开一家公司,看到它属于什么行业(加拿大官方行业分类 NAICS);「相似雇主」列的是同行业的公司,不是「都招过技工」的公司。
- 作为 Frank,我能看到每条分类是怎么来的(源带码 / 规则 / 模型 / 行业标签表),模型拿不准的留空,不硬塞;换模型或改提示词时整批作废重跑,不和旧结果混。
- 作为以后的「相似职位 / 相似公司」功能,我直接复用分类结果与嵌入向量,不再另起一套。

## 方案:新域 `etl/classify`

### 边界三问

- **回答什么问题**:「这条岗是什么职业,这家公司是什么行业」。
- **和已有域切在哪**:
  - `noc` 域 =「有哪些职业类」(官方表 + 本站分类树),基础设施叶子,不动。
  - `statcan` 域 =「有哪些行业类」:NAICS 是 StatCan 的表(先例:2026-09-06 NPR 刻度、分省临时居民搬去 statcan 域)。本方案给它加一步产 `raw/statcan/naics.json`。
  - `mart` 域 = 汇装与评分:只读本域产物填 `noc` / 行业列,不再自己猜。
  - `classify` 域 =「判归哪类」:规则、行业标签表、模型三种判法住一起,同一套口径。
  - 切法判据是「判定归类 vs 类目本身 vs 汇装」,不是「用不用 AI」(规则层也搬进来)。
- **寿命**:与职位板同寿;分类口径会持续迭代,节奏(盒子批处理)与 build 每小时汇装不同,拆开互不拖累。依赖方向:classify → noc(叶子)、classify 读 statcan / mart 产物文件;mart 读 classify 产物文件,不 import。

### 形状

照抄 `etl/jdformat/`(域五件套 + 局域网 Ollama 批处理 + 每 N 条落盘 + 失败冷却 + 断网整轮中止)。一域两役单元(METAS,load 域先例):`jobs`、`companies`,各自心跳。

### 职位段(结果:五位 NOC)

逐层判,**先命中先定,后层只填前层的空**:

| 层 | 判法 | 说明 |
|---|---|---|
| 1 源带码 | Job Bank 帖的官方 NOC | 本域不碰,原样过 |
| 2 规则 | `NOC_RULES` 正则 + 官方示例职称整名命中 | 从 mart 搬来,行为逐字不变(搬家批不改一字) |
| 3 候选检索 | 盒子 `bge-m3` 嵌入:岗(标题 + 正文前段)对 NOC(官方类名 + 示例职称 + 职责)求最近 K 个 | 只产候选,不定案 |
| 4 模型选择 | qwen3.6 读岗 + K 个候选的职责摘要,**只许从候选里选一个或答「无法判断」** | 输出必须是候选内的真实代码,校验不过 = 留空 |
| 5 留空 | 以上都没有 | 前端照旧显示「未分类」 |

- 板帖自带的线索(HireAC 专业名、Jobillico 行业标签)进第 4 层提示词当旁证,不单独定职业。
- 产物 `processed/classify/jobs.json`:`externalId → {noc, method(rule/title/model), candidates, model, v, at, note}`;只留当前 mart 在招岗。
- 版本号 `CLASSIFY_V`(先例:译文 `TRANS_V`):换模型、换提示词、换候选数 → 加一,旧 `v` 的模型记录作废重跑;规则层不受影响。
- mart:`collect_board_jobs` 改读本域产物填 `noc`,TEER / 大中小类 / 省提名照旧由 mart 按 NOC 算。

### 公司段(结果:NAICS 部门 + 子部门)

**前置:公司资料先补全**(2026-09-15 Frank「现在积累了一定的公司名。我觉得可以创建单独的公司信息抓取」「3 在 company 扩」,推翻「公司信息禁批量预抓」那条铁律的后半句)。实测 35,254 家在招雇主只有 28% 有官网、20% 有正文、19% 有简介,公司段吃不到料。改法 = `etl/company` 域母集从「在招担保雇主」扩到「全部在招雇主」:担保雇主按大类名次排在前,其余按在招岗数降序接在后面(`places_candidates` 分两段 + 新 `rank_tail`);sites 步去掉「只搜各大类前 `PULSE_RANK_MAX` 名」的闸(`sponsor_nosite_of`),否则尾段永远没官网,后面的正文、简介、行业分类全断在这一步。实测母集 26,087 → 35,254 家(尾段 9,167 家);**真正的松绑在搜官网那道闸**:排得上搜索的从各大类前 100 名的 2,638 家变成全部缺官网的 25,107 家。about 步的浏览器兜底仍只认前 `PULSE_RANK_MAX` 名,不放量烧浏览器。

找官网只用免费额度(Frank「2 用免费额度」):Google Places 每月免费 5,000 家、DDG 每轮 60 家、Wikidata 每轮 300 家;还缺官网 25,107 家,按免费额度约 5 个月补完,不买配额。

| 层 | 判法 | 说明 |
|---|---|---|
| 1 板行业标签表 | Jobillico 122 个行业标签 → NAICS 人工核定映射表 | 不用模型(先例:城市译名人工核定表);一家公司多标签取帖数多数 |
| 2 模型 | qwen3.6 读 `aiBrief` / `description`(可附在招岗职业分布当旁证),先选 20 部门之一,再在该部门子部门里选;可答「无法判断」 | 输出必须是 NAICS 表里的真实代码 |
| 3 留空 | 没标签、没简介 | 不为分类去抓公司资料(懒查询铁律) |

- 产物 `processed/classify/companies.json`:`slug → {naics2, naics3, method(label/model), model, v, at, note}`。
- 类目三语名:20 部门 + 99 子部门的中 / 韩名是人工核定表(随 NAICS 表一起进 statcan 域产物),不用模型现翻。
- 入库:companies 加 `naics_sector` / `naics_subsector` 两列 + `naics_industries` 维度表(按新维度表六步走,`docs/sql/` 手写 DDL 先行、补 `payload_locked_documents_rels` 列)。
- 老列 `companies.industry` 本批**不动**:消费者(公司页相似雇主、雇主板行业格、顾问提示词等)切到 NAICS 另立一批,切完再退役老列(将死的依赖幸存的)。

### 模型接线

- 局域网直连 `NEWS_LLM_BASE`(与 jdformat / news / company 同一台盒子同一个变量);嵌入走 `/api/embed` + `bge-m3`,选择走 `/api/generate` + qwen3.6。
- 只有 Frank 在家连着局域网时才跑;盒子连不上整轮中止,不记失败、不进冷却(jdformat 同款)。
- 量:未分类存量约 9 千条岗、一条约 10 秒 → 一天多追平;之后每天新增约一千条。NOC 候选向量 516 条一次算好缓存。

## 质量闸

- **只填空**:源带码、规则命中的,模型一律不碰。
- **只从候选里选、可以不答**:模型答不在候选里的码 = 校验失败 = 留空。
- **金标**:试点抽样由 Frank 人工核对,核对结果落 `data/raw/classify/gold_jobs.json` / `gold_companies.json`,之后每次改口径都拿金标跑一遍对比(判定层测试惯例:手写金标,不做快照)。
- **门槛**:模型作答部分准确率 ≥ 90% 才铺开;同时报弃权率(弃权高 = 候选检索不够,不是放宽门槛的理由)。
- 职位段铺开后跑 `noc` 域 `audit_noc_classes` 看大类分布有没有异动。
