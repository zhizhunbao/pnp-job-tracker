## 0. 目标一句话

雇主表每行回答:**「这家雇主满不满足它所在省的雇主侧提名门槛(经营年限/雇员数/营业额)」**——三态输出,不编数据。

## 1. 判定语义(红线先立)

- 三态:**✓ 达标** / **✗ 差某项(点名哪项)** / **「缺 X 判不了」**(照实说缺什么)。
- 营业额:官方不公布私企财务 → 有营业额门槛的省(ON/BC/MB),该项**恒为「判不了」**,除非将来上付费源(D&B,花钱操作 Frank 亲手)。
- 判定=对照官方公布的门槛标准,**不是省官方认证**;凭证≠承诺红线照旧,免责语义沿用。
- 公共部门雇主(卫生局/市政/学区,榜首多为此类)不在企业注册库里;省门槛主要针对私企——公共部门行显「公共部门」不硬判。

## 6. 实施记录(B3,2026-08-09)

**圈定**:named 集合 = `status=open && pnpStream` 非空的雇主(`data/mart/jobs.json` 按 `companySlug` 去重),
与首页三分表「PNP 榜」同一口径,实测 **1,982 家**(§3 设计里的 ~2,006 是估量,数据每日抓新有正常漂移)。

**两个数据质量 bug(过程中发现即修,均属「不编数据」红线)**:
1. **注册库两个日期字段都不是成立日**。联邦 CBCA CSV 的 `Anniversary date` 是年检周年日;OrgBook BC
   的 `registration_date` 属性是该条登记记录的**生效日**(amalgamation/续存都会刷新)——实测
   `englobe-corp` 落 `founded_year=2026`(荒谬值,会让它挂掉所有省的经营年限门槛判定)。
   官方真成立日在 Corporations Canada REST API(`activities[].activity="Incorporation"` 的 `date`),
   但该接口要 `user-key` 订阅(已实测无 key 直连 403 "Authentication parameters missing"),开账号超出
   本 agent 权限(信任边界:创建账号一律转人工)。**处理**:注册库路径整个删掉 founded_year 写入,只留
   `registry_status`/`registry_id`/`registry_src`;已写入的 72 条错误值全部清除。founded_year 现阶段
   唯一来源退回 AI 懒查(弱证据,`founded_src='ai'`)。**待办(需 Frank 亲自开通)**:Corporations Canada
   API `user-key` 订阅 → 补硬数据路(https://api.ised-isde.canada.ca/en/docs?api=corporations)。
2. **AI 批量脚本两处解析 bug**:① `[FOUNDED]`/`[SIZE]` 原正则用 `\s*` 接内容,`\s` 吃换行——模型把
   `[SIZE]` 答成空白(没照提示词写 `(not stated)`)时,正则会越过换行把下一节整行吃进来当 SIZE 内容,
   实测 `bell-canada` 落 `staff_est=1983`(其实是 FOUNDED 年份)、`cdc-computers` 落 `staff_est=30`
   (其实是 "Over 30 years" 司龄)。改按行严格切(`re.M` + `^...$`),一节只在它自己那一行里找。
   ② 原「一行里第一个数字就当员工数」在数字紧邻地点/车辆词时会取错:`englobe-corp` "Over 60 locations
   across Canada" 落 60(分部数非人数)、`winstar-transport-ltd` "12 trucks and 16 drivers" 落 12
   (卡车数非人数,真实人数其实是 16)。改成数字必须紧邻人数关键词(employees/staff/workers/
   professionals/people/personnel/team members/associates/workforce)才收,地点/车辆/门店数一律不当
   员工数——查不到可靠人数就留空。两处 bug 均已修复并重验(见下表,englobe-corp/bell-canada/
   cdc-computers/winstar-transport-ltd 现均无被误写的 staff_est)。

## 7. 复核与结案(2026-08-10,Frank「补 founded_year」→「所以这部分收益比较低」)

§6「待收口人清单」的 2、3 两条**就地结案**,别再按原文执行——原文的两个前提都已被实测推翻:

**清单 2 作废:AI 管道其实已经跑完了。** 缓存 `data/processed/employer_facts.json` 实查:1,984 家里
**1,863 家非公共部门全部 `ai_checked`**,剩 121 家全是公共部门(走 `public` 旁路,本就不判)。
命中 `founded_year` 521 家(28%),1,342 家查了查不到。**没有「尚未过 AI 的 ~1,833 家」这个待跑队列**,
重跑同管道无增量。天花板成因:friendLlm 无联网检索时只认名企,本地小企(Grand View Manor、4Tracks)查不出。

**清单 3 作废:不需要 user-key,但也救不了场。** 官方另有免费、无需 key 的 JSON 端点(来源=官方
「Accessing federal corporation JSON datasets」页):
`https://www.ic.gc.ca/app/scr/cc/CorporationsCanada/api/corporations/<corpnum>.json?lang=eng`
→ `activities[].activity == "Incorporation"` 即**官方成立日**,能纠 AI 错值(ZENFRI 2006→2010、
7-Eleven 1969→**1967**)。但**瓶颈在分母不在接口**:联邦库只收联邦注册公司,对 1,861 家非公共部门
雇主唯一名命中仅 **72 家(3.9%)**,其中 49 家(68%)拿到成立日,另 23 家 activities 是
`Amalgamation`/`Continuance`(合并/迁入,可作法人起始日,收进来该批覆盖可达 ~97%)。
本地雇主绝大多数省注册——§3 B3 那个 38.3% 来自 OrgBook BC(省注册库),不是联邦,两者别混。

**联邦 CSV 的 `Anniversary date` 复核:上一轮撤对了,别捡回来。** 61 家交叉验证 77% 对得上,但
不一致的 14 家**全部偏晚**,并复现了 §6 那个荒谬值(`Custom Helicopters` AI 1977 → Anniversary **2026**)。
它是滚动/续期年而非成立年,拿它判「未达标」会冤枉老雇主,触 CLAUDE.md 数据完整性红线。

**雇员数 / 营业额:永久结案,无公开源。** 不是抓取能力问题——联邦 Corporations Canada CSV 17 列、
ESDC TFWP 获批名单 8 列(`Province / Program Stream / Employer / Address / Occupation /
Incorporate Status / Approved LMIAs / Approved Positions`,`Incorporate Status` 8,790 行里 7,104 行=
`Unknown`),逐列核过均不含。加拿大私企财务只有上市公司强制披露。
**口径提醒**:联邦审 LMIA 时确实要雇主交财务报表/T4/经营记录,所以是「**官方掌握但不公开发布**」,
不是「官方不公布」——两者对用户意思相反,见 CLAUDE.md 举证铁律。

能回答的问题太弱(最多说「成立够 2 年」,用户要问的是「会不会担保我」,那由三合一判定答),
按主线判据推不动付费。已跑完的 49 家官方成立日在手(未落库),要不要回写待定;若回写,
仍走 §6 白名单外 + `docs/sql` 惯例。
