## 一、选项卡交互规范(Claude AskUserQuestion 的移植细节)

**灵魂六条(样式是次要的,这六条才是「眼前一亮」的原因):**

1. **需要决定才弹,不是每轮都弹**。触发只有两类:
   a. 缺关键档案槽(判定层 needs-info 指名的,如 PGWP 状态);
   b. 下一步分叉(先看 tier0 通道 vs 先比各省门槛)。
   装饰性选项三轮后用户就麻了 —— 宁缺勿滥。
2. **选项 = 短标签 + 一行后果**:「我有 3 年 PGWP →(纽芬兰通道立刻可判)」。用户一眼知道选它会发生什么。
3. **点选项 = 以用户身份发出这句话**,气泡进对话流。对话记录诚实完整;引擎拿到的是标准化槽位值
   (比自由文本抽取准 —— 这是选项卡对判定层的隐藏红利:抽槽 LLM 那步可以直接跳过)。
4. **推荐位带理由**:第一张「推荐」徽标 + 一句为什么(「先确认工签 —— 它决定你能不能走最快的 NL 通道」)。
   推荐规则复用判定层:**哪个缺槽解锁的 tier 价值最大问哪个**(与 C5 遗留的 needs-info 排序修复同一套逻辑)。
5. **永不堵嘴**:选项卡浮在输入框上方,随时可无视直接打字;第 4 张固定「自己说」→ 聚焦输入框。
   单选为主;确实不互斥的场景才多选(v1 不做多选)。
6. **手机优先**:点击目标 ≥44px、标签一行放下(折行=文案太长)、最多 4 张(超过 4 个用户就不选了)。

**实现落点**(不新造轮子):
- 编排层 followups 已存在 → 升级为结构化 `options[]`:{label, consequence, sendText, recommended?, reason?};
  缺槽反问(C5c 的 verdictFollowups)天然就是选项源。
- UI:ChatBox 空态示例卡就是现成形态基础,选项卡复用其胶囊样式 + 推荐徽标;点选走既有「示例可点即发」通道。
- 埋点:option-shown / option-pick(带第几位) / option-manual —— 推荐位命中率是「推荐规则准不准」的验收数。

## 二、与 C5 遗留修复的关系

选项卡的推荐规则 = needs-info 桶按 tier 潜力排序(同一次改动):
NL 因缺 PGWP 槽掉桶 → 修复后第一轮就该弹「你有工签吗?」选项卡,推荐位=「我有 PGWP(还剩≥4个月)」。

## 三、图片上传:有硬前置,先谈模型

**能力探测(2026-08-06 凌晨,实测证据):** 朋友服务 /v1 端点**接受** OpenAI 格式的 image_url 消息,
但 qwen3.6 是纯文本模型 —— 1px 测试图发过去 `prompt_tokens=16`(真 VL 模型会编码成数百 token),
答复「你消息好像没发全」= **图片被静默丢弃**。

- 🔴 **红线:模型看不见图就不许上传行**。文本模型 + 图片入口 = 用户传 offer 截图、模型假装看过开始编 ——
  比没有这功能坏一个量级。上线前必须有「模型真的看到图」的自检探针(就用本次的 1px 图 + token 数判据,进探活)。
- **前置(Frank 亲自)**:与朋友确认加视觉模型(Qwen2.5-VL 一类;显存/并发他说了算)。
- **场景价值排序**(有 VL 后):① 中介聊天记录截图 → 走 claims 对账(现成链路,只差 OCR 层);
  ② offer letter → 抽 NOC/时薪/时长喂判定层;③ 成绩单/语言成绩 → 抽 CLB。全部走「抽取→四态→guard」既有红线。
- **隐私(沿简历存档先例)**:默认不存、勾选才存;上传物是 offer/护照页级敏感件,隐私页三语同步;
  传输走既有 key 鉴权,不落第三方。
- **交互(Claude 侧细节,实施时照抄)**:附件钮 + 拖拽 + 粘贴三入口;缩略图预览可删;单图 ≤5MB、
  一次 ≤3 张;上传中禁发送;失败一句话不弹框。
