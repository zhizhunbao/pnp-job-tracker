## 二、差距清单(重写要补的,按职位板既有件逐条对)

1. **列宽与拖列**:职位板 `useColWidths`(表头第一/内容第二/总宽=容器宽永不横滚/cookie 记比例首屏不抻)
   + 2026-08-16 新的 **Excel 式拖列**(`resizeColWidths`:左列零位移、右侧整体让位)。雇主板现在是写死百分比。
2. **列显隐**:职位板的「字段 (N)」面板(选列、记忆偏好)。雇主板无。
3. **筛选区形态**:职位板是「常用一行 + 更多筛选折叠(激活计数徽标)」+ 清除筛选 + **保存此筛选**(登录态)。
   雇主板是一行平铺、无折叠、无保存。
4. **深链与快照**:职位板 `filters.shared.ts` 单一映射(URL↔筛选键↔SQL↔前端 state 四处同步)、返回时回放筛选快照。
   雇主板自己拼 URL,没有共用映射。
5. **排序**:职位板服务端排序 + 白名单(`SORT_COLUMNS`);雇主板是当前页内存排序(跨页排序不对)。
6. **手机形态**:职位板卡片流有星标/胶囊排/页脚等插槽约定;雇主板卡片只有三行,信息密度未对齐。
7. **空态/加载**:职位板有骨架与空态文案分型(未收录 vs 查无匹配);雇主板只有一句空态。

## 三、重写方向(建议,新 session 自行判断)

**优先考虑抽公共件而不是复制**:职位板与雇主板都是「筛选 + 表格 + 卡片流 + 分页 + 深链」。
可行路线 A(推荐):把职位板里与业务无关的那层(筛选壳、列宽/拖列、列显隐、分页、URL 同步)抽成
`ui/Board`,两边共用,雇主板只提供列定义与取数;路线 B:雇主板直接复用 `useColWidths` + `filters.shared`
的模式各自实现。**动手前先出一页设计**(design-before-refactor),别直接改 4,417 行那个文件。

## 四、红线(不许破)

- **被指定 ≠ 在招**:名录只说这家雇主可以走那条试点/试验计划,不代表在招、更不代表要你;在招一律以职位库为准。
- **职业「未列明」的行必须保留**:`nocs` 为空 = 官方名录没列职业(RCIP/FCIP 绝大多数如此),
  选了职业时**不许**当成不匹配剔掉——那是拿我们的数据缺口冒充官方排除(NL 实测 639 行里 115 行属此)。
- **性能**:6,680 行**禁止**整包进 SSR/RSC payload(#313 教训:/start 曾 6.92MB)。SSR 首页 + API 懒取。
- **站规**:PageShell 套壳、右上返回、无解释句、三语齐、375 优先、触控靶 ≥44、表格永不横滚、
  人话名主文案 + 代码灰字小注、禁「·」杂糅。
- **入口契约**:两条既有 URL 直达且预置筛选(初评表在用)。

## 五之前:Frank 2026-08-16 清晨追加的两条(**本次重写的一部分,优先级同正文**)

### A. 合成**一个路由**

「可以改成一个路由吧」——现在两条路由(`/employers/designated`、`/employers/hiring`)其实是同一块板的两种口径,
口径已经是筛选项之一,再分两条 URL 是同一件事写两遍。做法建议:

- 规范路由取 **`/employers`**(它现在 308 → `/start`,是 08-08 货架页下架的遗留;本次把它**改回真页面**);
  口径走 `?mode=designated|hiring`(缺省 designated)。
- 旧两条 URL **保留为 301/308 到新路由并带上原参数**(`/employers/designated?program=AIP&prov=NS`
  → `/employers?mode=designated&program=AIP&prov=NS`)。初评表「查雇主」的链接同批改成新路由,
  但**旧链接不许 404**(外部/收藏/SEO 都可能在用)。
- `SiteHeader` 的「雇主」一级项指向新路由。

### B. 指定雇主的**公司名要清洗**

「designated 公司名字 需要重新清晰吧」——名字是从各社区/省的官方名录 PDF/网页原样抄来的法人名,很脏。
**实测(6,680 行)**:`o/a`、`dba` 式「法人名 o/a 商号」**1,469 行**;纯数字号公司(`3291918 NOVA SCOTIA LIMITED`)
**509 行**;全大写 **283 行**;带 `Inc/Ltd/Limited/Corp` 尾缀 **2,527 行**;带括号 **1,003 行**;
同名多行(Tim Hortons ×6、Gardewine ×5、MNP ×4、Wal-Mart Canada Corp ×4)——加盟店/多址,**不是重复数据**。

样例:`56955 Nfld & Labrador Inc o/a Pleasantview Manor`、`Romm Holdings Limited o/a Pizza Delight`、
`CPRepair cellphone repair o/a CPRepair`。

清洗方向(**归数据层,不许在前端 format**,CLAUDE.md 核心理念:脏活在 ETL 干完,seed 只入库、前端只显示):

1. 新增清洗字段 **`display_name`**(展示名)+ 保留 `name`(官方原名,永不改——它是与名录对账、与 jobs.company 匹配的键)。
2. 规则:有 `o/a` / `dba` / `operating as` 的取**后半段商号**(用户认得的是「Pizza Delight」不是「Romm Holdings Limited」);
   纯数字号公司若无商号则**保留原样**(宁可留空不瞎猜:编一个名字比难看更糟);
   全大写做**保守的标题化**(保留 `MNP`、`CPRepair` 这类已知大小写混排/缩写,别把 `MNP` 改成 `Mnp`);
   尾缀 `Inc./Ltd.` 视展示密度决定去留(建议展示名保留、只做空白与标点归一)。
3. 同名多行**不许合并**(它们是不同地址的加盟店/分支):展示层按「名字 + 社区/城市」区分;
   若要聚合成一行,必须显式给出「N 个地点」并可展开——但那是二期,本次先把名字看得懂。
4. 三语:展示名是专有名词,**不翻译**;只在有官方中文名时另说(现在没有,不要造)。
5. 落地位置照既有惯例:`etl/clean/` 一个清洗关注点一个脚本(顶部声明 `IN_*`/`OUT_*` 绝对路径常量),
   产出进 mart → DDL 加列(手写 `docs/sql/`,禁 DB_PUSH)→ seed 接线 → 前端只读 `display_name`。
   **加列必须同时给 `payload_locked_documents_rels` 补列**(既有 checklist 第一坑)。
6. 验收:抽 30 条脏样本人工核对(尤其 `o/a` 与数字号公司两族);清洗前后行数不变;
   `name` 一字未改;前端不出现任何字符串 format 逻辑。
