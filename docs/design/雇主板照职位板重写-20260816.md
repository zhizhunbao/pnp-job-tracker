## 二、差距清单(重写要补的,按职位板既有件逐条对)

1. **列宽与拖列**:职位板 `useColWidths`(表头第一/内容第二/总宽=容器宽永不横滚/cookie 记比例首屏不抻)
   + 2026-08-16 新的 **Excel 式拖列**(`resizeColWidths`:左列零位移、右侧整体让位)。雇主板现在是写死百分比。
2. **列显隐**:职位板的「字段 (N)」面板(选列、记忆偏好)。雇主板无。
3. **筛选区形态**:职位板是「常用一行 + 更多筛选折叠(激活计数徽标)」+ 清除筛选 + **保存此筛选**(登录态)。
   雇主板是一行平铺、无折叠、无保存。
4. **深链与快照**:职位板 `filters.shared.ts` 单一映射(URL↔筛选键↔SQL↔前端 state 四处同步)、返回时回放筛选快照。
   雇主板自己拼 URL,没有共用映射。
5. **排序**:职位板服务端排序 + 白名单(`SORT_COLUMNS`);雇主板是当前页内存排序(跨页排序不对)。
6. **手机形态**:职位板卡片流有星标/胶囊排/页脚等插槽约定;雇主板卡片只有三行,信息密度未对齐。
7. **空态/加载**:职位板有骨架与空态文案分型(未收录 vs 查无匹配);雇主板只有一句空态。

## 三、重写方向(建议,新 session 自行判断)

**优先考虑抽公共件而不是复制**:职位板与雇主板都是「筛选 + 表格 + 卡片流 + 分页 + 深链」。
可行路线 A(推荐):把职位板里与业务无关的那层(筛选壳、列宽/拖列、列显隐、分页、URL 同步)抽成
`ui/Board`,两边共用,雇主板只提供列定义与取数;路线 B:雇主板直接复用 `useColWidths` + `filters.shared`
的模式各自实现。**动手前先出一页设计**(design-before-refactor),别直接改 4,417 行那个文件。

## 四、红线(不许破)

- **被指定 ≠ 在招**:名录只说这家雇主可以走那条试点/试验计划,不代表在招、更不代表要你;在招一律以职位库为准。
- **职业「未列明」的行必须保留**:`nocs` 为空 = 官方名录没列职业(RCIP/FCIP 绝大多数如此),
  选了职业时**不许**当成不匹配剔掉——那是拿我们的数据缺口冒充官方排除(NL 实测 639 行里 115 行属此)。
- **性能**:6,680 行**禁止**整包进 SSR/RSC payload(#313 教训:/start 曾 6.92MB)。SSR 首页 + API 懒取。
- **站规**:PageShell 套壳、右上返回、无解释句、三语齐、375 优先、触控靶 ≥44、表格永不横滚、
  人话名主文案 + 代码灰字小注、禁「·」杂糅。
- **入口契约**:两条既有 URL 直达且预置筛选(初评表在用)。

## 五、验收

- `cd cms && npx tsc --noEmit` 干净;`npx vitest run` 全绿(当前基线 38 文件 662 例)。
- 375 与 1440 双端实证:零横滚、控件 ≥44、SSR 文档不含全量行(给字节数)。
- 两条入口 URL 仍直达并预置筛选;筛选/排序/翻页均进 URL 且刷新可复原。
- 拖列:左列零位移、右侧整体让位(与职位板同一手感)。
