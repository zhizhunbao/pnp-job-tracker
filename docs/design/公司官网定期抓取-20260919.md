## 一、用户故事

**小王在雇主板上看到一家没听过的公司 Kognitive Sales Solutions,点开想知道三件事:它是干什么的、总部在哪、值不值得投。**

- 现在他看到的:一段「主营业务」—— 其实是模型凭记忆写的(网关的联网搜索 09-11 起没在工作,库里 39% 的 AI 简介零出处);
  「总部」是「—」;「地址」曾经是某一条岗的上班地点 Woodstock, ON(09-19 已清)。
- 官网页脚明明写着:`320 Matheson Blvd W., Unit #212, Mississauga, ON L5R 0H2`。
- 做完以后他看到的:每一条都来自这家公司自己的官网,点得开出处;官网没写的就空着,不编。

**Frank 自己(也是目标用户)的判据:** SOTI 总部被写成 Ottawa(真身 Mississauga)——「这不是胡说吗」。
凡是给用户看的公司事实,必须能指回一句官网原文。

## 二、做法(四层,照本站抓取链铁律)

| 层 | 产物 | 说明 |
|---|---|---|
| crawl | `data/crawl/company-<slug>/html_cache/` + manifest | 每家抓 3 页:首页、Contact、About(从首页链接里认,认不到就只抓首页)。带浏览器标识、跟跳转(Kognitive 的 `kognitive.ca` 跳到 `kognitivesalessolutions.com`,老抓法记成 `no text`)。原文落盘,解析写错了重算不重爬。 |
| raw | 每家一份抽好的页面文字(首页取**末尾**= 页脚,Contact / About 取开头) | 纯规则,不用模型。 |
| processed | `processed/company/site_facts.json`:每家一条「整理结果 + 每一格的页面原句 + 出处网址」 | 本地 qwen(不花钱)。**每一格必须附页面原句,程序回页面核对原句真的在,核不上这一格作废**。 |
| mart → DB | companies 表新列 | 见第四节。 |

**已验证**(09-19 试验,7 家):抽对 4 家(Compass `1 Prologis Blvd, Mississauga`、Extendicare `Markham`、Sienna、Kognitive 与官网页脚一字不差),
3 家答「没有」,**0 条瞎编**,每家 4~11 秒。

**来路排序(Frank 定):官网 → 维基 → 联网搜索。**
- 维基:Wikidata 有结构化的「总部所在地」(P159),`company` 域本来就在查 Wikidata,多取一格,不用模型。Magna(官网是 JS 渲染的,试验没读到)这类大公司靠它。
- 联网搜索:留作最后一档,**零出处的答案不算数**;先等网关那头修好。

## 三、整理成哪几节(**请 Frank 定**)

现有简介五节:主营业务 / 所在地 / 规模 / 成立年份 / 其他要点。建议改成下面七节,前四节沿用、后三节新增:

| # | 节 | 给用户回答什么 | 备注 |
|---|---|---|---|
| 1 | 主营业务 | 这家公司卖什么、服务谁 | 沿用 |
| 2 | **总部** | 街址 + 市 + 省 | 由「所在地」升级;进公司卡「总部」行与雇主板「总部」列(现在两处都是「—」) |
| 3 | 规模 | 多少人、几个点 | 官网写了才有 |
| 4 | 成立年份 / 母公司 | 多老、谁家的 | 沿用 + 母公司 |
| 5 | **其他办公地点** | 除了总部还在哪 | 新增;和岗位地点对得上,用户知道「这个岗是分店还是总部」 |
| 6 | **对新移民 / 外籍员工的态度** | 官网有没有提 sponsorship、LMIA、newcomers、visa support | 新增;**本站用户最想知道的一条**,只认官网原句,没提就空着,不推断 |
| 7 | **福利与招聘流程** | 官网 Careers 页写的福利、怎么投 | 新增;只在抓到 Careers 页时有 |

不做:联系人邮箱 / 电话(帖子上已有,抓来容易过期还招垃圾邮件嫌疑)。

## 四、要加的库列(companies 表,`docs/sql/` 手写 DDL 先行)

`hq_address` / `hq_city` / `hq_province` / `hq_quote`(页面原句)/ `hq_source`(出处网址)/ `site_checked_at`。
第 5~7 节进现有的简介文本(多三个节标记),不加列。region(相似雇主、雇主池主省在读)改成取 `hq_province`,没有总部的维持现状。

## 五、范围与节奏(Frank 已批:约 1.5 万家、每月一轮)

- 对象:**有官网 且 当前有在招岗**的公司(现 15,227 家有官网)。没人在招的不抓。
- 首轮:3 页 × 1.5 万家 ≈ 4.5 万次抓取;模型每家约 10 秒 ≈ 42 小时机器时间,盒子还要给整理版 / 译名 / 分类用,**首轮预计一周左右追平**。
- 之后每月一轮;页面内容没变(按正文哈希)的不重过模型。
- 顺序:被用户点开过的、在招岗多的在前(沿用探索队列「被列出次数」的排序)。
- 礼貌:同一主机间隔 ≥1 秒,遵守 robots.txt,失败冷却 14 天。

## 六、验收

1. Kognitive 卡上「总部」= `320 Matheson Blvd W., Unit #212, Mississauga, ON`,点得开出处;雇主板「总部」列同步。
2. 随机抽 50 家人工对官网:总部一格**零错**(允许空,不允许错)。
3. 首轮覆盖率报数:1.5 万家里抓到页面的、抽出总部的、各新节非空的各多少。
4. 老的零出处 AI 简介:官网版出来一家、替换一家。

## 七、与既有规矩的关系

- 「公司级数据一律懒查询,禁批量预抓」(Frank 铁律)—— 本案是 Frank 09-19 对**有官网的公司**改判为定期抓;范围收在「有官网 + 有在招岗」,没官网的仍走懒查询。
- 「抓取先落原文」「crawl → raw → processed → mart」—— 照办。
- 「LLM 不下结论」—— 模型只搬运官网原句,每格带原句核对。
