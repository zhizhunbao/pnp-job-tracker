# G3 简历对照 JD(「投前 5 分钟」)设计 — 2026-08-03

> 出处:[案例库](案例库-问题与结果先行-20260803.md) C03 / 缺口 G3,Frank 拍序第一。
> 完美结果(验收标尺):**「你的简历对这个 JD 缺哪三个词」** —— 最大流量入口(google_jobs_apply,
> 30 天 470 次,直落职位详情页)的用户已表达需求是「投中这份工作」,这是第一个对着它做的功能。

## 1. 形态(MVP)

- **入口**:职位详情页(整页 + 弹框两处)投递钮旁加一个按钮「简历对照这个岗」。
- **流程**:点开 → 粘贴简历文本(**MVP 只做粘贴**,文件上传第二期 —— PDF/docx 解析是独立工程,
  参考 OpenResume 的 MIT 解析器)→ `/api/resume-match` → 结果(**v2,Frank 2026-08-03 改拍**):
  - **表格**:左=工作要求、右=简历现状(缺的红 ✗ 排前、命中绿 ✓;固定布局百分比列宽永不横滚);
  - **免费层**:表格前 5 行(缺的优先)+ 尾行「其余 N 条命中 —— 覆盖 M/10」;
  - **锁区(Pro)**:全表逐条 + 按加拿大格式的重写建议;
  - 锁区入口用**全站统一 Pro 卡**(v2 新组件,见下)。
- **统一 Pro 卡**(Frank:「重新设计一个卡片全站统一使用,要精简,别让用户觉得烦」;
  规范经三轮效果图定稿 2026-08-03):
  - 结构:单行 flex = 文案(flex:1)+「解锁」钮(flex:none);
  - 色(Frank 五轮收敛定稿):卡底**淡黄** `#fffbeb` 边 `#fde68a`(付费信号)、文案正文灰 `#6b7280`、
    **钮全站统一蓝** `#2563eb`(白字 600)文字「解锁 Pro」——「Pro」只在钮上出现一次,文案里不再带;
  - 字:13px 单行;文案**极简**(Frank:「文字一多用户觉得烦,找不到重点」)——
    定稿式样只有两种:`<两三个词>`(如「完整对照和重写」)/ `还有 N 条结论`;
    **文案零符号**(Frank:不要任何符号 —— 连接词用「和」,禁 +、·、/、括号);
    不写枚举不写从句;超长**删词**,不折行不截断;钮内边距 7×13、圆角 8;
  - **打码区**(Frank 2026-08-03 拍:「做成打码更好」「还有 6 行就打 6 行码」):锁区正文用
    blur(5px) 占位纹理行,**行数 = 真实剩余条数**(数字真、纹理假);真内容照旧服务端不下发
    (付费闸铁律,devtools 翻不出),占位文案是固定假词不是糊掉的真话;
    **Pro 卡悬浮在码区正中**(absolute 居中 + 轻投影 `0 4px 14px rgba(0,0,0,.08)`,不再排在码尾)。
  - 落位:G3 首用 → **验收后单独一批**把报告页 ~5 行高的虚线锁区(🔒 多行 + 大 CTA)全站换装成
    「N 行码 + Pro 卡」。
- **登录墙**:必须登录(匿名不给 —— 同时喂注册漏斗);**每账号每天 3 次,Pro 不限**。

## 2. 中间(AI 进两头不进中间,照既有架构)

- LLM 走现有 `lib/llm.ts`(生产=Haiku,~$0.003/次;**#102 事故教训:必须带双闸** ——
  ①登录+日限 3 次(库表计数),②输入截断(JD+简历合计 ≤6k tokens)。
- Prompt 骨架:JD 原文(库里 `description`,懒抓兜底)+ 简历原文 → 强制 JSON:
  `{missing: [词1..3], coverage: 0-100, rows: [{req, hit, gap}], rewrite: …}`;
  免费响应只下发 `missing + coverage`(**服务端裁**,同 gateReport 惯例,devtools 翻不出锁区)。
- **简历不落库**(隐私红线):内存里比完即弃,不存原文不存解析件;日志只记长度与耗时。
  埋点:`jd-match-open` / `jd-match-run`(进漏斗表,分母=详情页浏览)。

## 3. 不做的(YAGNI)

文件上传、简历存档改多岗复用、中文简历翻译、投递代发 —— 全部第二期起议;
「缺三个词」验证有人用(埋点说话)之前不加码。

> **文件上传提前落地(2026-08-03 傍晚 Frank 拍)**:「只能粘贴」对手机用户(最大流量)近乎不可用。
> 且解析器不是新工程 —— E11-07 `/api/resume` 早有 pdf/docx 内存解析,抽成 `lib/resumeExtract` 复用;
> 新端点 `/api/resume-extract` 只抽文本不碰 LLM(登录墙 + 5MB,不占免费池),md/txt 前端 FileReader 直读。
> 文本一律回填粘贴框(用户能看能删改),对照链路一条没加。原件不落盘不入库照旧。
> 同批:眉题「AI 工具」删(Frank「不用标」);详情页重复锁行删(与报告钮同链接;jd-lock-seen/click 退役)。

## 3b. 已立项待做:简历存档与多岗复用(2026-08-03 Frank「按你的建议来」)

「不保存」在 MVP 是最便宜的信任姿态,但它让用户**每个岗都要重传一遍**,与求职副驾方向相拧。
立项范围(一个工作项,照 molit 六节惯例开工时出实现文档):
- 存:`users.profile.resumeText`(json 档案,零新列;上限 20k 字符)——上传/粘贴后弹「存进档案下次直接用」;
- 用:弹框打开时有存档即预填,一键对照;E11-07 建档抽取也直接吃它;
- 删:账户页「查看与清除简历」入口(能看能删是存的前提);
- 合规:隐私页改口径(存什么、怎么删),弹框小注同步。
**红线**:默认不存(用户点了才存);LLM 日志照旧只记长度。
