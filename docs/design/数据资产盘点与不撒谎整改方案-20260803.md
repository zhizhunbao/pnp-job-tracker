## 0. 病根:仓库里没有一层「数据说明自己覆盖到哪」

本 session 助手连错两次,值得记下来,因为**引擎犯的是一模一样的错**:

| 我说错的话 | 真相 | 我为什么会错 |
|---|---|---|
| 「SK 91 条清单里没有木匠 → 萨省不收木匠」 | 那 91 条是 SINP **三条行业专项通道**(医疗 48 / 科技 32 / 农业 11)。SINP 主线(International Skilled Worker 的 Employment Offer / OID / Express Entry)的职业口径**本站一条都没抓** | 我从 mart 表看到「SK 有 91 条清单数据」,就当成「SK 清单查全了」 |
| 「木匠不在 AB 的 78 条清单内 → ❌」 | AB 那 78 条 = 科技专项 44(indemand)+ AAIP Alberta Opportunity Stream **排除清单** 34(ineligible)。AB 是排除式省,木匠不在排除清单 = 按 TEER 粗筛**可以** | 同上,把「有清单行」当成「清单式省」 |

**`provListCoverage`([match.ts:62](../../cms/src/lib/match.ts))判定用的是同一个逻辑**:

```ts
const rows = dims.pnpOccupations.filter((r) => r.province === prov)
if (rows.length === 0) return 'uncovered'
return rows.some((r) => r.type !== 'ineligible') ? 'listed' : 'exclusion'
```

数行数 → 判「查全了」。于是 [report.ts:389](../../cms/src/lib/report.ts) 对着付费用户输出:

> Checked SK's published list: NOC 72310 is not on it.
> (查过萨省公开清单:木匠不在上面。)

**我们从来没查过那张清单。** 这条谎话现在就在生产站上,卡②「拿 PR」选「草原三省」即触发。
代码注释自己立过红线(「uncovered 不得当查过没有,三者混为一谈=报告撒谎」),`listed` 这一态漏了。

**结论:这不是人粗心,是缺元数据。** 人和引擎都只能靠数行数猜口径,就都会猜错。
补数据治不了这个病 —— 10 省 × 多通道 × 政策月月变,永远补不全;
**不全的时候敢不敢说清自己查到哪,才是能不能收钱的那件事**(中介卖的恰恰是「我什么都知道」,而且说不出出处)。

## 2. 方案:四层,自下而上

### L0 数据契约层(新建,是其余三层的地基)

一份 `data/source_manifest.json`,**每个原料源一行**,由 ETL 写入、mart 带出、前端与引擎共读:

```jsonc
{
  "id": "sk-tech",
  "province": "SK",
  "scope": "pathway",              // main(主线清单) | pathway(专项通道) | exclusion(排除清单) | none(政策上无清单)
  "stream": "SINP Innovation & Tech Talent Pathway",
  "authority": "saskatchewan.ca",  // 官方出处
  "script": "etl/pnp/scrape_sk.py",
  "cadence": "weekly",             // 期望周期 → 超期即告警
  "fetched": "2026-08-02"
}
```

**一份数据同时喂三个下游**:① `provListCoverage` 不再数行数,读 `scope`;② 报告每条结论的 asOf 有单一来源;③ 新鲜度告警拿 `cadence` 对 `fetched`。
**这三件事本来就是一件事** —— 分开做会做出三份互相打架的日期。

### L1 诚实层:coverage 五态 + 新鲜度自证

`provListCoverage` 四态 → 五态,判据从「行数」改成「该省有没有 `scope=main` 的源」:

| 态 | 省(按 L0 契约推导) | 未命中时**只许**这么说 |
|---|---|---|
| `listed` | MB | 「查过该省公开清单,不在上面」 |
| `exclusion` | ON(排除集为空)、NB、AB(AOS 排除式) | 「不在排除清单 → 按 TEER 粗筛」 |
| **`partial`(新)** | **BC、SK、NS** | 「本站覆盖了该省 N 条**专项通道**均未收录;**主线清单本站未覆盖**」 |
| `uncovered` | NL、PE | 「该省清单本站未收录,无法两向核实」 |
| `qc` | QC | 走自有体系,不参与 PNP |

命中侧不动(BC Build 收木匠、AB Tech 收 IT,都是真命中,带官方出处)。
**新增三语文案 `rpt.c.partialMiss`;`rpt.c.listedMiss` 从此只有 MB 能触发。**

新鲜度自证:`/api/health/freshness` + 超期源在报告里降 confidence 并写明「本条依据的数据最后更新于 X,期望周期 Y,已超期」。

### L2b difficulty 进选省份

难度进卡③。**两种走法,取 B**:

- **A. 难度进主排序**(清单命中 → 难度档 → 在招量):木匠得 MB→NS→BC 看着很对;
  但 Frank 这行会排出 **SK 第一** —— 推他去抢 13 个岗,安省 257 岗靠后。**荒谬,否决**。
- **B. 双栏并列摆事实**(推荐,已实算):
  - 木匠:「岗位最多:**BC 246 岗**,但竞争 tight(84.2)」／「最容易被提名:**MB**,easy(11.9)+ 在 MPNP 清单上 + 7-30 抽选 632 分」
  - IT:「岗位最多:**安省 257 岗**(渥太华 52),但 tight 且不公布清单」／「最容易被提名:**AB 49 岗全具名 + mid**;SK 更松但只有 13 岗」

  理由:「好走」和「有活」是权衡不是排序,压成一个名次就是替用户下结论 —— 违反本站措辞红线,也是我们跟中介的区别所在。

### L3 补全层(按两个案例反推优先级)

| # | 补什么 | 解锁哪句话 | 依据 |
|---|---|---|---|
| 1 | **PGWP 规则库**(时长叠加 / field-of-study) | 「再读一年 cloud 值不值」 | 现在只问 `pgwpBand`「还剩几个月」,没有规则能算「再读一年会变几个月」。这是留学生最贵的决策(学费 + 一年 $100K 收入),中介收钱最狠的一块,Frank 本人即用户,验收成本最低 |
| 2 | SK OID / NS / BC 主线清单 | 把 `partial` 三省升 `listed` | 直接消灭 §0 那类不确定 |
| 3 | SK / 海洋省抽选 + AB / MB 分值表 | 「哪个更快、我够不够分」 | 木匠问的三个选项里两个现在给不出时间窗 |
| 4 | 答题页加**海洋省**选项 | 现在只有 BC / 安省 / 草原三省 | 朋友的第三个选项压根不在题面上 |
| 5 | `designated_employers` 补 `fetched` | AIP 2931 家雇主可被引用 | 顺手,跟 L0 同批 |

## 5. 不做什么(YAGNI)

- 不建加权总分把「难度 + 岗位量 + 清单」压成一个数(§2 L2-A 已否决)。
- 不为「可能用得上」预抓公司级数据(懒查询铁律不变)。
- 不做十省全通道清单的一次性大抓 —— 按 §L3 优先级逐个补,每补一个省升一态。

## 6. 风险

- `scope` 的判定是**人工核对的政策事实**(同 `NO_LIST_PROVINCES` 惯例),政策变更需人跟。契约里带 `authority` + `fetched`,超期由 L1 告警兜。
- 加 `partial` 一态会让报告出现更多「本站未覆盖」——**这是诚实的代价,也是卖点**:说清查到哪,比假装查全更值钱。
