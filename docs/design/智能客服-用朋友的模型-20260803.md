# 智能客服(v1)——用朋友的模型(2026-08-03)

> 起因:Frank 的木匠朋友那句原话 ——
> 「亚岗昆学完木匠,现在安省,移民费劲,**中介说曼省有合作公司**,去曼省还是 SK 还是海洋省靠谱?」
> 四张卡的表单**收不到最后那半句**,而那正是他最焦虑的地方。
> Frank 拍板:大模型用**朋友的服务**(ngrok → qwen3.6),不用 Anthropic、不指望家里 Ollama。
> 前置依赖:[数据资产盘点与不撒谎整改方案](数据资产盘点与不撒谎整改方案-20260803.md)(结论层已修好,只差上线)。

## 一、为什么表单不够(三处,一处都补不了)

| 表单做不到 | 实例 | 客服能做什么 |
|---|---|---|
| **接住「别人跟我说……」** | 「中介说曼省有合作公司」 | 逐条对账:哪条我们能核、哪条核不了、核不了的他该自己盯什么 |
| **追问** | 报告出完他还有第二问:「那我要不要再读一年 cloud?」 | 顺着聊下去,不必重新答一遍题 |
| **说不出关键词的人** | 大多数人不知道「省提名」「TEER」,只会说「我想留下来」 | 从白话里抽出槽位;四张卡要求他先知道自己在做哪个决定 |

**卡片选择器不删**(2026-08-03 Frank 问过):点一下 = 零成本零幻觉的诉求采集,
输入框加在四张卡**上面**,两条路并存 —— 会打字的打字,不想打字的点卡。

## 二、红线(死的,不许商量)

**LLM 只做两件事:① 从自由文本抽槽位 ② 把引擎输出复述成人话并承接追问。**
**结论、数字、判定一律来自 `report.ts`;库里没有的就说没有。**

不是保守 —— 是 2026-08-03 当天的实证:助手(一个能力不弱的模型)在同一次会话里错了两次,
把 SINP 三条行业专项当成萨省全部清单、把 AAIP 排除清单当成清单式省。**静态页面里那是一行错字;
由一个会对话、听起来很懂的顾问说出来,用户会拿着它去跟中介吵,然后发现错的是我们。**
信任是拿 PR 那张卡收得到钱的前提(08-03 交接原话)。

## 三、模型:走朋友的服务

现状(实测 2026-08-03):

| 件 | 状态 |
|---|---|
| `cms/src/lib/friendLlm.ts` | ✅ 已有,46 行。`POST {BASE}/api/chat` + `X-API-Key`,支持 `system` / `web_search` |
| env `TRANSLATE_API_BASE` / `TRANSLATE_API_KEY` | ✅ 本地已配(ngrok 域名 + key) |
| 现有消费方 | JD 整理(J2)、公司调查(K) |
| `lib/llm.ts` 的 provider | ollama(本地,**生产不可达**)/ anthropic(**按量花钱**);**朋友的服务不在里面** |

**要做的**:把 friend 提升为 `llm.ts` 的一个 provider,客服默认走它。降级链:

```
friend(朋友 qwen3.6,零边际成本,公网可达)
  → anthropic Haiku(仅当 friend 掉线,且只用于抽槽位这类短请求)
  → 纯表单模式(输入框收起,四张卡照旧可用 —— 客服挂了不能把站带挂)
```

⚠️ **ngrok 免费域名会变**:`friendLlmReady()` 失败即静默降级(现有行为),但要加一条
新鲜度探针(启动时 + 每 N 分钟一次 `/api/chat` 探活),挂了在 `/funnel` 面板可见,
否则又是一个「探头没接线」——这站今天已经栽过三次。
语音(朋友那边有 Whisper)不进 v1,YAGNI。

## 四、交互(v1 最小)

```
首页:  [ 一句话说说你的情况 ______________________ ]  ← 新增
       拿 PR   |  找工作  |  选省份  |  职业规划        ← 四张卡照旧
```

1. 用户打一句话 → friend 抽槽位:`nocGuess` / `province` / `goal`(拿身份 vs 先找工作)/ `status` / `claims[]`(别人跟他说的话)
2. 槽位齐 → 直接调 `report.ts` 出报告;缺 → **一次只追问一个**(不甩题墙)
3. 报告渲染仍用现有 i18n 键(引擎回 key+params),客服只在下面接一段"人话小结 + 可以继续问"
4. 追问:每轮把「引擎已产出的事实」作为唯一可引用材料喂回去(grounded,同 `/api/advisor` 的既有手法)

**槽位与字段库对齐**:抽出来的东西必须落进 `lib/fields.ts` 的既有字段(单一来源),
不许客服自建一套。选省份那张卡 2026-08-03 已砍到 **2 道**(诉求 + 有没有 offer)——
客服要抽的就这两个,加职业与所在地。

## 五、差异化:外部主张对账(v1 就要有)

`claims[]` 是本站独有的一块 —— 中介核不了自己,小红书没有出处。

> 用户:「中介说曼省有合作公司,让我去曼省」
> 客服:「**能核的**:曼省 MPNP 在需职业清单收了木匠(官方清单,07-25 抓取),难度 easy
> (每个提名名额 11.9 人,BC 是 84.2),7-30 那轮 632 分发了 74 个邀请 —— 他推曼省这点站得住。
> **核不了的**:那家公司在不在招木匠、offer 是不是全职长期、雇主有没有走完 MPNP 手续 —— 这三点得你自己盯。
> **他没说的**:萨省也走得通(不在 152 条排除清单上),海洋四省 NS 也命中清单。」

对账三分法固定:**能核 / 核不了 / 他没说的**。第三格是杀手 —— 中介只会说他有渠道的那个省。

## 七、验收

1. 木匠原话整句喂进去 → 抽出 `noc=72310` / `province=ON` / `goal=pr` / `claims=[中介说曼省有合作公司]`,
   出报告 = 与 `buildProvReport` 直调结果**逐字一致**(客服不得改一个数)。
2. 追问「那我要不要再读一年 cloud」→ 必须回「PGWP 规则本站没有数据」,**不许编**(这条现在真没有)。
3. 断言:客服输出里出现的每个数字,都能在当次 `ReportFacts` 里找到出处。
4. friend 服务拔掉 → 输入框自动收起,四张卡照旧可用,站不挂。

## 八、不做什么

- 不让 LLM 排省份、算分、下资格判定(§二)。
- 不做通用聊天(问天气、问签证以外的事一律引回四张卡)。
- 不为客服另建题库/另建字段(§四)。
- v1 不做语音、不做多轮长记忆、不做人工接管。
