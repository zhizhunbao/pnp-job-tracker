## 0. 一句话

**规则先行,题跟着规则走。** 引擎里没有吃这个字段的规则,就不许加这道题 —— 否则用户多花十秒,报告一个字不变。

## 1. 现状:问了但算不了

| 已经在问的 | 引擎拿它干什么 | 结果 |
|---|---|---|
| 英语档 clb | **什么也没干**(各省语言门槛没建模) | 白问 |
| 加拿大经验 | 只对照 CEC 的 12 个月 | 一条 |
| 目标省 / 处境 | 决定算哪几个省 | 不改结论内容 |
| CRS | EE 分差(且站内没有计算器) | 多数人答不出 |

而规则本身**散在 `buildPrReport`/`buildJobReport` 的 if/else 里**:加一条规则=改一次代码、动一次测试,省与省之间还没法复用。这是这轮要改的根。

## 2. 规则的形状

一条规则 = **一个可核验的官方门槛**,不是我们的判断:

```ts
type Requirement = {
  province: string        // BC / SK / MB …
  program: 'PNP' | 'AIP'
  stream: string          // 官方通道名(与 pnp_occupations.label 同源)
  subject: 'applicant' | 'employer'   // 门槛落在谁身上(2026-07-31 Frank:「现在 OINP 对雇主也有要求了」)
  factor: 'language' | 'wage' | 'experience' | 'education' | 'age' | 'offer'
        | 'empRevenue' | 'empStaff' | 'empYears' | 'empLocation'   // 雇主侧
  op: '>=' | '<=' | 'in'
  value: number | string  // CLB 7 / 12(月)/ 'diploma' / 该职业省中位
  basis?: 'occMedian'     // 工资类:阈值不是绝对数,而是「不低于该职业该省中位」
  label: string           // 官方原文(英文),显示时挂 title 供核对
  url: string             // 官方页
  effective: string       // 官方生效日期
  fetched: string         // 我们抓取日期
}
```

三条硬约束(与既有数据层同族):
1. **阈值一个都不许前端编** —— 全部来自抓取入库的官方页,与 `pnp_occupations`(清单)、`pnp_score_factors`(分值表)并列;
2. **每条规则带 url + fetched**,报告里每句话都能点回官方;
3. **抓不到就是抓不到** —— 不写默认值、不拿别省的门槛套。

## 3. 引擎契约

```ts
evaluate(profile, reqs): {
  verdict: 'pass' | 'fail' | 'unknown'
  gap?: { factor: string; need: number | string; have: number | string; short: number }
  evidence: { label: string; url: string; fetched: string }
}
```

- **unknown 是一等公民**:该省该通道的门槛本站没收录 → 报告说「这条通道的门槛本站未收录」,**不猜、不按别省推**。
- 规则求值是**纯函数**(`lib/rules.ts`),builder 只负责把结果排成句子 —— 加省、改阈值都不动 builder。

## 3.5 雇主侧门槛(OINP 起,别的省也在跟)

Frank 2026-07-31:「现在 OINP 对雇主也有要求了」。ON 的雇主 offer 类通道对**雇主**设了门槛
(营业年限、营业额、全职雇员数,且 GTA 内外不同档)。这件事对引擎有两个后果:

1. **门槛不只落在申请人身上** —— 所以规则要带 `subject`。同一条通道会同时挂
   「申请人要 CLB X」与「雇主要经营满 N 年、营业额 ≥ M」两类行;
2. **我们只有一部分雇主事实,必须诚实分层**:

| 雇主侧要素 | 我们有吗 | 怎么用 |
|---|---|---|
| 地点(GTA 内外) | **有**(岗位地址已清洗到市/区) | 直接判档 |
| 在招规模、是否发过省提名清单岗 | **有**(jobs × company 聚合) | 作为「这家雇主熟不熟悉担保」的信号,不当门槛 |
| 营业年限、营业额、全职雇员数 | **没有** | 一律 unknown,报告写「这三项要雇主自己出材料」,**不猜不编** |

这恰恰是「规则先行」的价值:雇主门槛一入库,`/jobs` 的每个岗都能挂一句
「这条通道对雇主还有 3 项要求,其中地点这项这家满足」—— 而不是我们凭空说「这家能担保」。

## 4. 规则 ↔ 题 配对(这轮的六对)

| # | 规则 | 官方来源 | 需要的字段 | 题 | 报告里出现的结论 |
|---|---|---|---|---|---|
| 1 | 语言门槛 | 各省 stream 页 | `clb` | **已在问** | 「BC 这条通道要 CLB 7,你填的是中级 —— 达标 / 差 1 档」 |
| 2 | 工资门槛 | 各省 stream 页(多为「不低于该职业省中位」) | 本岗年薪 | **不用问**(岗位自带) | 「这个岗 $52K,BC 该通道要求不低于该职业中位 $57K —— 差 $5K」 |
| 3 | 加拿大经验 | CEC + 各省 | `canadianExpMonths` | **已在问** | 「差 4 个月到 12 个月门槛」 |
| 4 | 学历 | 各省 stream 页 | `eduLevel` | **新题一道** | 「该通道要求大专及以上,你填的是本科 —— 达标」 |
| 5 | 年龄 | 有分值表的省(SK) | `age` | **新题一道**(仅这些省出) | 进省估分,不单独下结论 |
| 6 | 雇主 offer | 各省雇主通道 | `hasJobOffer` | **已在问** | 已有 |
| 7 | **雇主门槛**(ON 起) | OINP 官方 stream 页 | 岗位地址(已有)+ 雇主材料(用户侧无) | **不加题** | 「这条通道对雇主有 3 项要求:地点这项满足;营业额与雇员数要雇主出材料」 |

**读法**:六条规则里四条用的是**已经问过的字段**——先补规则,报告立刻变厚,用户一个字都不用多答。真正新增的题只有两道(学历、年龄),而且年龄只在有分值表的省出现。

## 5. 数据层

```
etl/pnp/build_bc_req.py   BC 各 stream 的语言/工资/经验/学历门槛 → data/raw/pnp/bc-req.json
etl/pnp/build_sk_req.py   SK 同上
etl/09_build_mart.py      合表 → data/mart/pnp_requirements.json(列对齐 DB)
docs/sql/…-requirements.sql  DDL 先行(纯 ADD,手写,不跑 DB_PUSH)
```

- 自校照 `build_sk_points` 的惯例:**官方页结构变了 → 保留旧表不覆盖**,并在日志里喊;
- 与 `pnp_occupations` 的关系:清单回答「这个职业在不在」,requirements 回答「在了之后还要满足什么」;
- 与 `pnp_score_factors` 的关系:分值表是**打分**(BC/SK 才有),requirements 是**门槛**(所有省都可能有),两者不混。

## 6. 报告里长什么样

新增一节「门槛对照」:一行一条,左=官方要求,右=你的情况,差多少写在后面;未收录的通道单独一行说明。效果图见 §9。

**免费/付费的线不变**(库里查得到的免费、拿你的答案算出来的付费):
- 免费:门槛是多少(官方事实)+ 达标/不达标的判定;
- 付费:**差多少、按什么顺序补、补完够哪条通道**(这需要拿你的答案跨省算)。

## 7. 红线

- 阈值不许编、抓不到就说未收录(unknown);
- 判定只说「达标 / 差 N」,**不说「你能移民 / 不能移民」**(与 match.ts 措辞红线同族);
- 规则改版要留 `effective`,报告显示的是**当时有效**的那版,不是最新那版覆盖历史。

## 8. 施工顺序

1. BC 先行:官方 stream 页结构最清楚,先抓语言 + 工资两类(覆盖面最大);
2. `lib/rules.ts` + 报告「门槛对照」节 + 单测(黄金三例:达标 / 差一档 / 未收录);
3. SK 跟上(同一套 build 脚本模板,加省=加一个文件);
4. 学历题入库(第 4 条规则落地当天再加,不提前);
5. 其余省按官方页可抓性排队,抓不到的省保持 unknown。
