## 1. 用户故事

- 我在选定去哪之前要比城市,不是比省:同一张表看每个城市岗位多不多、工资多少、城市多大、失业率高不高。
- 我想知道哪些城市有自己的移民通道 —— 大城市卷,小城市要是有专属通道我愿意考虑。
- 我要查自己惦记的那个城市,输入名字直接到,不翻 40 页。
- 我在手机上看,表不横滚、城市名是中文。
- 我点一个城市,落到职位板就是这个城市的岗,数字和刚才表上对得上。

## 3. 定稿:四张横比表替四百张卡

段名「选城市」(锚点 pl-city 不变,子导航:主要城市 / 行业对比 / 试点社区 / 留学城市)。总判据:**选城市 = 横比**,纵深(单城历年序列、单城大类分布、雇主/DLI 名单)一律归批三城市详情页,不进本段。段内一搜四表,全部走通用表格件(与省份段同一件,职位板形态):

### 3.1 城市搜索

段首一个搜索框,全量 2,602 城可搜(中文译名或英文名),选中落职位板 `/?city=<name>`(带来源标记)。搜索件复用职位板既有搜索形态,不新造。400 卡与翻页器整体退役 —— 截断问题、翻页问题一并消失。

### 3.2 表 1 · 主要城市表(默认按在招降序,可排序)

| 列 | 数据 | 现状 |
|---|---|---|

| 在招 | 与职位板同口径 | **批一对齐**:现状 stats_city 快照比 jobs 现查少 18~22%,查清 mart 批次与 DB open 差异根因后统一 |

### 3.3 表 2 · 行业对比表(城市 × 大类在招,零新抓)

同一个城市对护士和程序员是两个城市:行 = 主要城市(与表 1 同序),列 = 大类在招数。数据 = jobs 表按 city × broad 聚合(mart 域新增段,列对齐 stats_city 的城市清单)。效果图取体量前九大类(医疗 / IT / 工程 / 技工 / 建筑 / 餐饮 / 零售 / 运输 / 制造);实施时列取本站 17 大类按体量截前 N,还是沿趋势段六分组,收口前定。格子点击落职位板 城市 + 大类 双筛选。手机四列(城市 / 医疗 / IT / 餐饮 —— 列取舍实施时可调)。真数已有判断力:温哥华餐饮 524 医疗 176,多伦多 IT 74 全国最高,素里技工 264 建筑 553。

### 3.4 表 3 · 试点社区表(城市级唯一专属通道,20 行全显)

列:社区(译名 + 英文灰注)/ 省 / 通道(RCIP·FCIP)/ 在招(覆盖城市 join stats_city)。行点击落职位板对应城市筛选;社区官网链接进详情不进表(避免外链噪音)。这是「小城市反而有通道」的差异点信号,从雇主段省级视角提为城市段主信号。

### 3.5 表 4 · 留学城市表(dli 表,零新抓)

学签人群选城市第一问是「那有什么学校」(Frank 本人画像)。行 = 城市按 DLI 数降序(蒙特利尔 27 / 多伦多 15 / 魁北克市 12 / 温尼伯 9 / 卡尔加里 8 / 哈利法克斯 7 / 渥太华 5 / 萨斯卡通 5),列 = DLI 院校 / 其中公立 / 毕业可申工签(dli 表 isPublic / gradProgram 三字段全现成)。不塞进表 1:手机列数有上限,且受众不同。行点击落点(DLI 名单页有没有现成家)实施时定。

### 3.6 埋点与收拢

- 表行点击、搜索选中、试点行点击各挂事件(白名单追加,照 pulse-sec 三事件形:低基数枚举只计数);落地 URL 带来源标记。
- advisor/citycards 富卡(大类分布/DLI/AIP/区级下钻)保留原位;**批三**评估是否升格为「城市详情」单页并与本段收成单一出口 —— 要另立项,不进本案。
- DLI 院校数、AIP 指定雇主数等每城富信息归批三城市详情,不塞对比表(列数守手机上限)。
