## 一、目标形态(完美问题 → 完美结果)

用户在职位详情页(或对话框)给出自己的档案(年龄/婚姻/CLB/学历/经验/身份),系统产出:

1. **排除表**:哪些路径走不通,每条挂官方原文理由(如「MPNP:自雇不计 + 外省 −100,估分 695 vs 抽选线 825,天花板 715 够不着」)
2. **可用表**:按「offer 到手后还要等多久」分档(Day 0 / 3–6 月 / 12 月 / 24 月),每条带门槛差距
3. **估分**:能自算的通道给分数与参照线(OINP EOI 62→94 的可推高路径;CRS 对照 CEC 516)
4. **单点杠杆**:「唯一毁掉全部路径的动作」「唯一同时加分的动作」这类跨路径结论

**红线不变**:排除/估分/排序全部由判定层(SQL + 纯 TS)算出,LLM 只组稿;每个数字挂 evidence;
「官方不公布」「本站未收录」四态一路带到见客层;凡是 C01 里标「待核」的,机器版只能说「待核」。

## 三、批次(接续 C 系编号,每批独立可上线)

### C4 数据补口 —— 库能撑住 C01 的每一个数字(纯 ETL,无版式)

- **A 已抓未入 mart(只写 ETL,不再抓)**:NB 抽签记录含职业类别(`crawl/nb-imm`)、MPNP EOI 六因子积分表(`crawl/mb-mpnp`)、SINP 清单适用范围+行业上限(`crawl/sk-sinp`)、NL ITA 批次(`crawl/nl-imm`)。
- **模型三修(走 docs/sql 惯例,DB_PUSH 答 N)**:`pnp_occupations.list_kind`(受理/排除/定向)、`pnp_draws` 子通道列、`pnp_score_factors` 补 MB(EOI 六因子)。
- **B 已知 URL 未抓(小)**:OINP 审理时长页、SINP 两个排除 PDF、配偶开放工签清单页。
- **不做**:就业区级工资(C01 认定的最大影响项,但要 URL 发现,单独立项别拖住本批)、RCIP 社区雇主名单(懒查询铁律)。NL 645 家指定雇主 NOC 已在缓存,入 mart 属 A 类。
- **出口**:C01 §八 A/D 清零;金标脚本能从 mart 直接 SELECT 出 C01 里的 MPNP 695、NB「建筑类 2026 至少 5 次」、SINP「Employment Offer 不受 243 清单约束」。

### C5 判定层 pathVerdict —— 档案进,裁决出(纯函数,无版式)

- **Slots 扩槽**:age / marital / clb / eduLevel / canadaStudyYears(LLM 只抽取,缺槽反问,不猜 —— 沿用 NOC 铁律)。
- **`lib/pathVerdict.ts`**:输入完整档案 → 对每条通道输出 `excluded(带 quote 理由) / eligible(带差距) / needsInfo(缺哪个槽)`;
  估分器三个:CRS(组合 `ee_points_grid`)、OINP EOI、MPNP EOI(用 C4 补的 score_factors)—— **全查表,零硬编码分值**。
- **排序即产品**:按「offer 后等多久」分档(0/3-6/12/24 月),档内按配额竞争度;这是判定层的输出字段,不是 LLM 的发挥。
- **金标 = C01**(案例库当验收标尺):马龙档案喂入,断言 CRS 185/199、MPNP 695/595(天花板 715)、OINP 62/81/86/94、
  排除表 5 条及理由 quote、「避开 75110」「CLB 6→8」两条杠杆 —— **任何一个数字对不上就是判定层的 bug**。
  第二金标沿用 2026-08-03 木匠对话(防止只对 C01 过拟合)。
- **出口**:`pathVerdict(profileC01)` 的输出与 C01 文档逐数字一致;接进编排后对话能答「我这条件走哪条路」。

### C6 见客 + 入口(Mode B:效果图先行,Frank 点头才 push)

- **对话内「裁决卡」组件**:排除表 + 分档可用表,照 JobsTable 形态,一行一条、无「·」杂糅、代码带人话注;英文先验、375px 先验。
- **职位详情页入口**(最大流量页,Google Jobs 落地不动):岗位已知 NOC/省 → 预填槽位的一句引导
  (形如「这个岗能不能带我拿 PR?」),点开进对话。位置与文案出效果图,Frank 拍板。
- **funnel**:`jd-chat-open / chat-profile-filled / chat-verdict-seen` 接进现 funnel。
- **出口**:真机截图(桌面+手机)过 Frank;生产验证入口点击进对话全链通。

### C7 付费闸(§五 拍板后实施)

- **切分沿用「事实免费、结论收费」**:免费 = 单省事实 + 排除表(带理由 —— 排除是「别踩坑」,免费给足信任);
  付费 = 完整裁决(全部路径分档 + 估分与可推高路径 + 单点杠杆 + 出处清单导出)。⚠️ 此切分连同 §五 原草案一并交 Frank 拍板,可能改。
- 复用 `PricingCard`/`buy()`;funnel 补 `chat-lock-seen / chat-pay-click`。
- **出口(=本计划总验收)**:第一笔陌生用户付费。在那之前,`chat-verdict-seen → chat-pay-click` 转化率是过程指标。
