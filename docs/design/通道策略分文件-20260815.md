# 通道策略分文件(一条通道一个文件)—— 20260815

> 起因:Frank 2026-08-15「每个通道一个策略文件吧?不要混在一起吧」。
> 今天两次踩坑(工签闸误判学签、NL 跨专业默认放行)都不是算法错,是**同一条通道的规矩散在四五个文件里**,
> 改一处想不起另一处。本文只定结构与迁移顺序,不改判定口径。

## 一、现在散在哪(实测,不是印象)

一条通道(以 `NL-intl-grad` 为例)的知识,今天分布在 **6 处**:

| # | 位置 | 装的是什么 |
|---|---|---|
| 1 | `lib/pathVerdict.ts` REGISTRY(1100 行文件里的 32 条 key 声明) | 通道名、去哪张表挑门槛行、抽选流名、算不算境外经验、清单型排除 |
| 2 | `lib/gateManifest.ts`(205 行) | 三类闸的有无 + 官方原句 + `asks`(今早新增) |
| 3 | `plan/pr/PrDecisionView.tsx` `FIELD_MATCH` | 专业对口提醒 + 原句(今天新增) |
| 4 | `api/profile-pathways/route.ts` `REGIONAL_FEDERAL_PATHWAYS` | AIP/RCIP 拆哪几个省 |
| 5 | `jobs/i18n.ts` `jpw.p.<key>` ×3 语 | 通道显示名 |
| 6 | `PrDecisionView.tsx` 若干 `row.key === 'AIP' \| 'RCIP' \| 'AB-opportunity'` 分支 | 在招口径、话术特例、gapKey 特例 |

**判据**:问「NL 国际毕业生这条路我们是怎么判的」,今天要开 6 个文件才答得全 —— 这就是要拆的理由。

## 二、拆成什么样

```
cms/src/lib/pathways/
  index.ts            # 汇总导出 PATHWAYS(数组+按 key 索引),其余文件只 import 这一个
  types.ts            # PathwayStrategy 类型(把上面 1/2/3/4/6 的字段收进一个契约)
  fed-ee.ts
  aip.ts
  rcip.ts
  ab-opportunity.ts
  bc-sw.ts  bc-build.ts
  mb-swm.ts  nb-sw.ts  ns-sw.ts  sk-offer.ts  nl-intl-grad.ts  on-workforce.ts  pe-sw.ts
```

一个文件的形状(`nl-intl-grad.ts`,示意):

```ts
export const NL_INTL_GRAD: PathwayStrategy = {
  key: 'NL-intl-grad',
  province: 'NL',
  stream: 'NLPNP International Graduate',
  name: { zh: '国际毕业生类别', en: 'International Graduate', ko: '국제 졸업생' },  // 从 i18n 挪进来
  match: { reqProvince: 'NL', reqStream: /international graduate/i },              // 去哪挑门槛行
  countsForeign: false,
  gates: {                                                                         // 原 gateManifest
    offer: { need: 'required', quote: '…', url: '…', fetched: '…' },
    statusInCanada: { need: 'required', asks: 'pgwp', quote: 'Must hold a valid PGWP.', url: '…' },
    credentialCanada: { need: 'required', quote: '…', url: '…' },
  },
  notes: [                                                                         // 原 FIELD_MATCH 等提醒
    { kind: 'fieldMatch', quote: 'Applicants … related to their field of study …', url: '…' },
  ],
}
```

**三条边界(拆的时候不许越)**

1. **数字仍在库里**。门槛的**数值**(CLB 6、24 个月、1560 小时)照旧来自 `pnp_requirements`,策略文件只写
   「去哪挑行」和「有哪几类闸」。把数值抄进代码 = 官方改版时代码与库两套真相,今天不犯这个错。
2. **算法不动**。`pathVerdict()` 的判定流程、排序、tier 语义一行不改,只把它读的常量换成 `PATHWAYS`。
   本次是纯搬家 —— 搬完 46 条 pathVerdict 测试必须全绿,一条都不许改断言。
3. **前端不许再写 `key === 'AIP'`**。第 6 类特例(在招口径 / 话术 / gapKey)进策略文件的字段,
   前端读字段不认 key —— 否则拆完还是散的,只是散得好看一点。

## 三、迁移顺序(一批一提交,每步测试全绿)

| 批 | 动作 | 验收 |
|---|---|---|
| A | 建 `types.ts` + `index.ts`,13 个文件**只搬 REGISTRY + gateManifest** 两处 | pathVerdict 46 条绿;`gateManifest.ts` 与 REGISTRY 删除 |
| B | 搬 i18n 通道名 + `REGIONAL_FEDERAL_PATHWAYS` | 三语页面名不变(实拍对比) |
| C | 搬前端特例(在招口径 / AB 话术 / gapKey / FIELD_MATCH) | 初评表实拍与 A 前逐行一致 |

## 四、代价(说在前面)

- 13 个新文件 + 2 个骨架文件,`lib/pathways/` 目录净增 ~15 个文件;换来的是「一条通道 = 一个文件」。
- 搬家期间任何人改判定都会撞车 —— 建议这三批连着做完,不要跨 session 悬着。
- `pathVerdict.ts` 从 1100 行降到约 800 行(REGISTRY 约 120 行 + import 挪走)。

## 五、待拍板

1. **要不要连「省级分值表因素」也进策略文件?** 现在它按省(`pnp_score_factors`)不按通道,建议**不动**
   —— 它是省的分制,不是通道的规矩,进来会把「一条通道一个文件」变成「一个省一个文件」。
2. **`FED-EE` 算不算一条通道?** 它没有 offer 闸、走 CRS 分数鸿沟,字段用得最少。建议照拆(结构统一优先)。
