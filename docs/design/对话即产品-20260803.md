# 对话即产品(2026-08-03 深夜拍板)

> Frank 原话:「之前的引擎和答题我不是很想要了」+「按你的建议来」+ 处置选「并存过渡」。
> 直接起因:当天木匠案例 —— 多轮对话(数据 + 逐条推理)给出的方案,质量远超答题页三张卡,
> 而且用户的真实输入就是一句话:「亚岗昆木工毕业,中介让我去曼省」。
> 本文是 [智能客服-用朋友的模型](智能客服-用朋友的模型-20260803.md) 的**升格版**:
> 那份文档把对话当四张卡的补充入口;本文把对话当**主产品**,答题页降为过渡形态。
> 红线、friend provider、claims 对账三分法沿用那份文档,不重复。

---

## 一、什么死、什么活(拆之前必须分清)

| | 去留 | 理由 |
|---|---|---|
| 答题页(SurveyJS 表单)、固定题库驱动的卡①②③ | **死**(并存过渡,不推广,追上后撤) | 形态淘汰:用户不知道自己该答什么题 |
| `rules.ts` 判定函数、`match.ts` 覆盖五态、措辞红线、i18n 键 | **活,换身份** | 从「报告生成器」降为**对话的工具层** —— 它们是当天答案没撒谎的全部原因 |
| mart 24 表 + 新三张运营统计 | 活(数据层不动) | 对话的全部弹药 |
| 报告卡片的渲染代码 | 活,改造成**对话内渲染组件** | 当天那张「省份横排表」就是对话里该出的东西,不必删,改成按需渲染 |

**总红线不变**(智能客服文档 §二原文):LLM 只做「听懂问题、决定查什么、把结果说成人话」;
**结论、数字、判定一律来自工具层,带官方出处;库里没有的就说没有。**
当天实证:能力不弱的模型在同一会话里连错三次(萨省清单、曼省 6 个月、「分母没人公布」)——
全靠「被问一句就去查」纠回来的。产品里没有 Frank 反问,**查表必须是默认动作,不是纠错动作**。

## 二、目标形态

```
首页: [ 一句话说说你的情况 ____________________________ ]   ← 主入口
       拿 PR | 找工作 | 选省份 | 职业规划                    ← 过渡期保留,下移,不推广

用户:我亚岗昆木匠毕业,还没工作,中介说曼省有合作公司让我去曼省
系统:(抽槽位 noc=72310/prov=ON/exp=0/claims=[中介推曼省]
      → 调工具:门槛×9省、学徒岗计数、曼省外省毕业生条款、SK EO 流程、NS CCW 命中
      → 合成)你现在缺的不是选省,是第一份算数的岗…(每句带出处,可展开省份对照表)
用户:那被抽中概率多大?
系统:(调 lookupOps)阿省官方发池子人数:23,056 人,7-15 一轮捞 833 ≈ 3.6%…
      萨省 Employment Offer 不进池,不存在抽选…(出处:官方 EOI 页)
```

与旧智能客服 v1 的差别:**不是「槽位齐了一次性吐整份报告」,是多轮、按需调工具、渐进作答**
—— 当天人工对话就是这么跑的,它就是规格。

## 三、工具层 v1(全部是既有代码/既有表的薄封装,不新造逻辑)

| 工具 | 底下是什么 | 答哪类问题 |
|---|---|---|
| `lookupThresholds(noc, teer, provs?)` | `evaluateRequirements` × pnp_requirements 205 行 | 「我够不够格 / 差多少」九省 |
| `lookupCoverage(noc, provs?)` | `provListCoverage` 五态 + pnp_occupations 616 行 | 「哪个省的清单收了我」(含 NS CCW 这类具名命中) |
| `lookupJobs(noc, prov?, {apprentice})` | jobs mart(~40k 在招) | 「哪里在招 / 有多少学徒岗」 |
| `lookupDraws(prov)` | pnp_draws + ab-stats 抽选史 | 「多久抽一轮 / 分数线」 |
| `lookupOps(prov)` | sk/ab/bc-stats(处理时长/配额 YTD/池人数/池分布) | 「等多久 / 名额还剩多少 / 被捞概率」 |
| `lookupEE(noc)` | ee_categories 94 | 「联邦类别抽选走不走得通」 |
| `checkClaims(claims[])` | 上面工具的组合 + 三分法(能核/核不了/他没说的) | 「中介说 X」 |

约定:每个工具的返回都带 `evidence{url, fetched, section}`;LLM 的系统提示里,
**没有 evidence 的句子不许出现数字**。工具入参对齐 `lib/fields.ts` 既有字段,不另建一套。

## 四、流程知识放哪(替代「学徒序」硬编码)

B1-2 那类顺序逻辑(0 经验 → 先学徒岗 → 攒满 1 年 → 选省)**不再写成卡片流程**,
写成编排层的**剧本提示 + 工具组合**:检测到 `exp=0` 时先调 `lookupJobs({apprentice})`
并把「经验是排期不是资格」的措辞规则(差多久、在哪干算数、fail 措辞禁用)放进剧本。
剧本是文本,改起来比改卡片代码便宜一个量级 —— 这正是对话形态优于表单的工程理由。

## 五、付费闸(草案,facts free / conclusions paid 在对话里的落点)

| 免费 | 收费(锁区) |
|---|---|
| 单工具事实:某省门槛、某省岗位数、抽选史 —— 「库里查得到的」 | **跨省合成方案**(≥2 省对比 + 时间线 + 下一步动作清单) |
| 第一轮粗答(方向性一句话) | **claims 对账全文**(能核/核不了/他没说的三栏) |
| | 方案的导出/收藏、后续追问深挖 |

呈现:对话里方案生成后出锁卡「完整时间线与出处已生成 → 解锁」,复用现 `PricingCard`/`buy()`
(pay-click 量具已验过接线正常)。数字与出处在免费层**不打码**——打码事实等于损害信任,
锁的是「合成」不是「事实」。⚠️ 这一节 Frank 未逐条拍板,实施前过目。

## 六、并存迁移(Frank 已拍:并存过渡)

1. 首页:输入框上主位,四张卡下移一屏;`/plan/*` 路由**不删、不加新功能、不推广**
2. 报告卡渲染代码改造为对话内组件(省份对照表、门槛对照行)
3. funnel 补 `chat-open / chat-slots / chat-answer / chat-lock-seen / chat-pay-click`,
   与旧 `jd-open → pricing-open` 并行量,**两形态转化对照是撤旧页的判据**(B7 的延续)
4. 88% 英文流量:对话三语跟随现 i18n 惯例,英文优先验收
5. Google Jobs 富结果落职位详情页的主通道**不动**(那是流量命脉,与本改造无关)

## 八、验收(金标 = 当天那场对话)

1. 木匠原话一句话喂入 → 多轮内产出:先学徒岗(含各省计数)→ SK 不抽签/NS CCW 具名命中
   → 曼省外省毕业生 1 年条款 → 中介对账三栏。**每个数字能溯源到工具 evidence**。
2. 追问「被抽中概率」→ AB 给 23,056/833 的官方算法,SK 答「EO 不进池」,
   NS/NB 答「官方无数据」——**不许编**。
3. friend 服务拔掉 → 输入框收起、四张卡照旧,站不挂(沿用旧文档验收 4)。
4. 旧 /plan/* 回归测试照跑(并存期两形态都不许坏)。

## 九、不做什么

- 不让 LLM 下结论/排序/算分(总红线)。
- 不删旧页、不迁移旧用户数据(并存期)。
- v1 不做语音、多轮长记忆、人工接管(沿用旧文档 §八)。
- 不为对话新建题库/字段/数据表 —— 工具层只封装既有资产,发现缺数据走铁律 4(先补 URL)。
