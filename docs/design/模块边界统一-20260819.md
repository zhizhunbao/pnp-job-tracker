## 三、这次真正定下来的一条规矩:运行环境分门

原先同一条缝有三种拼法(`lib/jobs` 的两个门 / `employerCompareShared` 的驼峰后缀 / `app/*/x.shared.ts` 的点后缀),
三处头注释讲的是同一个坑的三个侧面。**统一成 `lib/jobs` 那种:`index.ts`(浏览器也能跑)/ `server.ts`(要连库)。**
理由只有一条:只有它带 eslint 闸,另两种靠人记 —— 而这条缝的失败模式是编译期看不见的。

**分门的判据订正**(设计稿原来写错了):不是「有没有 import `./db/*`」——
`db/sql.ts` 自己**零 import**,是纯 SQL 字符串,进浏览器包只是多几 KB,不炸。
真正的判据是**依赖链上有没有 `payload` / `@/payload.config`**,以及**函数要不要外部注进来的 `pool`/`Db`**(那种在浏览器里根本没法跑)。

### 顺带定了一条可 grep 的边界

> **数据访问只允许出现在两处:`lib/**` 与 Next 的服务端入口文件(`page.tsx` / `route.ts` / `sitemap.ts` / `opengraph-image.tsx`)。**

落地前全仓有两个违例(`app/(frontend)/stats/lib.ts`、`app/(frontend)/employers/board.ts`),都已收编。现在这条是一条 grep 就能验的闸。

## 五、⚠️ 实撞:桶会把「不是环」焊成环

`reportFacts.ts` **退回 lib/ 顶层,没进 `verdict/`**。原因是落地时实撞:

- `chat/tools.ts` 要 `assembleReportFacts`;
- `verdict/verdictCache.ts` 反过来要 chat 的 `loadVerdictData`(**值**,不是类型)。

两个文件各自没问题,一旦同属 `verdict/server` 这一个桶,「chat → verdict → chat」就成了运行时环 ——
`tsc` 全绿、`build` 全绿,**只有测试炸**:`chat/normalize.ts` 初始化时 `PNP_PROVINCES is not iterable`
(和 `lib/chat/types.ts:6` 记的是同一次教训的第二现场)。

**推论(比这次搬迁更值钱的一条)**:桶的边界要看**运行时值依赖的方向**,不只看域归属。
两个文件同域、同运行环境,但只要它们的值依赖指向相反的两边,就不能进同一个桶。

**留给下一批的判断**:reportFacts 唯一的消费者就是 `chat/tools.ts`,按「只有一个消费者的东西不该住共享叶子」,
它更像该搬进 `chat/`,而不是留顶层。但那是域归属的判断,不是这次的搬迁。

   - `local/client-no-server-values`(自写,~30 行在 eslint.config.mjs 里):`'use client'` 文件不许对
     `/server` 门做**值**导入,`import type` 放行。补的是 `ALLOW` 的盲区 —— 它只管路径,不管取的是类型还是值,

     flat config 的 `files` glob 也选不了「文件内容里有没有那行指令」。
   - `import/no-cycle`:实测**存量 0 环**,直接 error。验过它**追得穿桶**(`export … from` 的再导出照样算边)——
     所以 §五 那个 `chat → verdict → chat` 本来就该被它当场拦下,而不是等测试炸。
4. **散在代码里的指路注释**:`stats/lib.ts` / `stats/shared` / `lib/plan.ts PRO_COLUMNS` 等 8 处已订正。
   其中 `Table.tsx` 那两行是**双重失效** —— 它指的 `PRO_COLUMNS` 常量早就退役了,只剩注释在提。
