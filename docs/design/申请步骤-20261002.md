## 一、用户故事

1. 老张拿到萨省一家餐馆的 cook offer。点开职位板 PNP 格,「申请步骤」卡第 2 步是橙点:「雇主递职位审批 —— 限额行业只在收件窗口递,先到先得」,下面一张小表写着 9 月窗口餐饮 175 个名额 09-15 用完、下一个窗口 11 月;第 3 步「进池与抽选」灰字「不需要:持 offer 直接申请」。他明白卡他的不是分数,是雇主能不能在窗口开的那一两天抢到位置。
2. 小王手里有萨省科技岗和阿省科技岗两份 offer。两个弹框的步骤卡排法一样:萨省第 3 步灰字「不需要」,阿省第 4 步是橙点「抽选,最近 09-22 59 分 100 人」。不用懂制度,一眼看出萨省少一道关。
3. 小陈在安省找工作,弹框第 4 步橙点「改制后还没抽过」,知道这条路现在是在等。
4. 同一张卡在 EE 弹框、AIP 弹框里也一样:EE 第 2 步「雇主 offer —— 不需要」,第 3 步抽选挂 CEC 分数线;AIP 第 1 步「拿指定雇主 offer」。

## 二、卡的形态(10-01 统一骨架只换第 ⑤ 张)

顺序:① 结论 → ② 申请门槛 → ③ 名单 → ④ 配额 → ⑤ **申请步骤**(原「抽选」)。

- 每一步一行:编号圆点 + 步骤名 + 谁做(你 / 雇主 / 省里 / 联邦)+ 一到两行事实。事实只有三类:多久(处理时长、递件期限)、现在怎样(窗口满额、改制后未抽、最近分数线)、门槛前提(经营满 N 个月)。
- 抽选是其中一步,原抽选表(含本岗高亮、组头、全年合计)原样挂在这一步下面;安省「改制前的抽选」也挂在这一步,折叠。
- 省提名各通道都列「进池与抽选」一步;不需要的灰字写「不需要」,需要的写现状。九省才比得出来。
- 卡住的那一步圆点标橙(有窗口且满额、要抽选、改制后未抽);判据写在数据上(步骤带 `stuck` 依据),前端不猜。
- 与 10-01 拍板的出入:当时定「不抽选的只写一行『不经抽选』,删掉『持雇主 offer 直接递申请』这类说明句」。这次步骤行写「不需要:持 offer 直接申请」—— 作为步骤里的事实保留(效果图上已标出,Frank 未反对)。

## 三、数据口径

### 3.1 步骤登记(etl/pathways,通道表每条通道加一格 `steps`)

通道表本来就是人工核定的登记表(一条通道一段,带官方原句),步骤是同一种东西:几年一变、每格要原句。每步一项:

| 格 | 说明 |
|---|---|
| `step` | 步骤词(固定词表,三语词条在 cms i18n):`employerRegister` 雇主登记 / `offer` 拿雇主 offer / `epa` 雇主递职位审批 / `eeProfile` 建 EE 档案 / `eoi` 递 EOI / `draw` 进池与抽选 / `apply` 收邀请、递申请(无抽选的叫「确认职位、递申请」)/ `review` 省里审批 / `pr` 拿提名,递永居 / `settle` 做安置计划 / `endorse` 雇主递省背书 |
| `who` | `you` / `employer` / `province` / `federal` |
| `none` | 这一步不需要(只给 `draw`、`offer` 用);带原句 |
| `facts` | 事实行:静态的写 `{kind, value, unit, quote, url}`(如 10 天确认、60 天递件);动态的写引用 `{ref: 'processing', scope: '…'}`(处理时长读 pnp_ops_stats)、`{ref: 'intake'}`(萨省收件窗口)、`{ref: 'draws'}`(抽选表) |

自校:每条 `quote` 在 crawl 缓存里逐字核得上(同汇装「来源定位」段的口径),核不上自校红、不写产物。

### 3.2 萨省收件窗口(etl/pnp,`build_sk_stats` 同一页加一块)

Processing Statistics 页「Capped Sectors Intake Windows and Position Limits」表:窗口开放日 × 行业 × 名额 / 已用 / 剩余 + 满额日期(注释行原句)。进 `sk-stats.json` 新键 `intakeWindows`,mart 摊成 pnp_ops_stats 行(`metric` = `intake_limit` / `intake_used` / `intake_remaining`,`scope_kind` = `intake`,`scope` = 行业原名,`period` = 窗口开放日,满额日期进 `value_text`)—— 表已有,不加列。

### 3.3 萨省配额分行业

已在库(pnp_ops_stats,`scope_kind` = `sector`:优先行业 2,380 / 1,466、限额行业 1,190 / 718、其他行业 1,191 / 444,截至 2026-06)。`PNP_OPS_QUOTA` 当初写明「萨省的行业档 sector 不取」,放开取、配额卡按行出。

### 3.4 萨省门槛「身份」行

限额行业原句:「Capped sectors are limited to supporting current employees with valid temporary residency status」+「Applications for candidates in capped sectors with more than 6 months left on their work permit will not be accepted.」进 sk-req(factor = `status`,`applies_condition` = 限额行业)。本岗属于哪个行业**不判**(公司表没有行业字段),门槛卡写成「限额行业:…」条件句。

### 3.5 库表

`pathways` 加一列 `steps jsonb`(DDL 手写进 `docs/sql/`,Frank 审后执行;Payload collection 同步加字段,`lib/mart` 装载规格加列)。
