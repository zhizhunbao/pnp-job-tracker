## 1. 完美问题(用户视角的原话)

## 2. 完美结果的形状(这份方案为什么算「完美」)

八节,**每一节都在回答一个会改变行动的问题**,而不是罗列资料:

| 节 | 回答的问题 | 形态 |
|---|---|---|
| PGWP 三年 | 我的时间窗有多长 | 一个数 + 它成立的条件 + 一条警告(一生一次) |
| 12 个月经验的自由度 | 什么样的工作算数 | **反例表**(公司规模无关 / TEER 4-5 按 0 计 / 自雇不算) |
| TEER 2 目标职业 | 英语没到之前该投什么岗 | NOC 码 + **真实招聘职位名**(可直接拿去搜) |
| CRS 估算 | 我现在多少分、差多少 | **情景矩阵**(四种组合各自的分与判定) |
| 阿省路径 | 哪条可行、哪条不可行 | **可行/不可行两栏 + 每条的理由** |
| 为什么卡尔加里 | 去哪 | 招聘量 / 华人社区 / 门槛 / 生活成本 |
| 时间线 | 什么时候做什么 | 逐年逐月的动作序列 |
| 提分杠杆 | 先做哪件最值 | **按 ROI 排序**(+65 分 / +50 分 / …) |

**三条可复用的形态规律**(写进产品时照这个来):
1. **每个结论都带「凭什么」** —— 方案里每节末尾都有出处链接;
2. **不可行的路要点名说不可行** —— 「AOS 不可行」和「AEES 主路径」同等重要,只说能走的等于没帮人排除;
3. **杠杆要排序** —— 用户要的不是「有这些办法」,是「先做哪件」。

## 3. 复现率实测:**12 / 36 ≈ 33%**(2026-08-04 首测)

方案里共 36 个可核查的数字/断言。本站库 + `data/crawl` 能给出官方出处的 **12 个**。

**能复现(12)**:AEES 最低 CRS 300 · ATP 名单含 22220/22221/22222/21232(四个全中且都不在排除清单)·
WEOI $135 · 申请费 $1,500 · 阿省配额 6,403 · PGWP 最短课程 8 个月 · PGWP 2 年档 · PGWP 3 年档 · PGWP 一生一次。

**复现不了(24)**,集中三块:
- **联邦 CRS/CEC 计分与资格(15 个)**:CEC 的 CLB 7 / CLB 5、30h/周、12 个月、1,560 小时、
  学历 128 分、年龄分 72/66/61/55/50/39、海外经验 10 年窗口、可转移性 25+25。
  **`pnp_requirements` 里联邦只有 PGWP 9 行与 PR-fees 6 行,CEC/FSW 零行;全库无 CRS 分值表。**
- **事实性背景(4 个)**:卡尔加里华裔人口与占比、渥太华华裔人口、阿省无 PST。**定位上不收,也不该收。**
- **规则跳档与失效数(5 个)**:PGWP「合并后 ≥2 年 → 3 年」这一跳、EE 480/530 两端。

> **📌 最重要的一条观察**:**省级(AB)这一半我们几乎全能验,联邦这一半基本验不了。
> 而方案里出错的两条,恰好都落在联邦侧。缺数据的地方就是出错的地方。**
> 这条案例把「案例库=验收标尺」验得很干净 —— 复现率不只是进度条,它直接指出下一批该补什么。

## 4. 核查抓到的四条(会让用户决策错的)

1. **AOS 被误判为整条不可行。** 阿省学历那条只长在 **PGWP 分支**上;AOS 的闸在**工签类型**。
   走 LMIA 工签者学历门槛只是高中等同 + ECA。整条划掉 = 提前扔掉阿省**最大的一支:3,425/6,403 名额(53%)**。
2. **PGWP「2+1 合并 = 3 年」没有官方原文支持。** 官方写了「可合并」也写了「**your program** 满 2 年 → 3 年」(单数),
   但**没有一句把合并后的长度接到 3 年档**。`data/raw/ircc/pgwp_rules.json` 的 note 早就写着「引擎不得替官方补这一跳」。
   整条时间线的缓冲压在这上面 → 要正式确认。
3. **「AEES 最低 CRS 300」是地板不是尺。** AAIP 发邀请用自己的 **WEOI 分(0–100)**:
   2026-07-08 ATP 抽选切在 **WEOI 55**、149 邀;池内 2,136 人、配额 600、已发 388、**剩 212**、只审到 05-18 递交的。
4. **「联邦常规轮次 480~530」——常规轮次近 12 个月 0 轮**(`history.general` 空数组,最后一轮 2024-04-23/CRS 529);
   唯一可比的 CEC 12 轮在 **507–518**,下限比 480 高 27 分。

## 5. 现有工具能生成哪几节

**能全自动(4 节)**:省级门槛与差距(`lookupThresholds`)· 职业清单命中(`lookupCoverage`)·
抽签节奏与分数线(`lookupDraws`)· 配额/池子/排队(`lookupOps`)。
外加 `checkClaims` —— §4 的三分结构(证实/矛盾/本站没有)与它的 `checked/uncheckable/unsaid` **同构**。

**两处最划算的补口**(数据已在库里,只差工具):
- **`lookupDraws` 接受 `prov='FED'`** —— FED 56 行早在 `pnp_draws` 里,一行 SQL,§4 第 4 条的证伪即自动化;
- **新增 `lookupPermit`** —— PGWP 九条规则躺在 `pnp_requirements` FED 行里,**七个工具没一个读得到**;
  `planTimeline` 的 `PlanStepKind` 也缺 `permit` 这一档。

**缺数据补不上的(3 节)**:联邦 CRS 计分 · CEC/FSW 项目资格 · 人口与税率(后者不该收)。
