# 汇装提速:一小时的链为什么要跑 35 分钟,怎么拆(2026-09-12)

> Frank 2026-09-12 深夜「跑完,拆吧。不然每次都半小时等不起」。
> 起因:撤无薪资闸只改了三行 Python,上线却等了 35 分钟(排在整点自跑那轮后面 + 链本身 13~37 分钟)。
> 本稿先量再拆:每一步的实测耗时来自今晚 build 容器三轮日志(21:03 / 21:42 / 22:19 起)。

## 1. 用户故事

- 作为维护者,我改一条汇装规则后,希望 **5 分钟内**看到生产换数,而不是半小时。
- 作为维护者,我希望整点自跑那轮 **不占着锁跑 37 分钟**,否则我手动那轮只能排队。
- 作为读者,我不关心这些 —— 但 35 分钟的链意味着 Job Bank 新帖上板最坏要晚一小时,保鲜是主线。

其余所有步加起来不到 8 分钟。

## 3. 拆法

### A. JD 索引写侧维护,读侧只读一个文件(主刀)

- 判据:**谁写 .md 谁记索引**。jobbank 的 `parse_jobbank_details` 每写一篇 `details/<pid>.md`,同时往
  `processed/jobbank/details/index.json` 记一行:`url → {pid, mtime, experience, body}`,body 是清洗后的正文
  (`clean_jd` 现在在 mart 做,搬到写侧 —— 清洗归数据源域,与「谁的数据谁清洗」一致)。ATS 侧同形,记进
  `processed/ats/index.json`(ats 域写 .md 的那一步顺手记)。
- mart `fill_jd_bodies` 与 jobbank `flag_jobbank_apprentice` 改读索引:一次 `json.load`,零目录扫描。
- 首轮回填:一次性扫全部 .md 建索引(约 10 分钟,只跑一次;放 jobbank 域一个手动件 `--only jd_index`)。
- 体量:33k 篇清洗正文约 100 MB json,读 2 秒;比 12 万次 open() 便宜两个量级。若嫌大,body 分片按 pid 前缀切 16 片,读侧按需。
- 预期:apprentice 7.6 → <0.5 min;JD 匹配 9.5~36 → <0.5 min。**全链 13~37 分钟 → 约 6 分钟**,其中 employers 2 + upload 2 + seed 1 是硬底。

### B. upload 跳没变的表(服务端知情)

- 生产的 upload 落在 /tmp、随部署即弃,seed 读不到的表按空表处理 —— 所以不能本地记哈希自己猜,
  要先 GET 服务端「现有表哈希」再决定跳不跳(细节见 §5 批 3)。pte_audio 30 MB 每小时白传的账当场清零。
- 预期:upload 2 → <0.5 min(jobs 8 MB 每轮都变,照传)。

### C. 手动改规则的快路(不新建,只写清用法)

- 直通表:`mart --only <表>_table` + `load --only upload` + curl seed(已立,见 dli_table)。
- 跨源 jobs 规则(今晚这种):A 落地后 `python etl/mart/main.py`(score+mart+rankings+stats ≈ 2 min)+ upload + seed ≈ 4 分钟;不必跑 load 全链的 11 步。
- 整点自跑与手动撞锁:A 之后整点那轮只占锁 6 分钟,排队代价可接受,不另做抢占。

### 不做的

- 把 jobs 汇装搬进 SQL:文本清洗 / NOC 分类 / 薪资抽取不是 SQL 活(Frank 问「用 sql 跑 etl 是不是更快」——聚合类已经在库内重算,stats_city 先例;jobs 主表不搬)。
- jobs 增量汇装(只重算变了的源):收益在 A 之后不到 2 分钟,复杂度不值;等 A 上线后再看还剩什么。

### 批 3:upload 跳没变的表(服务端知情,不是本地猜)

⚠ 前提:生产的 upload 落在 `/tmp`,随部署即弃;seed 读不到某表文件时**按空表处理**(`martPaths` 返回 [])。
所以「本地记哈希、没变就不传」不行 —— 换版后 /tmp 空了,跳传的表会被当空表灌。必须**问服务端有什么**。

| 改哪 | 怎么改 |
|---|---|
| `cms/src/app/api/mart/state/route.ts` + `lib/mart` | 新壳 GET:列 /tmp/mart 里每张表(含分片)的 sha256;seed token 鉴权同 upload |
| `etl/load/functions.py` `upload_mart` | 先 GET state;本地表哈希与服务端相同 → 跳过并打「跳过(线上已有)」;不同或缺 → 照传 |
| `etl/load/constants.py` | state 路径、跳过报行 |

| 测哪 | 判据 |
|---|---|
| 正常轮 | 日志逐表打跳过/上传;跳过的表 seed 计数为 -2 |
| 换版后首轮 | state 返回空 → 41 张全传(不许出现「跳过」) |
| 半程失败 | 上传中断后再跑,缺片的表被判「不同」重传 |

| 跑哪 | 命令 |
|---|---|
| 验 | `docker compose exec -T build python etl/load/main.py --only upload` 两次:第二次 pte_* / macro_series 等全跳,jobs 照传 |

### 三批之后的手动快路

改跨源 jobs 规则(今晚撤闸这种):
`docker compose exec -T build python etl/mart/main.py` (≈2 min) → `--only upload` (<0.5 min) → `curl seed` (≈1.5 min) ≈ **4 分钟**。
改直通表:`--only <表>_table` → upload → seed ≈ 2 分钟。整点自跑那轮占锁 ≈ 6 分钟。
