## 现状为什么乱

不是哪一屏没做好,是三处结构问题:

1. **发信有两套界面**:「我的求职」里的投递区三步(简历 → 求职信 → 预览)和「今日待投」卡各管一套,改信、逐项检查各写一份;手动投一岗时待投卡整个消失(两套抢同一个位置)。
2. **进投递流程有 4 个口,4 种跳法**:职位页「邮箱投递」(页内软跳)、注册后(整页跳)、清单「继续」(同页只改地址栏,流程不开 = 死钮)、收藏行「投递」。真用户实撞:10-08 00:42 Moncton 一位从 ChatGPT 来的用户注册后 5 分钟里点了 8 次投递,0 封发出,Umami 没有他落到投递页的记录(当时线上投递钮是 `router.push` 软跳)。
3. **职业借了 PR 评估的 11 题问卷**:「今日待投」准备清单的「想做的工作 · 去选」跳 `/plan/pr?quiz=1`,进的是申请人条件问卷,关掉回不到「我的」。

## 参考:Azure 门户「创建资源」

来源(微软官方文档,2026 年版):[Quickstart - Create a Linux VM in the Azure portal](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal)、[What is the Azure portal?](https://learn.microsoft.com/en-us/azure/azure-portal/azure-portal-overview)。Frank 本学期 Azure 实验天天在用这一套。

1. **入口多,向导一个**:Home、服务页、资源组里的「+ Create」打开的都是同一个「Create a …」向导;从资源组里点进来,资源组已经替你填好。
2. **页签式向导**:Basics → Disks → Networking → … → Review + create;必填项标 `*`;底栏 Previous / Next / Review + create 一直在,随时能跳到最后一页。
3. **Review + create 先校验**:点了先跑一遍校验(文档原话 "A final validation runs"),通过出绿条 Validation passed;不过出红条,出错的页签亮红点,点回去改。下面按页签列出填过的全部内容,再点 Create。
4. **创建之后**:部署页从「正在部署」变成「部署完成」,给一个 Go to resource;右上角 Notifications 同时记一条。
5. **所有资源是一张表**:能筛选,每行点进去是这个资源的 Overview。

## 用户故事

### 入口(第 A 批)

1. 作为在职位页 / 职位弹框看到想投的岗的人,点「投递」→ **当前页弹出投递向导**(手机全屏,电脑大框;从职位弹框里点就叠在它上面)。收藏行「投递」、清单「继续」、待确认行「查看并投出」弹的是同一个框。地址栏同时带上 `?apply=<职位号>`,刷新、分享、邮件链接打开都是这个框;关掉框参数就去掉。不再有跳页。
2. 作为没登录就点了「投递」的人,只弹注册 / 登录框(不再先答目标、专业、职业、省四题);成功后留在原页并弹出投递向导(`?next=` 带着 `?apply=<职位号>`)。访客向导其余由头(进站即弹、点开职位、收藏)不动。
2b. 弹框好用的三个前提(10-09 Frank 问「现在所有的操作都是弹框 是不是用户会更方便一些」):
    - **手机返回键关最上面那层**:开弹框时往浏览器历史里记一笔,按返回只关顶层,不整页退走(10-09 查:通用 modal 只听 Esc,没接返回键;安卓用户一按返回,写了一半的信就跟着页面没了)。全站弹框共用,随 E 批一起做,A 批的投递弹框先用上。
    - **最多叠两层**:向导 + 预览可以,再往上不叠;要第三层就在当前层里换内容。
    - **能直达、不丢稿**:每个弹框都有地址参数(`?apply=<职位号>` 这类),刷新、分享、邮件链接都回到原处;半路关掉自动存草稿。职位页、公司页本身仍是真页面(Google 收录靠页面),弹框只管站内点击。
3. 作为点「继续」的人,向导落在**第一个还没齐的页签**;都齐了落「求职信」(唯一按岗变的一步);从待确认行进来落「检查并投出」。草稿里的信和选过的简历都带着。

### 向导弹框(第 B 批)

4. 弹框照站上公司弹框的形(通用 modal 桶的窗口形:标题栏可拖、拉边改大小、记住尺寸;10-09 Frank「所有弹框 都能放大缩小 拖动,保持一致」):顶栏小字「投递」+ 标题职位英文名(中文界面下一行灰字译名)+ 右上关闭;正文先三行键值:公司、市、省,每格英文黑字、中文界面下灰字译名(市、省分开)。
5. 页签四个:**基本 / 简历 / 求职信 / 检查并投出**(英文 Basics / Resume / Letter / Review)。375 宽一行放得下;缺必填的页签名后亮红点。
6. 按钮一排钉在弹框底部:上一步、下一步、检查并投出(任何页签都能直接点);到了「检查并投出」那页,主钮换成「投出」。
7. **基本**:英文姓名*、所在省*(按时区预选)。从档案预填;改了回写档案。职业不问 —— 用这条岗的职业。
8. **简历**:默认那份已选;能换成已传的另一份,或当场上传新的;点文件名叠一层弹框预览(复用「我的简历」的 pdf.js 预览)。
9. **求职信**:进页签时已写好。标题旁一枚小标:「AI 写」或「模板」;AI 写的旁边灰字「试用 2/3」。「改信」叠一层弹框编辑;「按职位重写」(试用用完弹升级框,照现在)。向导里**不出「代投」标签**(整个框本来就是在替他投)。

### 检查并投出(第 B 批,5 分)

10. 进这一页先跑系统检查(复用发信接口的同一套判定,只查不发,单一来源),一行一条,✓ 绿 / ✗ 红:
    - 岗位还在架(`E_CLOSED`)、这一岗有投递邮箱(`E_NO_EMAIL`)、没投过这一岗(`E_SENT`)
    - 收件邮箱没退过信(`E_BOUNCED`)、30 天内没给这个雇主邮箱投过(`E_SAME_EMAIL`)
    - 英文署名合规(`E_NAME`)、信长度与字符写得进 PDF(`E_LONG` / `E_CHARS`)、选了简历(`E_RESUME`)
    - 今天还能投(`E_LIMIT`,每人每天 20)
    - **新增**:信里出现这家公司名和职位名、没有残留占位符(纯函数,查信的正文)
11. 全 ✓:顶上绿条「检查通过」;有 ✗:红条「有 N 项要改」,对应页签亮红点,点那一行切回那个页签(同一个框里切,不另弹)。✗ 未清,「投出」不亮。不再有让人手动打的勾。
11b. **要他自己判断的只有两类,用 ⚠ 标出,每条两颗钮「去改」「照发」,不设空勾**(10-09 Frank 问「检查的时候需不需要 用户判断」):
    - ⚠ 信里有简历上找不到的说法(年限、证书、技能逐条比对;AI 写的信才查)—— 只有他知道真假,发出去收不回、伤的是他的信誉;免费号也全给。
    - ⚠ 岗位的硬性要求简历上没写(如这一岗的 Medical Terminology Certificate、2–5 年经验)—— 投不投是他的事,只提醒不拦;免费 / Pro 怎么分见待拍板 4。
    - 不做「我已阅读并确认」勾:闭眼能勾完,和现在四个空勾一样是形式。最后点「投出」就是他看完预览的确认(照 Azure 看完汇总点 Create)。
12. 下面是**邮件原样预览**(Frank「改成类似于邮件那种」):收件人、标题、正文全文、两个附件(简历文件名、求职信 PDF 名,点开叠一层弹框预览)。收件人默认只显示邮箱域名(`@connectwell.ca`),见待拍板 1。
13. 点「投出」→ 同一个框切到状态视图:发送中 → 已发出(绿)→ 两颗钮「查看这次投递」(换成投递详情框)、「关闭」(回到原页)。

### 我的求职一张表 + 今日推荐(第 C 批)

14. 「我的求职」只剩一张表:草稿 / 待确认 / 已投 / 雇主回复 / 退信,一行一岗,照职位板表格形(手机一岗一张卡;卡里职位名、公司名、市、省照英文在上中文灰字在下)。「今日待投」卡撤 —— 表上方摆今日推荐几条(每条带一句理由),操作「查看并投出」→ 弹出向导(此时才备信)停在「检查并投出」页签,一封一封过检查;点开过没投的留在表里成「待确认」;职位名 → 职位弹框;已投行「打开」→ 投递详情框。
15. **今日推荐不设开关**(10-09 Frank「投递这个也不需要开关吧」):开关是「自动投递」要征求同意用的;改成推荐后只是摆出来,投不投由他点,没什么要同意的。「我的求职」顶上一直是「今日推荐」几条;目标(找工作 / 拿 PR,复用访客向导第 1 题,答题档 `goalBand`)、想做的工作(职业单题)、所在省(拿 PR 的人是「愿意去的省」,多选,默认所在省)三样缺哪样,就在推荐的位置就地问那一题,答完推荐就出来;不弹表单、不跳问卷。
    - 信不在后台提前写:点开一条推荐时才准备(模板信即出,AI 信他点了才写才扣),给没人看的推荐写信的钱也省了。
    - 想每天收邮件提醒才要征得同意:另设「每天把推荐发到邮箱」一项,默认不勾;「每周邮件摘要」现在默认勾上(走查 3 分)一并改成不勾。
    - 推荐每人每天算一次、当天缓存(单人约 250ms,不在每次打开页面时现算全站)。
    - **条数与收费**(10-09 Frank「可以」):免费每天 3 条、配模板信;Pro 每天 10 条、每封 AI 写(10 是本稿定的默认,可调;每人每天发信上限 20 不变)。两档排法相同(15b)。免费号第 4 条起在推荐末尾露一行「另有 N 条今日推荐」+「升级 Pro」,点了弹现成的升级框。Pro 清单加一条「今日推荐每天 10 条,每封 AI 写」。
15b. **按目标挑岗,两套排法**(10-09 Frank「如果他目标是拿 pr 和 找工作 那 推荐的肯定是不一样的是吧」):
    - 共用的硬条件:在架、有投递邮箱、没投过、雇主邮箱没退过信、30 天内没投过这家(现 `QUEUE_CANDIDATES` 已有)。
    - **找工作**:职业对口 + 简历过硬性要求 → 越新越好 → 只推所在省 → 薪资不低于本省同职业中位。
    - **拿 PR**:先筛能走省提名的(`pnpEligible`、命中具名通道 `pnpStream`、指定雇主;全职)→ 按通道档 `gradeChannel` 往前排(5 = 省具名清单命中)→ 再看对口与新旧;省份按他选的「愿意去的省」。
    - 每条推荐附理由胶囊(照 Azure Advisor 每条建议写「为什么」;10-09 规范「小信号一律胶囊」用通用 `Tag` ok 档,一个理由一枚):如「能走 OINP 雇主担保」「今天新发」「职业对口」。投递表状态同用 `Tag`(待确认 info、草稿 gray、已投 ok),状态筛选用 `Chip`;求职信页签的「AI 写」用 `Tag` info。
    - 现状对照:线上 `QUEUE_CANDIDATES` 只按职业组 + 所在省筛、按旧的移民价值分 `score` 排,不分目标。
16. ~~关掉开关,表里的「待确认」行同步收起~~ 不设开关后这条不存在(原走查 3 分「关了开关清单仍待投 3」随之消掉)。
16b. **三个 section,顺序即先后**(10-09 测「我的求职」时 Frank「单独一个我的收藏没意义」「收藏之后,下一步就是准备投递了」「单独一个 section」):今日推荐 → 我的收藏 → 我的投递。「我的收藏」页签撤,收藏表原样搬进来,每行主钮「投递」弹投递框;投出后这一岗出现在「我的投递」。末尾第四段「新岗推送」:「每天把今日推荐发到邮箱」「每周邮件摘要(收藏岗动态)」两个勾,默认都不勾(见 15),下面一行灰字写发到哪个邮箱、随时可退订(10-09 Frank「加一个新岗推送的 section」);每段各一张白卡,照职位页「相关职位」卡(10-09 Frank「每个 section 都有一个单独的框」);公司名、城市、省份英文可点(N 批 Name 组件,10-09 Frank「英文加上可点击吧」);旧深链 `?sec=favs` 落「我的求职」。页签剩 我的求职 / 我的简历 / 我的档案 / 我的订阅。准备清单撤(简历、英文姓名、所在省到投递框「基本」「简历」页签就地填)。空态:收藏、投递各一行「还没有…」,不放「去职位板」(10-09 Frank「去职位板 删掉吧」,投递表已删)。
