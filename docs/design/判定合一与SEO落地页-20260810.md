## 1 · 拍板记录（2026-08-10，Frank 四连拍）

## 2 · 目标架构：一个核 + 一张决策页

```
决策页（一个 URL，默认 /plan/pr）
├─ SSR 事实区（爬虫吃这个）：各省通道概览表 + 低门槛通道卡 + 官方出处
├─ 答题（唯一采集面，默认收起一行入口——批1 补拍「不逼人考试」）：点选卡逐题 → 写 users.profile
├─ 三关判定卡：判定核算，付费闸唯一所在；带 ?job= 上下文时三关全开
│   └─ 官方分值表估分只活在个人关里（批1 实施中 Frank 补拍「测分数完全不用显示」——
│      页面不出测分工具，答案喂核，各省分数=个人关付费实底；加分事实转题目同批，见实现文档 C6）
└─ 「有疑问问顾问」：唤起全站挂件（带判定上下文）  ← 顾问只是补充出口
        ↓
判定核（唯一引擎）  pathVerdict + rules.evaluateRequirements + tripleVerdict
                    + pathwayRecipes（配方并入，管低门槛通道）+ pnpSelfScore
        ↓
事实层  chatTools 的 lookup* + reportFacts（口径纪律照旧：查不到=「本站未收录」）
```

分工一句话：**答题收人、判定核出结论、判定卡收钱、顾问答疑。**

## 3 · 决策页设计

### 3.1 SSR 事实区（免费，给爬虫和陌生人）

- H1 + 一段说明：靠雇主 offer 走省提名是什么
- **各省通道概览表**：省 / 是否收具名清单 / 语言与经验门槛 / 最近一轮分数线与日期
  （`pnp_requirements` 的 `label`+`value_text`+`url`+`fetched`、`pnp_draws` 的 `score`+`draw_date`+`stream_zh`）
- **低门槛通道卡**（原 /pathways 的配方内容）：护工试点 / 医护 / 技工 / 留学→PGWP / AIP，
  每卡步骤 + 出处，措辞红线沿用（摆信息不下结论）
- 官方出处与抓取日期逐条挂
- **SSR 区不挂付费闸**（硬规矩沿用初版 §3.5：陌生人第一眼撞墙，SEO 与信任两头亏）

### 3.2 答题（唯一采集面）

- 形态照既有点选卡：一轮一张、档案已有不问、答完写回 `users.profile`
- 题目全集 = `Slots` 已建模字段（noc/occText/provs/expMonths/status/clb/age/married/edu/eduYears/canadaStudy/studyProvince）
- **题目不进对话**：对话侧建档点选卡撤下；槽位抽取（`profileFill`）只作「聊天顺手补空」保留，档案正门是答题

### 3.3 三关判定卡

- `TripleVerdictModal` 组件迁入决策页（是搬家不是重写——它本来就是独立组件，判定核已同源）
- 无岗位上下文（从答题进来）：出个人关 + 职业关，雇主关提示「从职位页带岗进来解锁」
- 带 `?job=<id>` 上下文（从职位行/详情跳转进来）：三关全开
- **付费闸只在这一处**
- 官方分值表估分（`pnpSelfScore`，BC/SK 下界分）与 CRS 分差挂个人关——全站唯一「算出来的数」，按**留**设计

### 3.4 钩子（每屏出口，都是求职者的下一步）

1. **看这个职业在招的 N 个岗** → 职位板（`?noc=` 带好）
2. **哪个省岗最多 / 薪资最高** → 跨省对照
3. **问 AI 顾问** → 唤起挂件（带上下文）

## 4 · 顾问入口收敛（治「到处都是」）

**现状**：两套 UI、四类入口——

| 入口 | 形态 | 去向 |
|---|---|---|
| 全站悬浮挂件（layout.tsx 挂 `ChatLauncher`） | 独立 UI ① | **留，成为唯一 chat UI** |
| JobsTable 内嵌 `AdvisorChat`（多轮 grounded，`CHAT_ON` 现关） | 内嵌 UI ② | **删**（本就熄火，退役无痛） |
| /start「问顾问」按钮（`o2p:chat-open` + prefill） | 唤起 ① | 留，机制即终态 |
| 职位详情 C6 通道卡 `openChat` | 唤起 ① | 留 |

**终态**：全站所有「问顾问」按钮统一走 `o2p:chat-open` 事件唤起挂件、带各自上下文（岗位/职业/判定结论）。
对话不再收题（§3.2），只答疑。

## 5 · 引擎合并与 `report.ts` 迁移清单

| 资产 | 去向 | 理由 |
|---|---|---|
| 官方分值表估分（`pnpSelfScore`） | 决策页个人关（`PnpScoreCard` 组件现成） | 全站唯一「算出来的数」，付费解锁的实底 |
| EE CRS 分差（`crsEstimate`） | 决策页个人关 | 同上 |
| 换省对照、最快通道 | 弃（判定卡个人关已有） | 重复 |
| 雇主名单（sponsors） | 弃（判定卡雇主关已有） | 重复 |
| PDF 下载 | 弃 | 免费给出去的，无人使用记录 |
| `conclusions` / `LOCK_CAT` / `gateReport` | 删 | 第二套判定，口径分叉的根 |
| `pathwayRecipes` 配方表（原 /pathways） | **并进判定核**作低门槛路径候选 | 它是 /pathways 唯一独有资产（判定核只管雇主担保主路） |
| `evalPathways`（143 行） | 删 | 第三套判定 |

## 9 · 风险

1. **301 掉收录**：`/pathways` 挂着头部词 meta，301 后那个词位让出。可接受：流量大头在招聘富结果，
   两张页头部词本就没跑出量（存活方已拍定 `/plan/pr`，§6）。
2. **JobsTable 手术**（4,496 行，三处 modal 入口 + AdvisorChat）：判定改跳转会打断职位页内闭环，
   而入口=出口=职位页（67.5% 单页会话）。缓解：入口按钮原位保留、上下文带全、决策页右上 `goBackOr` 返回；
   手机上跳转本就比行内大弹框体验好（mobile first）。
3. **删 1,353 行 `report.ts` 牵动测试**：`report.int.spec` 有拿 PR 行为树 216 路径矛盾扫描,
   删之前确认哪些断言要迁到判定核的测试里。
4. **答题与对话采集并存的窗口期**：顺序上答题先上、点选卡后撤（§7.7），避免两头都在问或两头都不问。
