## 1. 为什么

一张 375×812 截图 ≈ 1.5k token，一轮两端全量 30 张 = 40–50k；同一页文本 dump ≈ 1–3k。
**截图占走查开销八九成**，而过去几轮真正查出的问题（废话、重复、裸词、折行、该点点不了）
**绝大多数能用 DOM 量出来**，不需要眼睛。

## 2. 工作模式（改这一条，别改整套工作法）

原：全量截图 → 逐张看 → 出整改意见。
新：**体检脚本跑全量 → 输出可疑清单 → 只对命中项截图确认（一轮 3–5 张）** → 逐条出整改意见 → 实施 → 下轮复查。
轮次文档、编号规则、闭环标记**一律照旧**（`docs/功能盈利点检查.md` + `docs/整改轮次/`）。

## 3. 脚本落位与约定

- 位置：`.claude/skills/iterate-audit/scripts/checkup.py`（与 capture_*.py 同处，走查 skill 一起调用）。
- 运行：**系统 Python312**（playwright 装在那儿，`uv run` 会 ModuleNotFoundError；`PYTHONUTF8=1` 必加）。

- 输出：`scratchpad/checkup-<轮次>.json` + 终端摘要表（**只打命中项**，不打全量通过项——输出过滤是省 token 的第二刀）。
  每条命中带：`page / viewport / lang / rule / selector / text 片段 / 建议截图=true|false`。

## 4. 检查项清单（首版就做这些，逐条可编程）

**文案**
1. 裸词/黑话：正文出现 `X/5`、单字「高」「中」「低」、`TEER` 无注、NOC 码无职业名。
2. 三语缺键回退：非中文界面里出现中文字符（白名单：公司名、地名原文、NOC 英文名）。
3. 废话与重复：同一容器内文本近似重复（归一后 Jaccard > 0.8）；同页同一事实出现两次。
4. 占位符泄漏：`{`、`undefined`、`null`、`NaN`、`[object`、`—` 连续多格。

**布局**（这几条替代肉眼看图，是本方案成立的关键）
5. 折行/截断：`el.scrollWidth > el.clientWidth`；或 `nowrap` 元素被 ellipsis 截断。
6. 出屏与横向滚动：`rect.right > innerWidth`、`documentElement.scrollWidth > innerWidth + 1`。
7. 元素重叠：同层兄弟节点 `getBoundingClientRect` 相交面积 > 0。
8. 触控目标（仅手机）：可点元素 `rect.w < 40 || rect.h < 40`。

**交互**
9. 可点必有态、不可点必无：`onClick`/`jcellAct` 与 `cursor:pointer` 不一致。
10. 死链与空动作：`href="#"`、点后 DOM 无变化的按钮（抽样点，不全点）。

**数据口径**
11. 页面数字与库对不上：抽样几个（在招总数、命中清单岗数、心跳「核对」时间）直连生产库比对。
12. 空态说人话：`—` 格是否有对应解释路径（本轮刚改过 PNP/AIP，重点复查）。

**运行时**
13. console error / warning（hydration mismatch 单列）。
14. network 4xx/5xx；首屏 LCP 与 JS 体积（有现成数就记，别为它加依赖）。

## 5. 不查什么（诚实划界）

留白舒适度、配色深浅、字体渲染、"好不好看"——**这些必须眼睛看，而且 Frank 自己判断比模型准**。
脚本只保证：**凡是能量化的问题不靠运气发现**；观感类留给命中项的那 3–5 张截图与 Frank 本人。
