# 职位正文服务端直出(2026-09-14)

> 起因:Frank 2026-09-14「检查一下 Search Console 数据」→ 点击从 7/25 日 200 掉到日 1~2;「那就把职位正文服务端直出,先出方案」。
> 证据(全部 2026-09-14 实测,详见本文「现状链」):Google 3 个月 2,000 点击几乎全来自 Google Jobs 富结果;职位富结果有效条目 8 月初起为 0;抓取量 7/22~7/28 日 2.5 万 → 9 月接近 0;Soft 404 1,211 + 已抓取未收录 2,865 全是 open 岗;用 Googlebot UA 抓 open 岗页,服务端 HTML 可见文字约 350 字,正文位置是「加载中…」。
> 主线哪一格:流量入口。没有 Google 来的求职者,后面所有付费动线都没有人走。

## 用户故事

- 作为 Googlebot,我抓 `/jobs/<id>` 拿到的 HTML 里就有完整职位描述,不用再执行脚本、不用再打被 robots 禁掉的 `/api/`。
- 作为求职者,我打开职位详情页,正文和现在一样在同一个位置、同一副样子,只是不再先看一眼「加载中…」。
- 作为在职位板弹框里看岗的用户,行为一个字不变(弹框仍懒取)。
- 作为 Frank,我改完能用一条 curl 证明「爬虫看到的正文长度」从约 350 字变成几千字,能在 Search Console 用「测试实际网址」看到正文被识别。

## 现状链(改前)

```
页面门 app/(frontend)/jobs/[id]/page.tsx
  ├─ loadJobById ──────────────► job(JobFact,不含 description)
  ├─ db.query(SQL.JD_BY_JOB_ID) ► jdText(库里的 description,原样未脱敏)
  │      └─ 只喂 JsonLd(jobPostingJsonOf({ job, jdText }))   ← 正文已经在服务端手里
  └─ <Job job plan dims related updatedAt />                 ← 没把 jdText 传下去
        └─ <JobBody> → useJobBody → useJdText
              SSR 时:text = '' / status = loading → 渲「加载中…」
              客户端 useEffect:fetch /api/jobs/text?url=<applyUrl>
                    └─ jobsTextRoute → jobDescription:DB 命中脱敏返回;没有才懒抓原站
```

三个事实决定方案:

1. **正文已经在页面门服务端手里**(为 JSON-LD 查过一次),只是没往组件传。
2. `/api/jobs/text` 在 robots.txt 的 `Disallow: /api/` 之内,且按 IP 日限流(429),Googlebot 的渲染器拿不到也不该拿。
3. 库里 open 岗正文覆盖率(2026-09-14 生产只读查):

| origin | open 岗 | 有正文 | 覆盖 |
|---|---|---|---|
| jobbank | 52,766 | 45,096 | 85%(缺口 = 详情回填每轮限 3,000 帖的追赶滞后,2026-09-05 立) |
| jobillico | 20,154 | 20,150 | 100% |
| jobboom | 2,147 | 2,146 | 100% |
| ats | 318 | 314 | 99% |
| gcjobs | 244 | 244 | 100% |
| careerbeacon | 41 | 41 | 100% |

## 方案:把已查到的正文顺着 props 传到 JD 身体,SSR 直接渲「拿到了」态

### 数据流(改后)

```
页面门
  ├─ loadJdTextById({ db, id }) ──► jdText(库里有 = 脱敏后正文;没有 = '')   【新函数,替换门里那段内联 try/catch】
  ├─ <JsonLd json={jobPostingJsonOf({ job, jdText })} />                     【不变,同一份串】
  └─ <Job … jdText={jdText} />
        └─ <JobBody … jdText={jdText} />
              └─ useJobBody → useJdText({ job, jdText, onFreeLeft })
                    jdText !== '' → 初态 text = jdText / status = done,effect 不发请求
                    jdText === '' → 现有懒取路径原样(loading → fetch → done/empty/limited)
弹框(advisor/actmodal、acthead)
  └─ <JobBody … jdText={TEXT_NONE} />  → 走懒取,行为不变
```

### 改哪几件(全部在两个已重构域内)

### 被否掉的替代路

- **robots 给 `/api/jobs/text` 开洞**:端点按 IP 限流且会懒抓原站,Googlebot 一天抓几万页就是几万次外抓;而且正文是 fetch 来的,Google 渲染器要排队执行脚本,收录慢且不稳。否。
- **页面门 SSR 时对无正文岗懒抓原站**:把外站请求塞进每次页面渲染,TTFB 不可控,违反懒查询铁律。否;无正文岗照旧懒取,靠 ETL 回填把 85% 补到 100%。

### 可证伪假设(改前立,验收时逐条勾)

1. 改后用 Googlebot UA 抓任一有正文 open 岗,服务端 HTML 去掉脚本样式后的可见文字 ≥ 1,500 字(现在约 350),且包含库里 description 的前 80 字。
2. 页面首帧不出现「加载中…」,375px 与桌面浏览器控制台零 hydration 警告。
3. 详情页 DB 查询次数不增加(正文那一查本来就有),`/jobs/<id>` TTFB 不劣化。
4. 职位板弹框打开同一岗,网络面板仍出现一次 `/api/jobs/text` 请求,内容与页面直出的一致。
5. Search Console「测试实际网址」对一条 Soft 404 样本(如 `/jobs/31957239`)显示页面可用、检测到 1 条有效 JobPosting,且「查看已测试网页」的 HTML 含正文。

### 验收闸

- 代码闸四道:`npx tsc --noEmit`、`npm run lint` 零新增、`npx vitest run` 无新增红、`npm run build`。

- 生产闸:push ≠ 上线;换版后拉 `/jobs/31957239` `/jobs/1280026` `/jobs/645367`(GSC 三类样本)各一条 curl 核假设 1,再进 GSC 跑假设 5。

### 本批不做(另立批,等 Frank 拍)

- 爬虫无 Accept-Language 时默认英文渲染(现在 ③ 中文兜底;88% 流量英文,导航与占位对 Google 是中文)。
- 开放岗 JSON-LD 补推荐字段(Frank 2026-09-14 贴的「Improve item appearance」七行,全是推荐项不是必填,Items 现为 0 只因有效条目归零):`validThrough`(Job Bank 帖带截止日)、`employmentType`(ATS 岗缺)、`baseSalary`(库里有 salary_text 可折)、`jobLocation.address` 的 `postalCode` / `streetAddress`(有精确地址的岗才填,没有留空不猜)。两条红的(缺 hiringOrganization / datePosted)是 7 月底一过性尖峰,现无实例,不处理。
- sitemap `lastmod` 改用岗位真实更新时间(现在一批 URL 的 lastmod 是生成时刻)。
- 改完后对样本 URL「请求编入索引」并重提 sitemap index(Frank 亲手,GSC 走 Chrome 登录态)。
