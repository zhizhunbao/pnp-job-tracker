# advisor 域重建(上 pi)设计 — 2026-08-23

> 拍板依据(2026-08-23 凌晨三连):consult 老的不变;advisor 单独一条线;advisor 也依赖
> agent 那一套,不用重写一套 ai 代码。质量关:advisor-quality-gate —— 烂的一逼就不切。

## 一、三问定界

- **回答什么问题**:「看着这张卡(职位/公司/职业/地点),按场景给我解读」。与 consult 的分界:
  consult 是用户**主动来问**(自由文本 → 模型挑工具),advisor 是**场景发起**(field 定死 →
  服务端备好事实 → 定向生成)。两者都是「跑什么」层,共用 agent(怎么跑)与 llm(怎么调模型)。
- **边界切在哪**:按**发起方**切(场景卡片 vs 自由对话),不按模型/后端切(那是会变的事实)。
- **寿命**:与职位板各弹框同寿;老 api/advisor(454 行,streamChat 直调)将死,新域幸存 ——
  依赖方向:老 route 最后一步整删,新域不 import 老的任何东西。

## 二、契约变更(本次唯一的行为级改动,其余逐字保形)

**现状问题**:`POST /api/advisor` 的 `body.job` 是前端整包上传的事实对象,服务端只截断不验
—— 请求方可以伪造「PNP-eligible: yes」喂给模型再截图传播。信任边界校验是宪法永不上砧板项。

**新契约**:`POST /api/advisor` 收 `{ field, id, lang, messages? }`(company 场景 `id` 允许为
公司 slug;occ/prov/city 速读收 `noc`/`prov`/`city` 键)。**事实一律服务端现查**:
fetchJobById / companyRow / loadNocDuties / loadProvinceCard / loadCityCard(全部现成,
routes 借各域 server 门)。前端 Advisor.tsx 改传 id(它本来就有),不再拼 job 包。
locationFacts 这类「面板同源数字块」由服务端用同一取数函数重建,保证与面板同数。

## 三、域形态(九名字规约,rows/callbacks 不建)

```
lib/advisor/
├── prompts.ts    SYSTEM / GROUNDING_RULES / PLAN_RULES / HEADINGS / ASK / 各场景模板
│                 —— 老链 20+ 轮实测炼出的措辞红线逐字搬(#46 简体令、#50 身份红线、
│                 #162 禁资格判定、#167 反编铁律、语言纯度令…),一字不改先搬后评
├── constants.ts  SIMPLE 集、CH_NAME 档名、numPredict 各档、缓存版本号 v4、限额键
├── types.ts      AdvisorBody / Field 联合 / 各场景 FactsIn / 缓存槽
├── functions.ts  jobFacts / scoreFacts / profileFacts / buildPrompt 家族(纯拼装,事实进
│                 参数);行构造器尾段(若需)
├── variables.ts  CACHE.readsBy(初判缓存,key 含 v4:field:id:lang[:p<uid>])
├── routes.ts     advisorRoute:鉴权→freeGate→限流→服务端取事实→选链→流式回传
└── index/server  两门
```

**pi 的用法(克制)**:大多数场景是**定向一发**(事实已备好,不需要模型挑工具)——
走 llm.completeText/streamChat 即可,硬套工具循环只加时延。真用 agent 循环的只有两处:
① `company`:web_fetch 官网(老链已有此形态,pi 的工具循环承接)+ 可选 friend 联网调查;
② `chat` 多轮:注入本岗事实为底,开放 consult 同款只读工具子集(lookupNoc/lookupProvs/
lookupDraws)—— 追问「这个省最近抽分」不再答「无数据」。工具面是 advisor 自己的
(跑什么),循环机制借 agent(怎么跑)—— agent 第二消费者,不复制一行循环代码。

## 四、流式与缓存(保形)

- 输出仍是纯文本流(前端 Advisor.tsx 逐字渲染);前导话闸(吞【之前 300 字)保留。
- 初判进程内缓存保留,键版本 bump 到 v4(契约换 id 制,旧键天然失效);对话不缓存。
- 三层帽保形:freeGate 统一池 + 全局日帽 + Pro 个人日帽(PRO_ADVISOR_DAILY)。

## 五、评测与质量关(切换前置条件)

- `tests/eval/advisor.eval.spec.ts`:场景批 ——
  每 field × 三语抽 2 个真岗(生产库现查),新老两链各跑一遍,按老链 20 轮教训做**断言探针**:
  ① 禁令探针:输出不含「无法作为…通道 / X/5 / 0-100 分 / 繁体字(zh)/ 编造中位数」;
  ② 形状探针:【标题】段数、结尾 ❓ 行、字数窗;
  ③ 接地探针:事实块没给的数字不得出现(抽查薪资/名单类 token)。
- 质量关:探针全绿 + Frank 抽读三语各 2 篇点头,才走替换四步的③(切换)。
- 切换后老 route 观察一轮生产流量再整删(④)。

## 六、批次拆分

1. 域骨架 + prompts 逐字搬 + functions 纯拼装(不接线,tsc/lint 绿);
2. routes 接线(id 制取事实)+ 前端 Advisor.tsx 改传 id;
3. eval 批跑通 + 质量关报告 → Frank 点头 → 切换 → 删老 route。

## 七、风险与对冲

- **措辞红线回归**(最大风险):prompts 逐字搬 + 探针断言化,20 轮教训变成可执行闸。
- 事实服务端化后与面板数字不一致:取数走各域同一函数(与面板同源),探针抽查对数。
- friend/anthropic 后端差异:走 llm 现有 provider 抽象,不在 advisor 里感知后端。
