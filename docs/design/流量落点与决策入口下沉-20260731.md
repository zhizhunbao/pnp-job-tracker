## 2. 诊断:三个错位

1. **入口错位**:超过一半访客经 Google 落在**某一张职位详情页**,不经首页、不经 /start。而决策入口(七目标卡、答题、报告)全挂在 /start。人和门不在一个地方。
2. **信号被浪费**:字段弹框 565 次是站内最强的意图信号,点的正是 PNP / 移民 / EE / 薪资 —— 与付费面同一主题。**弹框里没有任何通往报告的出口**,用户举了手,我们没接。
3. **漏斗在最前段就漏干**:三问 80 开 → 20 完成(25%)。后面所有的报告与锁区,能见到的人本来就只剩两成。

## 3. 设计:决策入口下沉三层

原则:**入口跟着流量走,不要求用户先回到首页**。同一份报告,三个落点:

```
第一层  职位详情页(唯一有真实流量的着陆点)
        → 卡片式入口:「你这行在 <省> 的清单命中与在招」,带真数,点进 /plan/job?noc=…
第二层  字段弹框(PNP / 移民 / EE 三个,合计 256 次)
        → 底部一行:按你的职业出报告(把弹框里的字段当上下文带过去)
第三层  三问(已经是共用底座,不动题)
        → 只补分步埋点,先看清 80→20 掉在哪一步,再决定改哪里
```

三层用的是**同一套字段库与同一个报告引擎**(统一题库那批已经铺好),所以这次只加入口,不加第二套逻辑。

## 4. 具体三刀

### 刀 1:职位详情页挂报告入口(有量的地方先做)

- 位置:JD 正文之后、页脚之前,一张与站内同款白卡。
- 内容三行,全是库里查得到的真数:该 NOC 在**本岗所在省**的在招数、命中具名清单数、ESDC 中位对照。
- 动作:「看这行的完整报告 →」进 `/plan/job`,带 `?noc=` 预填(答案已存的用户直接出报告,不再答题)。
- 空态:该省零在招或职业未分类 → 整卡不渲(不出空壳)。

### 刀 2:PNP / 移民 / EE 三个弹框底部加出口

- 一行文字钮,不是横幅广告:「按你的职业出报告」。
- 带上下文:弹框已经知道 NOC 与省份,直接拼进链接,落地即出结论。
- 只上这三个(它们的语义与报告一致);薪资/地点/公司弹框不加 —— 语义不对的地方硬塞就是牛皮癣。

### 刀 3:三问分步埋点

- 现在只有 `quiz-open / quiz-step / quiz-done`,`quiz-step` 的步号在参数里,而 share 链接关了 breakdown,读不出来。
- 改法二选一(建议前者):① 事件名带步号 `quiz-step-1/2/3`(零后台配置,立刻可读);② 在 Umami 后台打开 breakdown 权限。
- 判读口径:**掉队最多的那一步**才是改文案/改交互的地方;在此之前不动三问的题面。

## 6. 不做什么(这轮明确挡掉)

- **不自建 CRS 计算器**:二维交叉矩阵,成本是省表的 1.5 倍,而它在漏斗最深处;现在连报告都没人看到。
- **安省计算器做不了**:ON 改制后 EOI 未开、官方不公布分值表(E12-09 逐省实核过),没有数据源。
- **不再打磨锁区文案**:pricing 打开 1 次/月,现在改的是没人看的东西。
- 不给职位详情页加第二套答题:入口带 NOC 进 `/plan/*`,题库只有一套。

## 7. 施工顺序与验收

1. 刀 1(半天):职位详情页报告入口 + 埋点 `jd-report-open`。
   - [ ] 有职业且该省有在招 → 卡片出现,数字与 `/api/report` 同源
   - [ ] 无职业 / 零在招 → 整卡不渲

2. 刀 2(半天):三个弹框底部出口 + 埋点 `modal-report-open`(带 field 参数)。
   - [ ] 只在 PNP / 移民 / EE 三个弹框出现
   - [ ] 链接带 NOC 与省份,落地即出结论
3. 刀 3(半小时):`quiz-step-N` 分步事件。
   - [ ] 三步各自可读;旧事件保留一周做对照
