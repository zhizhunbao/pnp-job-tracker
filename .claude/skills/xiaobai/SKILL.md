# /xiaobai = 扮小白真走一遍 → 分级汇报 → 多选拍板

来源:2026-10-08 Frank「你模拟一个小白用户走一下 看他能弄明白吗」「先走浏览器吧」。那一轮靠真走找到了代码审不出来的四处(两块同时要简历、开启后对着空态、注册完顶栏没变、不知道发给谁)。判据只有一条:**小白自己能不能走到底,不靠解释**。本站文案铁律是「不放解释性文字」,所以小白看不懂 = 动线的错,不是加一句话能补的。

## 第 0 步 · 定人设与入口(不问 Frank)

- **人设**:一个真要在加拿大找工作的人,不懂移民术语,不知道本站有什么,手机 375 宽,中文界面(第二遍换英文)。参数给了功能或入口就从那里起;没给就**随机**从下面抽一个(用当天日期取模):
  1. Google 招聘富结果落到某个职位页(真实入口占七成):随机开一个在架岗 `/jobs/<id>`;
  2. 首页职位板 `/`;
  3. 就业把脉 `/start`(2026-10-08 实撞:旧址 `/pulse` 已 404;入口表过时先按菜单里的链接为准);
  4. 雇主板 `/employers`;
  5. 定价页(从某个付费入口被引过去)。
- **目标**:他想投一个岗 / 想知道能不能走省提名 / 想让系统替他投。走到哪一步算到底:**付款页出现**(Stripe Checkout 页面打开即止,不付;生产是真钱)。
- **环境**:默认生产 https://offer2pr.com(真流量真库;@test.local 测试号不发真邮件、邮件改投 Resend 测试地址,见 lib/apply recipientOf);Frank 说「本地」才用他起的 localhost:3000(助手不起 dev)。

## 第 1 步 · 真走(浏览器面板,Frank 能看)

用内置浏览器(`mcp__Claude_Browser__*`),`resize_window` 先 mobile,走完一遍再 desktop 看一屏首页。规矩:

- **每一屏先写「小白以为」再点**:看到这屏,他以为这是什么、该点哪、点了会发生什么;然后点,记实际发生的。两者不一致就是一条发现。只读屏上的字,不许用自己知道的代码知识补脑。
- **每一屏再记「他可能的困惑」**(2026-10-08 Frank「可能有哪些困惑也要记下来」):走得过去也要记。用他的口气写成问句,一屏最多三条,例:
  「这个站是干嘛的,是中介吗」「为什么投个工作要先答专业」「英文姓名填拼音还是英文名」「这封信是谁写的,发出去署我的名吗」「发给谁了,雇主回信我在哪看」
  「智能投递开了会不会乱投」「免费能用几次,Pro 到底多了什么」「付了钱能保证什么」「我的简历雇主看得到吗,安全吗」。
  **每条困惑打困惑分 1–5**(2026-10-08 Frank「困惑分数越高的优先解决」):5 = 会让他放弃或走错;4 = 会卡住很久或选错;3 = 会停下来想;2 = 一闪而过;1 = 不用管。
  **同一内容在不同页面展示不一样,也记成困惑**(2026-10-08 Frank「不同的页面相同的内容,展示不一样也算困惑」):同一职业 / 状态 / 价目 / 清单在两页叫法或形态不同,逐处列出页面。
  **页面太乱、太难看也记成困惑**(2026-10-08 Frank「页面太乱，太难看 也算」):卡套卡、一屏塞太多、折行断词、对不齐、首屏被装饰占掉,照截图逐屏记,同样打分。
  困惑分三类标出来:**产品该回答的**(动线 / 状态 / 结果可见性能解决,不靠文案)、**信任类**(数据来源、隐私、是不是中介)、**不用管的**(他自己点一下就明白)。
- **空态不许停在那里**(2026-10-08 Frank「这些问题你之前 小白 都没查出来？」:那轮智能投递撞「今天没有新岗」就收工,待投卡、「全部投出」、没有上一个 / 下一个全漏;草稿行因为一口气投完也没见过):核心功能出空态先记一条,再想办法把它弄满接着走(换职业更宽的测试号重开、留一封草稿不发),**每个列表 / 卡片都要看过「有东西」的样子**。
- **每个动作都点一次「反悔」**(2026-10-08 Frank 追问漏查原因:那轮只走顺路,从没点过跳过再想找回、发错想撤回):跳过 / 删除 / 关掉 / 改了又想改回,都真点一次,看能不能回来;回不来又没提前说的,记 🟠。
- **收不回的动作前必须有逐项确认**(同日:投递第 3 步只列了公司名和文件名,点「发送」就发给真雇主,那轮还记成「顺」):发信、付款、删除、批量操作前,小白能不能一项一项看到「发给谁、附了什么、用谁的名字」并逐项确认;做不到直接记 5 分。判「顺」只看走不走得通不够,还要看该不该这么容易发出去。
- **凡是显示「用的哪份 / 发给谁 / 署谁名」的行,都要问一句能不能当场换、能不能当场看**(2026-10-08 Frank「哪块不完善不完整你没测出来吗」:逐项检查四行本地验收时只看了走得通,没点「打开」看它新开标签页、没问简历能不能换):看不了 / 换不了都记 🟡,「换」要有去处不是跳回别页。
- **别用自己知道的底细给小白兜底**:走查中去代码里核实安全性可以,但汇报里小白的感受只按屏上看得到的写。
- **每个视觉元素问一句「它告诉小白什么」**(同日漏了卡片前的首字母色块):答不上来 = 装饰或占位,记成困惑(乱 / 难看类)。名字一律对照展示约定看英文在上、译名灰字在下。
- **只点小白会点的**:最大最亮的那颗钮、唯一的入口;要靠猜 URL 或滚到底才找到的入口记成「找不到」。
- **注册**:走到要登录时,现场注册一个 `novice-<MMDD>[-n]@test.local`(密码自生成,**记进 `cms/.env.example` 末尾注释**,不在对话里重复),走完整个访客向导,记每一问他答不答得上来(专业、职业、省)。注册完看三件:顶栏变没变、落到哪、他要干的事还在不在眼前。
- **核心功能**:投一岗(简历、英文名、信、预览、发送;@test.local 的发送落 Resend 测试地址,可以真点)、开智能投递(等它跑完一轮,看第一张卡多久出来)、收藏、看「我的」四页签。免费额度用完的那一下(AI 信试用、全部投出)是付费闸,记他看到的是什么、知不知道为什么要付。
- **付费**:从他自然碰到的升级口进定价页,选一档,到 Stripe Checkout 页**停**,截图,不填卡。
- **每步截图**(`scale: 0.6` 省 token),控制台报错顺手记;卡住超过两次尝试就记「卡死」继续下一条路,别硬闯。
- 走完中文再用英文界面快速重走注册→投递一遍(88% 流量是英文)。

## 第 2 步 · 汇报(先落文件,再发摘要,再提问)

- **报告落 `docs/design/小白走查-<YYYYMMDD>.md`**(2026-10-08 Frank「会落报告吗」),截图拷进 `docs/design/img/小白走查-<YYYYMMDD>-NN-<屏名>.jpg` 并在报告里按编号引用;聊天里只发摘要 + 链接。

固定四块,短:

1. **他走的路**:一行一屏,「屏 → 他以为 → 实际」。
2. **发现分级**:🔴 卡死(走不下去)/ 🟠 以为坏了(其实没坏,但他会放弃)/ 🟡 看不懂(猜对了但犹豫)/ 🟢 顺。每条带截图名与一句根因(动线 / 状态没刷 / 入口藏着 / 文案),**不给加解释文案的建议**。
3. **困惑清单**:**按困惑分从高到低排**(同分按屏序),每条带分数;列他可能问的问题,每条标类别(产品该回答 / 信任 / 不用管),产品该回答的那些注明现在站上**哪里能看到答案、还是看不到**;看不到的才是待办,并说明用动线还是用事实(数据、状态、结果)去回答,不用解释文案。
4. **三个硬指标**:从入口到注册完几屏几分钟;到第一次核心动作成功几屏;到付款页几屏、在哪一步看到付费理由。到不了的写到不了在哪。
5. **留下的痕迹**:新建的测试号、真发出去的投递、开了的开关,写清楚让 Frank 知道库里多了什么。

## 第 3 步 · 多选拍板(照 /fe)

- **题目和排期一律按困惑分从高到低**(2026-10-08 Frank「分高先解决啊 2 8 原则啊」):先问、先修 5 分和 4 分;不许按改动类型分批把高分项压到后面。同分内一批仍只做一种变换。

`AskUserQuestion`、`multiSelect: true`,一轮最多 4 题,每题 2-4 项:🔴 🟠 与「产品该回答」的困惑逐条列「改法 + 工作量档(小时级 / 半天 / 要立项)」,推荐项第一位加 `(Recommended)`;「先不管」是合法选项。Frank 勾了才动;改完照 [[local-test-before-push]] 本地验、他点头再推。
