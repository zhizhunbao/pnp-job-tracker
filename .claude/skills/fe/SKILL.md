# /fe = 评估 → 多选拍板 → 只做勾选项

节奏固定三段:**先评估(只读不改)→ 再提问(多选拍板)→ 后执行(只做勾了的)**。这是 Frank 定的工作法(2026-09-04):评估阶段一行代码不许改,提问环节不许跳,未勾选项 = 未批准。

## 第 1 步 · 定对象

参数即对象(`/fe pte`、`/fe 公司弹框`、`/fe 定价页`)。把对象映射到四样东西再开工:

- 组件桶 `cms/src/components/<域>/` 与相关 `cms/src/lib/<域>/`;
- 页面路由(哪些 page.tsx 消费它);
- 埋点事件清单:grep `TRACK_|EV_` 常量,含义从 constants 的 JSDoc 抄,**别猜事件名的意思**;
- 若涉数据展示,追到 mart 列与 ETL 段(内容层问题多半在数据层)。

没给参数才追问一次「评估哪个功能」,其余功课自己做。

## 第 2 步 · 收证据(只读,不改一行)

四路取证,每条结论必须挂证据(代码位置 / 数据 / 所见截图),量力取舍但不许凭印象:

1. **代码侧**:读组件桶 + lib 域,列出功能的动线与埋点事件表(事件名 → 人话含义)。
2. **数据侧**:
   - 第一方 `funnel_events` 表(day, event, prop, n;白名单见 `cms/src/lib/funnel/constants.ts` 的 FUNNEL_STEPS)——用 node+pg 只读直查生产库(连接串在 `cms/.env` DATABASE_URI),拉近 30 天按事件汇总,漏斗内功能算每步转化率;
   - Umami:share 链接看该功能事件量与相关页面流量(链接见记忆 umami-share-url),**先剔 Frank 本人两台设备**;
   - 两源数对不上是正常的(umami 被广告拦截器吃、免费档无正式 API,见 `cms/src/lib/track/functions.ts` 头注释),漏斗分母以 funnel_events 为准;拿不到的数写「拿不到」,不编。
3. **生产实测**:375px 手机优先真开 https://offer2pr.com 走一遍该功能动线(可复用 `.claude/skills/iterate-audit/scripts/checkup.py --only <模块>`,别重写脚本);只看不改,别起本地 dev。
4. **站内对照**:同形态别处怎么做(通用桶单一出口)、该功能与站内哪里重复、数据面过 iterate-audit 的内容层六问。

## 第 3 步 · 评估报告(先发报告,再提问)

简短,四块:现状一句话 / 数据表现(带数) / 问题清单(逐条带证据) / 优化机会。别写长文,Frank 看完报告紧接着就要答题,报告是他答题的依据。

## 第 4 步 · 多选拍板(本 skill 的灵魂)

用 **AskUserQuestion** 工具、`multiSelect: true` 把优化建议做成选择题:

- 每轮最多 4 题,每题 2-4 个选项;建议多就按主题分题(文案 / 动线 / 数据 / 砍留),装不下分第二轮,**不超两轮**;
- 推荐项放第一位、label 尾加 `(Recommended)`;label 短(≤5 词),description 写清代价与预期收益,工作量标档(小时级 / 半天 / 要立项);
- **「维持现状」「砍掉这功能」也是合法选项**,该列就列,别只出「怎么改」不出「要不要」;
- Frank 可多选、可用 Other 给自由建议;Other 里的建议视同新勾选项,含糊就一句话复述确认再动。

## 第 5 步 · 执行(只做勾选项)

- 执行前一句话复述勾选范围;未勾选 = 未批准,不顺手做、不扩范围(scope-follows-decree);
- UI 新形态 / 新动线:先出效果图(注入生产页 DOM 拍真样式)等点头再写码(mode-b);
- 清洗 / 换算 / 分类归 `etl/` 数据层,不在前端干;
- 闸门按改动类型:动了代码跑 tsc + lint + vitest + build 四道;新增文案过四闸;push ≠ 上线,收口拉本轮路由验换版;
- 需要 Frank 亲手 / 花钱 / 破坏性的项:列出来等他,不代做。

## 第 6 步 · 收口

报告四块:逐勾选项做了什么 + 验证结果 / 没做的勾选项及原因 / **未勾选项一句话留档**(别丢,但也不写进待办文档,除非 Frank 说记下) / 建议下一步。

## 与 /dd 的分界

`/dd` = 全站或模块级截图走查整改,问题驱动、清单轮次闭环;`/fe` = 单功能深评估 + 方向拍板,决策驱动、一次性。/fe 过程中发现的渲染级小问题可以顺带列进拍板选项,成批的版式问题指给 /dd,不在这儿追编号。
