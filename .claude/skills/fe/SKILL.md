# /fe = 子代理评估 → 多选拍板 → 只做勾选项

节奏固定三段:**先评估(子代理只读取证)→ 再提问(多选拍板)→ 后执行(只做勾了的)**。这是 Frank 定的工作法(2026-09-04):评估阶段一行代码不许改,提问环节不许跳,未勾选项 = 未批准。

2026-09-10 改子代理模式:评估段派子代理 `batch-worker`(opus)跑,prompt 里写死「只读不改」。为什么:取证要读一堆文件、查库、开浏览器,全塞主循环把上下文吃光。子代理不能 AskUserQuestion,所以拍板与执行仍留在主循环(经理:派活、拍板、收口)。

## 第 1 步 · 派评估(主循环只做转发)

参数即对象(`/fe pte`、`/fe 公司弹框`、`/fe 定价页`)。没给参数才追问一次「评估哪个功能」。

用 **Agent 工具**、`subagent_type: batch-worker`、`run_in_background: false` 派一个子代理,prompt 写:对象原话 + 下面「取证三步」全文 + 红线(只读:不 Edit / 不 Write / 不 commit / 不起本地 dev / 库只许 SELECT)。它跑完把四块报告作为结果交回。主循环**不自己取证、不补查**;报告写「拿不到」的数就是拿不到,不编。报告若说「对象不明」,把候选转给 Frank 选一个,再派一次。

### 取证三步(原样贴进子代理 prompt)

**定对象**:把对象映射到四样东西 —— 组件桶 `cms/src/components/<域>/` 与相关 `cms/src/lib/<域>/`;页面路由(哪些 page.tsx 消费它);埋点事件清单(grep `TRACK_|EV_` 常量,含义从 constants 的 JSDoc 抄,别猜事件名的意思);若涉数据展示,追到 mart 列与 ETL 段。映射不到就报「对象不明,候选:…」。

**收证据**(每条结论挂证据:代码位置 / 数据 / 所见,拿不到的数写「拿不到」):① 代码侧,读组件桶 + lib 域,列动线与埋点事件表;② 数据侧,`funnel_events` 表(白名单 `cms/src/lib/funnel/constants.ts` FUNNEL_STEPS)用 node+pg 只读直查生产库(`cms/.env` DATABASE_URI)拉近 30 天按事件汇总、漏斗算每步转化率,Umami share 链接(记忆 umami-share-url)看事件量与页面流量、先剔 Frank 两台设备,两源对不上以 funnel_events 为准;③ 生产实测,375px 手机优先真开 https://offer2pr.com 走动线(可复用 `.claude/skills/iterate-audit/scripts/checkup.py --only <模块>`),只看不改、别起本地 dev;④ 站内对照,同形态别处怎么做(通用桶单一出口)、与站内哪里重复、数据面过 iterate-audit 内容层六问。

**报告**固定四块:现状一句话 / 数据表现(带数小表)/ 问题清单逐条带证据并标工作量档(小时级 / 半天 / 要立项)/ 优化机会逐条一句话,含「维持现状」「砍掉」值不值得列为选项。短,不给拍板,不动代码。

## 第 2 步 · 转发报告(先发报告,再提问)

把子代理的四块报告原样转给 Frank:现状一句话 / 数据表现(带数) / 问题清单(逐条带证据) / 优化机会。别改写成长文,Frank 看完报告紧接着就要答题,报告是他答题的依据。

## 第 3 步 · 多选拍板(本 skill 的灵魂)

用 **AskUserQuestion** 工具、`multiSelect: true` 把优化建议做成选择题:

- 每轮最多 4 题,每题 2-4 个选项;建议多就按主题分题(文案 / 动线 / 数据 / 砍留),装不下分第二轮,**不超两轮**;
- 推荐项放第一位、label 尾加 `(Recommended)`;label 短(≤5 词),description 写清代价与预期收益,工作量标档(小时级 / 半天 / 要立项);
- **「维持现状」「砍掉这功能」也是合法选项**,该列就列,别只出「怎么改」不出「要不要」;
- Frank 可多选、可用 Other 给自由建议;Other 里的建议视同新勾选项,含糊就一句话复述确认再动。

## 第 4 步 · 执行(只做勾选项)

- 执行前一句话复述勾选范围;未勾选 = 未批准,不顺手做、不扩范围(scope-follows-decree);
- UI 新形态 / 新动线:先出效果图(注入生产页 DOM 拍真样式)等点头再写码(mode-b);
- 清洗 / 换算 / 分类归 `etl/` 数据层,不在前端干;
- 闸门按改动类型:动了代码跑 tsc + lint + vitest + build 四道;新增文案过四闸;push ≠ 上线,收口拉本轮路由验换版;
- 需要 Frank 亲手 / 花钱 / 破坏性的项:列出来等他,不代做;
- 执行段可以再派 batch-worker 干机械批量活,但拆批、收口、闸门由主循环负责。

## 第 5 步 · 收口

报告四块:逐勾选项做了什么 + 验证结果 / 没做的勾选项及原因 / **未勾选项一句话留档**(别丢,但也不写进待办文档,除非 Frank 说记下) / 建议下一步。

## 与 /dd 的分界

`/dd` = 全站或模块级截图走查整改,问题驱动、清单轮次闭环;`/fe` = 单功能深评估 + 方向拍板,决策驱动、一次性。/fe 过程中发现的渲染级小问题可以顺带列进拍板选项,成批的版式问题指给 /dd,不在这儿追编号。
